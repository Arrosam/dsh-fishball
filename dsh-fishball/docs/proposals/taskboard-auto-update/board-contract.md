# 自动更新任务板：写入、核验与撤销契约（评审稿）

**结论：**弱模型提出有证据的补丁；任务板负责认定目标、比较版本和提交。模型不是第二个看板编辑器。一次返回可以改多个已有任务，但只产生一个新看板版本和一份给 Fishball 的摘要；只有完成建议、没有实际字段变化时，保存待核验项，不发通知。以下均为拟议行为，不代表 staging 已有此功能。

## 1．沿用什么，新增什么

| staging 基线 `bdcccc66` | 对新入口的约束 |
|---|---|
| [数据契约](../../../docs/plugins/fishball-taskboard.md#L33-L67)、[严格读取校验](../../../packages/fishball-taskboard/src/board.js#L101-L129)：持久值只有 revision/tasks/memos；任务按 parentId 成树，无会话绑定。写入上限为 500 个任务、200 个 memo、深度 5（根为 1）。| 不在任务、memo 或旧文档上加 source/session/review 等字段。会话 ID 只证明这一次更新的来源，不把未来所有返回绑定到同一任务。不要使用另一个会话型插件 fishball-board。|
| [工具](../../../packages/fishball-taskboard/src/tools.js#L42-L69)：manager 会话双重检查；add/update/memo 共用队列，update 可改 title、整段替换 note，且没有基准版本参数。| 手工工具原义不变。不要将弱模型注册为 manager，不提供任何工具，尤其不循环调用 update。|
| [整板编辑与通知](../../../packages/fishball-taskboard/src/routes.js#L33-L86)、[旧 UI](../../../packages/fishball-taskboard/client.js#L490-L555)：用户 POST 带 baseRevision；过时返回 409 stale 和现版本；有改动才发 user-edit，已提交但未送达为 notified:false。| 不冒充用户 POST。现有 GET、SSE、页面主题、任务行及编辑草稿投影保持旧形；审计从独立投影读，同源 UI 显示即可，不开第二条持久浏览器流。|
| [看板维护提示](../../../packages/fishball-taskboard/src/guide.js#L9-L15)、[压缩后提醒](../../../packages/fishball-taskboard/src/reminder.js#L23-L37)：前者要求 Fishball 在受管会话返回时维护板，后者只有未完事项计数。| 原返回处理不被消费。启用时明确“自动摘要是已提交的事实，不照抄再写；无摘要也不表示已完成”；保留 Fishball 的判断和正常手动维护，但工人在终稿中声称「已完成」本身不是验收证据，不能为满足旧提示而直接写 done/100。计数、压缩提醒和用户保存通知不借来发自动更新。|

旧提案（review-fishball-trigger-consult-design，基线 eb74c115）的 [Tasks and user edits](../../../../review-fishball-trigger-consult-design/docs/proposals/fishball-trigger-flow.md#L40-L46) 仅建议提示 Fishball，明确同名、猜进度、竞态和无 session 绑定的风险。此次授权增加了**可选弱模型更新已有任务**，不是允许同步会话、自动验收或改写旧表单。存量检查可读旧记录时只查结构；新功能的额度不能使旧板打不开。

## 2．送入模型之前

1. 只有已选可用模型，且宿主证实是**这一个受管工作会话的这一次已结束轮次**的非空、完整 final message，才允许进入。带上宿主给的目标实例/端点世代、session ID、turn ID 和稳定回执键；不从正文提取这些身份。新到达的 mailbox event、反向扫描出的最近一段非空文本或本轮空回复，都不是同轮证明。来源、权限、轮次不确定或消息截断即跳过；不去抓历史补齐。无此证明能力时展示不可用，不启动自动写。
2. 读取同一瞬间的 `baseRevision` 和**所有任务**。计数是 `tasks.length`，含子孙、done、dropped，不含 memo。0 或无可更新的未关闭任务跳过；1–20 才考虑；21 起整个跳过，不按“前 20”、未完成数或筛选后的可见行数截取。20 是建议的**推理准入上限**，不影响 21–500 项板的手动读写。独立检查模型上下文/速率预算，装不下整份必要输入即跳过，不裁掉同名候选或根路径。空模型即关闭；关闭、换模型或解除管理使尚未提交的旧请求失效。
3. 输入仅同轮终稿、任务投影（id、parentId、title、note、status、progress）和必要规则；不传 memos、其他会话、审计详情或凭据。不把正文、标题、备注里的命令当指令；不让模型选择 session、模型路由、通知对象或执行工具。ID 存在只是必要条件：终稿须唯一、明确指向该任务（例：精确任务 ID，或唯一对应的完整标题及必要父路径）；把输入板上的 ID 复述出来、模糊相似、同名且不可消歧都不算证据。片段逐字定位在本轮文本，并指向已发生的状态，而非计划/否定/引用。无法安全区分即返回空建议，不新建任务。

## 3．候选补丁：字段独立，完成只进入待核验区

每项用一个既有 taskId、一段有界证据引文及其对应的字段建议；模型给的是差量（例如 progress 与 noteAppend），不是 Task 或整板。宿主用同一份快照复算目标匹配、限制、去重和实际差异。额外键、未知或重复 ID、memo ID、非法类型或不可验证字段均拒绝整批，不采用“写到第几个算第几个”。

| 字段 | 自动入口能做什么 | 明确不能做什么 |
|---|---|---|
| status | 只对已有且未关闭项，在有直接事实时写入允许的开放状态（如开始实施→in_progress、明确等待依赖→blocked）。独立校验，不连带写 progress。| 不自动 done/dropped、不重开关闭项；不因结束轮次而改变状态。|
| progress | 只接受能归属到该任务的明确实际百分比、整数 0–99；未报告数值则保留现值。相同值不是变化。无明确授权不自动下调。| 不按轮数、阶段、已结束子项数量估算；不四舍五入，不把 100 压成 99。0 不是缺省，更不能拿来清空已知进度。|
| note | 只能追加本轮终稿中的必要事实短句。trim 新片段而**不改旧文本**；旧 note 非空用一个换行分隔，空则直接写。已有相同事实片段不重复追加。同批/回执重放不能重复追加。| 不传整段替换、不抹掉用户文字、不把会话全文/日志/隐私或来源标签写进 note。按 [码点规则](../../../packages/fishball-taskboard/src/board.js#L37-L60) 计入分隔符，合并后上限 2000；超过即整批拒绝，不裁前文、截引文或悄悄漏掉 note。|
| 其他 | 标题、层级、顺序只用作定位。宿主负责时间。| 不增删、重排、迁移任务，不碰 memo；不改 id、createdAt、未改行的 updatedAt。|

**完成不是一个自动字段。** 对某项提出 done、100%，或证据只宣称“全部完成”时，将这一项转成待 Fishball 核验；整项不改 status/progress/note，以免把“已验收”绕道写进备注。无独立证据的其他任务不受影响。例：A 明确进度 60%，B 自报完成：只改 A；同一份回执为 B 留待核验项。全是 B 型建议：没有新 board revision、没有“最近自动更新”伪标记、没有 Fishball 唤醒，用户仍能看到待核验。单纯无匹配/无差异则不建核验项。

## 4．一个提交点，两个版本概念

**选用同一存储域的私有 v2 封套**，不是另一张板，也不是先写 v1 再补审计。逻辑结构如下（示意，不公开为可写 JSON）：

    封套 = { board: 完整旧版文档, auto: { receipts, batches, reviews, 通知处理状态 } }
    board.revision：仅 board 内容变更时递增；不是运行次数或核验项数量。
    review.version：单个核验项的状态版本；不挪用任务 updatedAt 做并发令牌。

- **迁移与降级：**仍由 fishball_taskboard 唯一打开。安装版本支持时用 version 2 + compatibleVersions:[1]，解码器按形状严格接受原 v1 或完整 v2，v1 在内存归一为“原板＋空旁记录”；首次写才原子保存 v2。只读启动不碰 revision、时间、顺序或数据。坏板或不兼容版本拒绝打开，不能当空板重建。DSH 0.2.2-rc.3 的 storage-domain 声明支持 compatibleVersions；老 SDK/后端须实测版本准入与单次 durable set，缺能力不升级原域。**关闭功能不等于降级存储**：先停止写入，导出当前 v1 板并单独备份 v2 全量审计，验证 v1、版本戳和可恢复备份后再显式迁回；不声称旧二进制能直接读 v2。
- **写入顺序：**在 [现有 store.change 的串行边界](../../../packages/fishball-taskboard/src/store.js#L24-L56) 统一调度旧工具、用户保存、自动批、核验和撤销。推理在队列外。到队首重新读封套，先看稳定回执是否已处理，再查配置世代、来源资格、任务数及整板 revision。即便只发生无关 memo 修改，基准不同也整批 stale，保留对方修改，不逐字段合并、不带新 revision 自动重放、不二次付费。用户编辑中的草稿不被推送覆盖；若先提交的是自动批，旧用户草稿依原约定收到 409 并保留。
- **一次写完：**在内存验证所有项，用同一提交时间构造改后行、字段前后值、核验项、带基准/结果版本的批回执和通知意图，一次 `domain.global.set(封套)` 成功才发布。复用旧字段校验/树索引/差异规则，但不循环调每次都会加版本的 [updateTask](../../../packages/fishball-taskboard/src/board.js#L168-L182)。有一行或多行真变化都是 revision+1、一个板广播；仅核验/回执更新不广播旧板，在现有同源页面流上向本项目专用主题发布审计失效提示，新 UI 据此重读私有审计投影；断线重连或打开审计面板时重读，不为刷新元数据伪造板帧。普通错误不写不报；若存储结果未知，隔离写、重开后按回执对账，不猜失败重做。
- **交付不是事务的一半：**稳定批号限定为本项目＋经验证的目标实例/端点世代/工作会话/轮次；幂等优先于再次生成批号。只从已提交且有字段变化的批构造一份摘要。崩溃和通知错误不能撤回板或将重复输入变成第二次写。没有可核对的幂等交付保证时，先持久认领发送权，最多发起一次；结果分已登记、未送达、结果未知，不自动补发。不可把“宿主接受”写成“Fishball 已读”。保留去重水位不得短于可重放窗口；窗口外、无法判断是否重放则不处理。

## 5．用户看到的标记、Fishball 读到的摘要

**父就是直接父节点。**从**整批提交后的板**按 parentId 查 id、标题、状态和已存百分比；深层可另给根→直接父路径以说明所属主任务。根任务显示“顶层任务，无父任务”，没有父百分比；不是自身 0%。父任务也在本批有独立证据时取它的提交后值。绝不写回父、不做平均/加权，不用分组标题冒充父任务。

例如板在 r17 有“发布 40% → 验证 25% → 冒烟测试 30%”。终稿说“冒烟测试实际进度 60%”，另一个任务只自报完成。Fishball 收到 **1** 份：“已提交 r18，来源会话 S。冒烟测试 [任务 ID]：30%→60%；直接父 验证 [父 ID]：25%（路径：发布→验证）。另有 1 项待核验，未标为完成。”只有 status 或 note 变化也要逐项列**提交后实际进度**（可注明未变），而非省略或虚构。正文按数据转义；不是让 Fishball 再调用 update 的指令。不给每个子项单独发送，不触发新的工作会话、聊天回复或用户推送。普通用户看板行及审计（修改来源、会话、批号、时间、字段前后、投递状态）；若 Fishball 后续主动写用户消息，是另一条明确动作。

**待核验的发现与关闭：**建议仅 manager 的 `taskboard_read({})` 在有待核验时从同一封套快照附加外层可选 `autoReviews`（含 reviewId、reviewVersion、taskId、轮次来源、受限引文、建议及生成版本）。没有就完全保持旧返回；不是 Task 键，不经旧 GET/POST、SSE 或压缩提示透传。PTC 和原生均读同一工具结果；弱模型无权读取此审计视图。新 UI 从 owner 范围的独立审计读口读同一记录，板版本不匹配时刷新，不把旧徽标套到最新改动。

建议增加**仅 manager** 的 `taskboard_resolve_review({reviewId,expectedReviewVersion,baseRevision,decision})`，不对工人、弱模型或其他项目开放。Fishball 应重新读板、核验事实，decision 可拒绝，或明确确认建议中经核验的字段；确认 done 不隐式设置 100，确认 100 也不隐式写 done。排队后要求当前整板版本、待审版本、pending 状态、原目标及该项受影响字段与审阅快照一致；任何一项不符即提示重读/重新核验，不盲采纳旧提议。成功时同一封套写入人工判断及必要板改动，关闭该标记；拒绝只关标记，不增 board revision。目标已删或换作他用只允许作废；不重建任务。两人/两次点击不能完成两次。此处是 Fishball 作出的新决定，不是再次触发“弱模型自动更新”。

## 6．撤销与保留

用户可在批详情看清受影响的所有行后，按**整批撤销**；仅限有实际板变化的自动批。所有权及操作权限在服务端检查，不能相信浏览器传的前值。请求只指向批号、用户看到的当前版和批状态令牌；服务端取已持久化的前后镜像。

1. 进入同一队列，要求批未撤销、当前 revision = 用户所见 revision = 批后 revision；逐项当前字段也须等于批后值。同批附带核验项若已处理/改变，拒绝而不是抹去新决定。任何后续板编辑（包括另一行或 memo）都使旧批不能一键撤销；提示“看板已变化，请查看差异后手动编辑”，不提供强制覆盖。
2. 只恢复当初实际改动的字段，按任务更新时刻写新的 updatedAt；保留 id、createdAt、顺序、无关行。新的 revision = 当前+1，不把时间和 revision 倒回；同批仍 pending 的标记一并作废。记录谁、何时、撤销了哪一批及其新版本，一次落盘后广播一次板变化。重复撤销返回已撤销，不写、不再通知；不把撤销伪装成另一次自动批，不触发弱模型。已投递的历史摘要不会被“收回”。
3. 审计不保存整份终稿、模型思维或完整提示。仅保留定位来源、必要证据、字段差异/反向补丁、状态和时间，完整 note 前值仅在仍需安全撤销的受限记录中。审计/反向补丁保留期、容量和值得保留的去重水位须由本功能单独制定；不能清理仍可撤销批、pending 核验项或未对账回执来腾空间。不能安全记录新批时停止自动写，不能牺牲普通看板手动编辑。关闭模型仍能读/撤销旧批、核验旧标记。

## 7．可验收的边界

| 输入或竞态 | 可观察结果 |
|---|---|
| 0、20、21、500 项；含已关闭项和深度 5 的子孙 | 仅 1–20 且有候选才可调用模型；21 起手动操作照旧。|
| 两个同名“验收”；模型仅回显板上 ID；终稿为上一轮、未来计划或缺失 | 拒绝或无匹配；不写任何任务、无通知。|
| note 追加（含换行和非 BMP 字符）正好 2000/超过 1；重复引文 | 前者可提交，超界整批不写；重复不产生 note 差异。|
| 只变 status 或 note；父子同时变；顶层；100/done 单独或混合 | 摘要用提交后实值；不派生父进度。只有核验项则板版本不动、重启可见、无唤醒；混合批只通知一次。|
| 模型推理中用户改 memo、删目标、或 Fishball 先更新同一任务 | 全批 stale，无通知/自动重试；反向顺序的旧 UI 保存返回 409，草稿仍在。|
| 自动提交前崩溃、后崩溃、投递结果未知、同回执并发进入 | 查一种封套，板/审计不会半成功；不得多一个版本、重复 note 或同批再唤醒。|
| 一键撤销、重复撤销、撤销前有后改、核验/撤销竞争 | 成功为一次新版本；重复或冲突不动板、不覆盖。|
| 升级旧板、读取坏板、关闭模型、模型不可用/限流、来源能力缺失 | 旧板不丢数据、不变成空板；保留用户保存与手工工具；自动入口停止，状态页说明原因，不把失败当成功。|

回归依据：[看板黑盒用例](../../../test/v3/fishball-taskboard/cases.mjs#L653-L731) 已固定 stale 和各写入者的通知矩阵；[页面用例](../../../test/v3/fishball-taskboard-view/USE-CASES.md) 覆盖草稿保留、层级、进度、备注等。上表为新增验收建议，不声称已有这些测试或其已通过。
