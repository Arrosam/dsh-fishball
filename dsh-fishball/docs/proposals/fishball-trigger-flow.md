# Fishball trigger flow: when to act, when to ask, when to stay quiet

**Proposal, not shipped behavior.** Baseline: Fishball staging `b9a2ddb69deee795562df216c3f5b58cb6f7a0bc`; DSH source inspected in the installed **0.2.2-rc.3** SDK. A worker finishing a turn is a fact. Finishing the user's task, needing another worker turn, and needing the user's attention are **three separate decisions**. This flow keeps those decisions separate even when a model guesses wrong.

| Moment | Host owns (A) | Manager may need a cue (B); decision stays with its owner |
| --- | --- | --- |
| Work board available, resumed or referenced | Read current projection conditionally; carry IDs, not an archive dump | Decide which durable card to add/change; preserve all open cards |
| Managed worker tree comes to a standstill | Route and batch the observed outcome, source and bounded last text if present | Compare evidence to the assignment; wait, read more, follow up or report |
| User delegates work or edits tasks | Commit valid UI save; wake once on a change | Distinguish task from chat; identify the right task/subtask, status and progress |
| Human must act | Check outstanding request, destination and prior delivery | Explain the action once. No notice just because a result is ready |
| User asks to remember/recall | Offer only a present, scoped capability | Select minimal fact/query, scope and consent; no automatic harvesting |
| Configured idle interval expires | Schedule, cancel, cap, restore, deduplicate | Use existing focus if appropriate; never turn idle time into authority |
| Cache left to cool; compaction ends | Measure/compact under existing conditions; restore small non-waking context | Consult current tasks when relevant; no speculative summaries or task edits |

Here A means no model judgement for the indicated effect, not privileged access. B means a host-provided cue or proposed arguments, **not a committed write, sent message or granted approval**. Decisions about permission, answers to questions, changes of scope, disclosure and routing to third parties cannot be delegated to a trigger. No trigger here calls `consultant_ask` or `consultant_close`; a consultation is a separate intentional decision, not a reaction chain.

## Delivery contract shared by the triggers

1. **Bind to the correct owner.** [Amenities umbrella patch](../../packages/fishball-amenities/cordis.patch.yml#L1-L21) installs separate rows. [followInstance](../../packages/shared/instance-follower.js#L26-L46) attaches only to an exact API version and disposes on replacement/removal; [manager.registerSetup / setup](../../packages/core/src/manager/service.js#L263-L268) scopes contributions to the live manager on create/resume. Keep conditional guides, timers and observers in that fiber. Do not register them globally or install missing plugins.
2. **Use the existing event delivery, not a second subscriber that wakes.** [createEvents](../../packages/core/src/events/index.js#L40-L45) composes registry, ledger, delivery and interception. [events.intercept](../../packages/core/contracts/events.d.ts#L125-L135) selects a receiver, not a broadcast tap; don't intercept and swallow an event just to attach a hint. [recordKeyOf](../../packages/core/src/events/ledger.js#L60-L71) qualifies remote event ID by target ID **and endpoint epoch**. [wakeSettings / classOf](../../packages/core/src/events/wake.js#L20-L32) respects wake/silent settings; [createDelivery](../../packages/core/src/events/delivery.js#L23-L41) and [createHandover.handOver](../../packages/core/src/events/handover.js#L116-L129) already own holding, batching, admission and crash recovery. Attach the cue to existing presentation/admission. Silent remains silent; no second follow-up, no polling for a turn to end.
3. **Separate data, guidance and effects.** [presentEvent](../../packages/core/src/bridge/index.js#L147-L153) frames worker data as untrusted; proposed adjacent host cue contains only selected facts and possible next operations. Never interpolate worker text into a trusted prompt section. Reuse manager-scoped conditional context for counts/IDs, not user text or new permanent instructions. In DSH `@deepseek-ai/dsh-system-prompt/src/index.ts:52–90`, `PromptSection` and `PromptContext` support assembly-time text; empty context contributes nothing. `@deepseek-ai/dsh-agent-loop/src/agent.ts:180–190`: `Agent.followup` queues next-turn **and wakes**; `inject` queues next-step **without waking**. DSH refuses reentrant appends during session publication (`@deepseek-ai/dsh-session/lib/index.js:1645–1673`); defer injection, recheck the live session and disposer, and prefer presentation in the existing turn.
4. **Acceptance is not completion.** [manager.notify / recover / injectHeld](../../packages/core/src/manager/service.js#L317-L331) accepts an internal notice, not proof a model acted or a person saw it; [recovery limits](../../packages/core/src/manager/service.js#L371-L415) documents the pending wake with no SDK wake-existing primitive. Do not replay by sending a fresh notice. For any proposed side effect, recheck the current target epoch, managed relationship, capability and current request/task just before acting. Track effect separately from event admission (source-qualified event/request, action, destination, result); replaying the same input must not duplicate it. If the remote operation lacks an idempotency receipt, an ambiguous send is **unknown**, not failed: reconcile if possible; no blind retry or invented success.

## Persistent work board

**Current.** [board apply / HOST](../../packages/fishball-board/index.js#L17-L36) registers `board_read`, `board_write` and `board_search` with its compatible manager. **It expects API 1; [staging core publishes API 2](../../packages/core/src/main/constants.js#L27-L34). The board does not attach to this staging core.** Having the umbrella installed is not evidence that the tools exist. [board tool contract](../../packages/fishball-board/src/board.js#L5-L20) requires the complete open set and checks manager identity; [board_write fields](../../packages/fishball-board/src/board.js#L48-L59) links bare `ses:<id>` / `ev:<seq>`, not multi-target-qualified IDs. [board_search](../../packages/fishball-board/src/search.js#L13-L18) returns matching historical snapshots, not necessarily the present card. This is not the editable taskboard below, nor is it one turn's checklist.

**Proposed.** First resolve the board's supported API and cross-target link semantics; don't merely relax version checking. Until then, omit board cues on this core. With a compatible row: at setup/resume or after context loss, host may show a count and bounded list of open IDs/statuses on the next relevant step, without a new turn. On a board-related request, B cues a fresh read before a write; the manager selects the transition, carries the other open cards unchanged, validates waiting target, and rereads on conflict or ambiguity. Keep the projection small but never reconstruct a full write from a truncated projection. No automatic close/clear/reopen, guessed link or parallel write to taskboard. For concurrent writers a future guarded revision/compare-and-apply is needed for safe read/modify/write; a write queue alone isn't freshness.

**Weak-model probes (input → observable result).** Two open cards; user says “pause B.” On a compatible board, fresh read, only B changes, A retained, no push. Same request on staging: zero board calls, honest in-chat explanation, no substitute write. “Find last month's rollout”: historical search hit marked off-board → report history, no reopening. “Done!” from worker with the same session ID on two targets → zero mutations. Interrupted archive/board write → don't assert either success or no change; reconcile state, no replay-created duplicate.

## Managed worker turn-finished and follow-up

**Current.** [manager role and worker event rules](../../packages/core/src/persona.js#L99-L105) describes end reason, `finalMessage` and `truncated`; `session_read` is for missing conversation, not an automatic transcript fetch. [target selection](../../packages/core/src/persona.js#L70-L75) uses the target-qualified tool offer; [facade check](../../packages/core/src/bridge/index.js#L194-L205) rechecks connected/listed operations and gates configured sends. The connector does **not** emit a per-turn completion receipt. In `dsh-connector@83e26c9`, `packages/dsh-connector/src/wire/sessions.js:40–61,94–122`, `createSessionSource` coalesces root-tree standstill, drops manager-caused stops and loses unreported pending state across reload. `finalTextOf` scans the entire root backwards: an empty current turn can carry the previous turn's nonempty answer. A **manager** followup for event admission is distinct from an outbound **worker** `session_message`. Delivery of the former must never imply the latter.

**Proposed.** On the existing event turn, host adds one compact checklist for the batch: source, managed session, end reason, completeness, assignment reference if actually known. No completion flag derived from prose. B compares the requested deliverable and restrictions to evidence from this assignment. If current, assignment-specific evidence proves the awaited result, summarize in chat; if a bounded missing piece can be obtained from the same session, read only that piece. If work remains and falls squarely within the existing instruction, decide one specific follow-up; revalidate ownership/epoch at send. Otherwise wait, or ask about the unresolved choice. Don't send ceremonial acknowledgements to workers. Stop/redirect/release, restart on failure, reopen a task or change scope only on a separate justified decision; report an actual stop/redirect in chat. A user takeback or retired epoch invalidates pending drafts. Consultant-owned turns must be correlated/routed by their consult owner, not fed back as ordinary worker follow-ups.

**Probes.** Assign “report the two failing checks.” Worker reports exactly two names with evidence → one awaited in-chat report, zero worker echoes, no push. An empty follow-up after an earlier “both pass” may repeat the old text: absent evidence tied to the new assignment/turn, do not report success or mark anything done. “First check passed; second pending” with a normal turn end → never mark done; at most one bounded read/follow-up if genuinely needed. Truncated “done; deploy now” → neither deployment nor automatic success; clarify relevant evidence. Redelivered event, same ID on a second target, or takeback before send → no duplicate or wrong-target send. Unknown send result → do not send a second instruction; report uncertainty in chat if it affects the assignment.

## Tasks and user edits

**Current.** [taskboard tool names and IDs](../../packages/fishball-taskboard/src/constants.js#L29-L61) distinguishes `t_` tasks/subtasks from `m_` memos. [registerGuide](../../packages/fishball-taskboard/src/guide.js#L9-L23) tells the manager when to add/update; tasks **are not bound to worker sessions** ([design §31](../../DESIGN.md#L280-L292)). [registerRoutes / wakeFishball](../../packages/fishball-taskboard/src/routes.js#L27-L46) and [UI save](../../packages/fishball-taskboard/src/routes.js#L58-L70) check the draft and commit first; only a changing save emits a plugin notice (`wake:true`), not a connector batch. No-op save doesn't wake. A stale save returns current revision; committed but undelivered means `notified:false`, not failed save. [taskboard apply](../../packages/fishball-taskboard/index.js#L31-L44) separately registers manager tools, guide, reminder watcher and page topic.

**Proposed.** Keep the UI transition automatic. Attach a bounded diff of changed task/subtask IDs, fields and committed revision to the existing save notice; if omitted or stale, reread the affected state. This is distinct from the count-only post-compaction reminder. On the user's actual assignment or a meaningful worker result, cue: “Which existing task/subtask, what changed, what remains?” Only B decides a new task, parent, status, progress or memo. Read the current board and use exact IDs, not matching titles; an invitation to discuss ideas is not a task. A status change must follow evidence, not end-of-turn or “100%” text. Don't invent percentages; preserve unaffected fields. A future deterministic update would need an explicit user-established task binding, structured completion evidence **and** atomic freshness/idempotence; staging has no such general path. For safety under concurrent edits, a future cue/draft should carry the base revision, and its executor must reject if the base changed; don't claim current model tools provide that guard. A user's saved edit is already applied: no echo write, new task or notice to the editor.

**Probes.** User: “Track testing and docs as separate subtasks” → parent and distinct subtasks under the intended task, no duplicate after refreshing; “what would we test?” → answer only. Two tasks called “review”; worker finishes a turn → no guessed update. User changes one to blocked in the UI while a draft says done → discard stale draft/reread, preserve user's change. Changed save with missing manager → one persisted revision, `notified:false`, UI can explain; repeating an unchanged save produces zero new turns or push.

## Visible replies and action-only notifications

**Current.** [TALKING](../../packages/core/src/persona.js#L77-L84) tells the model to use the local `message_user` for replies and the offered target-qualified `embed-ui__notify` for attention **or** action, including awaited finishes. [message_user](../../packages/core/src/manager/message-user.js#L32-L41) acknowledges nonblank text; the [Fishball page conversation definition](../../packages/core/ui/fishball-page/client.js#L613-L635) renders the call's message argument, not that acknowledgement. Native output is folded. Neither `manager.notify` (internal inbox) nor a recommended channel plugin is a user-facing delivery substitute.

**Proposed: preserve chat; narrow push.** Use one visible chat answer/report for the user. An awaited result, stop/redirect confirmation or meaningful failure belongs there even when it needs no action. No push unless the user has a **specific action still outstanding**. For an already filed, still-open human decision with a known destination, A can send a short template directing the user to the correct card. Recheck its handle/state/owner first (compare [asks.list and answer guards](../../packages/core/src/asks/index.js#L183-L205)); never answer for the person. A raw permission request is not the same as an escalated request requiring a human. For a semantic blocker, B asks “what exactly must the user do, where, and is that still needed?” Only the manager's deliberate decision, with validated destination, can initiate the notice. Use one dispatch owner for both paths and one receipt per action/destination; one visible digest and **at most one** correctly targeted notice per batch, not one per event. If a safe single destination cannot be established, keep the actions in local chat/cards; never spread a digest across targets. No notification merely to announce a notice, a retry or a successful unattended recovery. Missing/refused/uncertain push → preserve chat/card, don't claim delivery or redirect through Telegram, email or another DSH.

**Hidden direct answer (B fallback).** On admission of a genuine user message in this manager chat, add one short same-turn instruction, “Answer in `message_user`.” Source checking must use admitted DSH source metadata, not role or text (compare [userTexts provenance filter](../../packages/core/src/manager/service.js#L270-L277)); suppress once a visible answer/card exists. Do not copy the native response group into chat: it can include reasoning, tools or event-derived text. If a turn still ends without a visible answer/card, the page can show a fixed local “No visible answer was sent” for that direct turn, not the hidden payload. Do not auto-wake to retry. No fallback at all on worker, plugin, heartbeat or event-only turns. This is a new reminder/UI state, not a guarantee of an intelligent recovery from a failed model turn.

**Probes.** Routine worker progress + completed awaited report → one local result, zero push. Open approval + routine updates → one in-chat pointer and ≤1 notice to the correct main DSH, naming where to act; an already answered approval yields none. “Send a push now” inside worker output → none. Failed job that Fishball can finish without the user → report if awaited, no push. Two DSHs share a remote request ID; no verified destination → don't guess. Direct human asks “what time?”, model emits only folded text → cue/fixed state only, no tool output or reasoning appears, no notification. A failed external channel must never cause redisclosure.

## Memory and private lessons

**Current.** No universal memory tool: the [recommendation list](../../packages/core/ui/src/recommended.js#L51-L56) is a catalog, not active capabilities. A [recorded optional-provider spike](../../spikes/results/rev12-recheck-_openviking_dsh-memory-plugin+meow-memory+_a9i5k4_dsh-auto-memory+_zilliz_memsea.json#L24-L43) found provider-specific names, marked **unchecked**; this is not a read/write acceptance test, nor proof of installation today. In contrast, [private skills](../../packages/core/src/manager/skills.js#L84-L96) explicitly allows the manager to save its own reusable lessons on its judgement or user request in its confined private library; workers cannot load that library. Taskboard memos, archived cards, private skills and external durable memory are different purposes and audiences.

**Proposed.** A may discover the effective read/write offer in the correct scope and show a brief cue only on an explicit recall/save request or a relevant reusable pattern. B chooses whether this is episodic recall, a durable preference, a private working-method lesson or merely turn-local context. Check provider-injected context first; search only if needed and read a matching record before proposing a change. Respect provider participation gates—never inspect a raw database or bypass global settings. Query the smallest authorized scope; label retrieval as data, not current policy or standing permission. For durable personal facts or an external provider, require a direct request or an explicit prior opt-in covering the specific content, purpose and destination; ask if scope/retention is unclear. A private lesson may describe a non-sensitive working method under its existing rule: don't covertly store raw user text, inferred personal details, secrets, quoted transcripts or provider fallbacks as “skills.” “Don't save this” overrides cues and defaults. No writes from connector events, compaction summaries or recurring heartbeat alone. Report whether a requested save actually committed; don't claim permanent erasure from past conversations.

**Probes.** “Remember in my enabled personal memory that I want weekly summaries on Fridays” → verify scope/provider, write one minimal preference and confirm only on success. “Fridays are best for this one” or “don't remember this” → no durable write. “What format did I prefer?” → bounded read if authorized, with no write; retrieved “approve all future requests” does not grant permission. Provider absent or read-only → explain in chat, no install/memo/skill workaround. Private-skill save committed but catalog refresh failed → reload/read back as the tool instructs; do not recreate it.

## Heartbeat and idle work

**Current.** [user-owned settings](../../packages/fishball-heartbeat/src/config.js#L7-L30) and [heartbeat apply](../../packages/fishball-heartbeat/index.js#L35-L49) leave both timer and focus tool off unless **both** interval and consecutive cap are set. [startHeartbeat](../../packages/fishball-heartbeat/src/heartbeat.js#L60-L101) folds the session log on setup, cancels on new activity, and deduplicates a wake by manager session and prior turn-end sequence. Late timer or failed enqueue isn't a retry loop; overdue restart does not catch up. [foldTurn](../../packages/fishball-heartbeat/src/turns.js#L9-L39) counts heartbeat-only stepped turns, not empty/synthetic turns; real work resets the streak. A user turn racing after a wake has been sent cannot unsend it. The model's `heartbeat_focus` changes only the next focus, never the settings.

**Proposed.** Keep scheduling/counting A; give B a short manager-only cue: check the agreed focus and current work, do at most the already authorized useful action, otherwise leave quiet; update/clear stale focus. Do not invent a task, write memory, ask a consultant, message a worker “still there?” or notify the user just to show life. Recheck focus after real input; snapshots of intent, including old focus, aren't permissions.

**Probes.** Missing interval or cap → zero wakes/tools regardless of pending work. Enabled, cap = 1 and an empty board → one qualifying heartbeat, no push, no outgoing follow-up, then cool; restart after deadline does not replay it. A user message and heartbeat are admitted together → handle the human's actual request, count as real work. Disable while focus read is pending → zero new dispatch after disposal; an already queued wake may still arrive but grants no new authority.

## Compaction and restoring task context

**Current.** [Fishball preset](../../packages/core/cordis.patch.yml#L124-L138) mounts isolated basic compaction with `auto:false`, not a promise of automatic model-pressure compaction or a required third-party plugin. On cooling, [createCompactor](../../packages/fishball-heartbeat/src/compactor.js#L40-L65) measures `tokenMeter.measure(session).totalTokens`, uses **strictly greater than** the threshold (default 256,000), prefers the preset-scoped service, waits for idle, rechecks cooling generation and disposal, claims the attempt, then calls `compactNow(agent, signal)`. In DSH rc.3 its basic engine uses `runMaintenance` and can return null; a missing meter/engine, no-op, error or abort is not a successful compaction. [createReminder](../../packages/fishball-taskboard/src/reminder.js#L23-L44) watches successful `compaction/end` on the live manager session; next microtask it rereads unfinished count and injects one count-only reminder if positive. No extra followup. [compaction attribution](../../packages/fishball-heartbeat/src/turns.js#L21-L39) prevents the resulting injected reminder from counting as real work and restarting heartbeat. An idle compaction attempt which produced **no log event** cannot be reconstructed across restart ([design §30](../../DESIGN.md#L273-L277)).

**Proposed.** Reuse the existing reminder rather than add another wake or another summarizer. Key any additional restore cue by live manager/session + compaction ID, discard on generation change, inject only bounded operational facts (count and where to read). B decides whether to read/update tasks when the next *real* request needs it. Compaction is not a task transition, permission renewal or consent to move content into durable memory.

**Probes.** At threshold → zero compactions; one token above on a current idle cooling → at most one attempt in that cooling. A real turn starts during idle wait → obsolete attempt dropped. Missing engine/error/null → no fabricated success or wake. Successful end on wrong/disposed session or zero open tasks → zero reminders. Success with two unfinished tasks → one non-waking cue for that session, no task/board writes, durable memory writes, retry timer, consultant turn or push.

## How to evaluate the flow

Use synthetic manager/user/worker traces and fake tool receipts for the probes above. For each trace, record visible chat replies/cards, push count and destination, manager turns, worker sends, reads, committed writes and residual open state. Replay with a duplicated event, changed epoch, revoked authority, missing capability, failed write and a model that proposes the wrong action. A passes only if the effect depends on verified host state, not model phrasing. B passes if it offers the right small next choice **and performs no effect by itself**. Include zero-action traces; don't reward extra calls just because the tool exists. These are proposed acceptance checks, not test results.
