# B1 — What Claude’s advisor actually does

**Finding:** the executor chooses *when*, not *what to send*. Its call is `advisor()`. Anthropic supplies the transcript and runs the second model; the executor retains the task. A Fishball consultant taking a focused question and selected evidence would borrow the division of labour, not the wire protocol.

### Evidence and limits

Checked the public [Claude Code guide](https://code.claude.com/docs/en/advisor), [Claude Messages API reference](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool), and Anthropic’s [Python SDK type, `BetaAdvisorTool20260301Param`](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/types/beta/beta_advisor_tool_20260301_param.py) on 2026-11-25 UTC. **Documented** below means vendor description, not an observed paid call. **SDK code** confirms client configuration fields, not server internals. No claim below relies on model memory.

| Question | Verified evidence |
| --- | --- |
| **What is called?** | **SDK code + [API: how it works](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool#how-it-works).** The client declares `{type:"advisor_20260301", name:"advisor", model:…}` under `tools` with the `advisor-tool-2026-03-01` beta header. The model emits `server_tool_use(name:"advisor", input:{})`. No question string, session ID or hand-built brief. In Claude Code, `/advisor` selects/enables a model; it is **not** a command to run a consultation immediately. |
| **What can it see and do?** | **[API: how it works](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool#how-it-works).** A separate, tool-less inference receives the executor’s full transcript *as quoted context*: executor system prompt, tool definitions, prior turns and tool results, and generated text so far in this turn. That is not direct access to files, other sessions or tools. No extra application round trip normally; a paused turn is an exception. |
| **What comes back?** | **[API: result variants](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool#result-variants); [Code: session view](https://code.claude.com/docs/en/advisor#what-you-see-during-a-session).** A matched `advisor_tool_result` brings strategic advice (plan, correction or check) into the executor’s continuation; advisor thinking is dropped. Clients get human-readable `advisor_result.text` or model-dependent `advisor_redacted_result.encrypted_content`, not necessarily readable prose; round-trip the original blocks. The UI distinguishes reviewed, declined and unavailable. Advice is neither a user-facing answer nor authorization to act. |
| **Who pays?** | **[API: usage and billing](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool#usage-and-billing); [Code: cost](https://code.claude.com/docs/en/advisor#cost).** Add the advisor’s input and output at its own model rates to executor usage. API top-level usage is executor-only; look at `usage.iterations[]` entries of type `advisor_message` for advisor charges. The guide gives a typical 400–700 advice-text tokens, 1,400–1,800 including thinking; these are examples, not limits. Claude Code subscription usage consumes plan allowance or applicable usage credits. Code documents an uncached advisor reread; the Messages API separately offers opt-in [advisor-side caching](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool#advisor-side-caching), off by default. Savings versus using the larger model throughout are task-dependent, not savings versus never consulting. |
| **What prompts it?** | **[API: suggested executor prompt](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool#suggested-system-prompt-for-coding-tasks).** The built-in description encourages early calls for complex tasks and calls at difficulty. Published *example executor instructions* recommend orienting first, consulting before substantive decisions, and checking difficult work against durable results. They also advise reconciling advice with contrary evidence. The advisor itself has an Anthropic-supplied system prompt. Its exact deployed text and Claude Code’s exact internal executor instructions are **unknown here**; the examples are not a prompt dump. |
| **Who chooses when?** | **[Code: timing](https://code.claude.com/docs/en/advisor#when-claude-consults-the-advisor); [API: nudging](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool#mid-conversation-nudge-for-under-calling-executors).** Normally the executor decides: plan choice, recurring error, change of approach or completion check, not “every N turns”. A user can request it; Claude Code exposes no force/cap setting. Direct API clients can nudge an under-calling model, use supported `tool_choice` to force a specific request (model/thinking restrictions apply), or set `max_uses` *per turn* and `max_tokens` *per advisor call*, including thinking. No built-in conversation-wide call cap. A prompt is not a guarantee. |

### Implications for Fishball (proposal, not staging behaviour)

- **Keep dispatch separate from judgment.** At staging `b9a2ddb`, [`createInterception.toFishball`](../../packages/core/src/events/interception.js#L83-L97) adds the won ledger record to delivery and acknowledges it; [`createHandover.handOver`](../../packages/core/src/events/handover.js#L116-L130) sends a follow-up at true idle. Neither obtains an advisor answer. Don’t make ordinary wake/delivery contingent on paid inference.
- **Choose the context contract explicitly.** Empty input spares a weak executor from summarizing, but only works because Anthropic supplies the complete conversation. Crossing a Fishball target/provider boundary changes both disclosure and cost. Prefer host-selected, bounded evidence and an explicit decision to review; record what was omitted rather than implying the consultant saw the workspace.
- **Keep the answer advisory.** Return a short next step, supporting evidence and uncertainty to the executor; treat decline, timeout or unavailable as no advice. Do not send it to the user, mutate a board, or grant permission as a side effect. Cap calls and output, and measure actual usage and wait time before adopting automatic triggers. Fishball call frequency, cost and quality improvements are **unmeasured**.
