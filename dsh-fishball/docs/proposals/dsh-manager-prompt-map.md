# What the Fishball manager inherits from DSH

**Finding:** With the shipped Fishball preset on DSH Web, the manager keeps the harness identity, read/file-reference guidance and Web UI guidance. It does **not** inherit the Web coding persona, the harness checkout, or a standard coding agent's tool manual. The working directory and effective permissions still reach the model, but as runtime context, not system prose. Moving Fishball's own instructions behind a tool would change none of these host contributions.

**Scope.** Source audit, not a captured request: Fishball staging base `b9a2ddb6` and published DSH **0.2.2-rc.3** package sources. Host paths below are relative to the package named (under `@deepseek-ai/`). No live profile, settings, messages, memory, credentials or server responses were inspected. “Retained” means emitted under the stated source conditions, not an instruction to copy the text into Fishball's persona or a byte-for-byte guarantee for a deployment.

## How to tell what reaches the model

1. Apply `dsh-base/cordis.patch.yml`, then `dsh-web-app/cordis.patch.yml` and its preset declarations, then [Fishball's core patch](../../packages/core/cordis.patch.yml#L24-L57). Later bundle, owner and launch overrides can change the result. The hosted child's launch overlay can also change instruction/skill roots; it is not a reason to assume the parent's plugins or files are in the child's scope.
2. The [Fishball preset](../../packages/core/cordis.patch.yml#L107-L138) replaces the Web preset choice. On create/resume [manager composition](../../packages/core/src/manager/session.js#L345-L376) mounts the selected preset, applies the manager's persona, then runs manager setup. A previously published agent resumed by another owner **keeps its mounted preset**; setup does not remount it. The [persona registration](../../packages/core/src/manager/persona.js#L30-L46) shadows entries by name in the manager scope, not across the host.
3. Count the right thing. In `dsh-agent-loop/src/agent.ts:447–485`, rendered nonempty **sections** become system-message updates; refreshed **contexts** are projected separately as runtime-context user messages when needed. Other admitted pre-step messages and transcript history are separate again. **Tool schemas** come from `assembly.tools` at request build. Neither a registry order constant nor an installed package proves any text was emitted. A literal `<system-reminder>` tag does not determine message role.

**Not part of the native manager preset.** Web disables the base host rows for filesystem/search/shell tools, plans, goal tools, subagent/control/workflow, skill loader, workspace instructions, todo and Web tools; presets can reintroduce them (`dsh-web-app/cordis.patch.yml`, “presets” overrides). Core disables standard, PTC, Cordis and minimal presets. Its preset re-adds only read/read-image filesystem tools, native `ask_user_question` and an isolated compaction backend with `auto: false`. The base working-directory service/tool is separate. Thus no default write/edit/patch, shell/search, delegation, AGENTS.md or native skill-catalog manual follows from the installed SDK. Structured-output and delegation context for a subagent are **child** registrations. The native executor projects schemas only (`dsh-tool-executor-native/src/index.ts:15–17`); a PTC SDK reference, computer-use manual, or another executor's sections would require its own effective configuration, not just an order slot.

**Fishball-owned boundary.** The persona plus taskboard/board guides are not inherited DSH copy. Core also registers `fishball-private-skills` and six private-skill tools only in the manager generation with a skill registry ([setup and section](../../packages/core/src/manager/skills.js#L213-L255), [registry guard](../../packages/core/src/manager/skills.js#L322-L331)); the file-write exception is not generic host guidance. Target façades, reminder tools and `message_user` register in [manager setup](../../packages/core/src/main/index.js#L157-L168). Their descriptions/parameters are tool schemas; an actual reminder, incoming offer, receipt, delegated transcript or tool result is conditional history/input. A UI notification is not even model input unless an owner admits a message. Do not count either as fixed system prose.

## Two meanings of “manager” at the connector

The **Fishball manager** is an agent composed by core. A **connector manager** is a principal recorded for a remote **root session**: `managerOf(rootId)` controls ownership, visibility and routing; managed interaction tools can send offers to that principal. Assigning or releasing it does not install a prompt section in the Fishball agent. See `dsh-connector/packages/dsh-connector/mcp-schema/README.md:157–192` (sibling checkout, staging `83e26c9`).

The **adapter** is a client bridge, not another persona: `packages/dsh-connector-adapter/src/proxy.js:1–8` describes its native MCP-client child row per server. A scoped adapter client can expose discovered tool schemas, resources and any actual server instructions through the native rows above. The checked connector endpoint constructs its server with capabilities/limits, not a fixed manager instruction string (`packages/dsh-connector/src/mcp/http/endpoint.js:201–212`). A Fishball target façade instead registers tools through core's setup; do not count an adapter's MCP section a second time merely because Fishball has a paired target. Tool descriptions, discovery results and forwarded messages are distinct surfaces.

The separate instance onboarding list (`dsh-fishball-instance/packages/dsh-instance/client.onboarding.js:63–69`) also offers `billion-context`. Fishball's own catalogue explicitly excludes it because it edits other rows; its 0.1.206 `dsh.bundle.patch.yml:21–39` targets host compaction and stock presets. Do not infer a change to Fishball's isolated preset, or a fixed manager system section, simply from the onboarding entry.

**Design implication:** Leave inherited guidance and safety context with their current owners. Put only Fishball-authored, always-needed rules in a Fishball baseline count. Report optional system sections, runtime snapshots, notices/history and tool schemas separately: moving a paragraph to a tool description or an always-delivered notice changes its location, not necessarily its per-request cost.
