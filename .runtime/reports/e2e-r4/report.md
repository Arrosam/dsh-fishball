## P1 — R4-02: Child language choice is lost after host reload

1. Start with both host and child in English. Use the child's **DSH settings** gear (inside the frame, not the host Account menu or the Fishball core plugin settings) → General → Language → `中文`, then close Settings.
2. **Before reload:** host showed `Workspaces`, `Fishball running`, `Refresh`. The child showed `收起侧边栏`, `插件`, `DSH 目标`, `已连接`, `设置`, `Fishball 设置`, `DSH 设置`, `更多操作`, `打开右侧边栏`, `对话`, `轨迹`, `轮次导航`.
3. Reload the same browser tab and reopen the Fishball sidebar entry. **Actual:** host remained English; child now showed `Collapse sidebar`, `Plugins`, `DSH targets`, `Connected`, `Settings`, `Fishball settings`, `DSH settings`, `More actions`, `Open right sidebar`, `Chat`, `Trajectory`, `Turn navigation`. No failure banner or dialog appeared. **Console:** `(no console messages captured)` on the post-reload sample.
4. **Expected:** the child stays Chinese across a host-tab reload with no intervening host-language change. This is a loss of the explicit language choice, not a recurrence of R3B-07 or a failure to load chat. Source review shows that a fresh embedded document applies the host language again after the child's saved settings load; browser evidence does not independently show a failed settings write.
