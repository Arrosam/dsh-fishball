# R-FIX-REDACT: the redactor (`dsh-connector-shared/redact`)

Source: the R-FIX-REDACT requirements relayed with the task (2026-11-18). Expected outputs come from
them only, never from `redact.js`. The rows are data in [constants.mjs](<constants.mjs>) (`REDACT_ROWS`);
[cases.mjs](<cases.mjs>) registers them for each SDK. Each test name is `<case id> <row> [SDK x] <title>`.

Every row checks three things: the exact output; every planted secret substring is absent from the
output; and `redact(output) === output` (idempotence). The mask text is exactly `[redacted]`.

## Requirements under test

| # | Rule |
| --- | --- |
| R1 | A name is a bare identifier or a quoted one (`"…"`, `'…'`, or escaped JSON `\"…\"`). It is split at camelCase, acronym and non-alphanumeric boundaries. It is sensitive if any component is exactly token, key, secret, password, credential or authorization, or that word plus `s`. `APIKEY` and `apikey` are one component, so they stay unchanged (a known limitation). |
| R2 | The separator is `:` or `=` straight after the name. After a quoted name (`'…'`, `"…"`, `\"…\"`) `=>` is one too, for util.inspect's Map entries. After a bare name `=>` is an arrow function, so it is not a separator (the second review, 2026-11-18). The separator is with optional spaces or tabs on either side and no newlines. A name with no separator masks nothing. |
| R3a | A quoted value has its contents masked and keeps its delimiters. Escapes are honoured, one level of escaped JSON included. An empty value stays as it is. An unterminated value is masked to the end of its line. |
| R3b | A container (`[` or `{`) is masked whole, and the brackets inside strings do not count. A container may span lines. An unbalanced container is masked to the end of the text. Inside a container, a `'`, `"` or `` ` `` opens a string only when an unescaped closing quote follows on the same line. A quote with no closer on its line is an ordinary character (the second review, 2026-11-18). There is one exception: a string that runs to the end of the text still opens (the third review, F2, the shape the F4 cut's head can end in). An escaped quote (`\'`, `` \` ``, `\"`) opens no string (F1). After an escaped key (`\"name\"`), the container is read in escaped mode: its strings are `\"…\"` (an inner `\\\"` does not end them), and a raw `"` also ends the container. An escaped string not closed by `\"` ends at the raw `"` or at its line end, and counting resumes on the next line. With no raw `"`, an unbalanced escaped container still runs to the end of the text (the review, 2026-11-18). |
| R3c | An Authorization name with an unquoted value is masked to the end of the line, scheme included. |
| R3d | Any other sensitive name with an unquoted value has its run masked. The run ends at whitespace, `"`, `'`, `,`, `;`, `&` or the end of the text. A leading `Bearer` or `Basic` (any case) is masked together with the next run. |
| R5 | A backtick is a quote wherever a quote is: in quoted values and in strings inside containers. util.inspect uses it for a string that holds both `'` and `"` (the second review). |
| R8 | About 64 KiB of adversarial input (quotes, nesting) redacts in under one second (the second review). |
| R4 | A standalone `Bearer <run>` keeps its scheme and masks the run. Only spaces or tabs may come before the run, never a newline. A standalone `Basic` is not masked. |
| R5 | A run of 32 or more characters from `[A-Za-z0-9_+=-]` is masked. `/` and `.` split runs. |
| R6 | Overlapping or touching masks merge into one. |
| R7 | The function is pure and stateless. Unrelated text comes back unchanged, and several credentials in one text are all masked. |
