原生 DSH 插件个人助理 · 2026 年 10 月 4 日 · 拟议需求与验收方案
结论与阅读方式
bubbles 是依附 DSH 运行的开源原生插件，简称 bub。建议先完成可信的任务与授权账本、DSH 会话控制和
隔离存储，再接入远程聊天与事件唤醒。目标是把成熟个人助理可观察到的体验做完整，而不是重新造模型执
行框架。
这份评审把 16 张拟议工单一次性放在一起，供 owner 慢慢读。BUB001 至 BUB016 是本地规划编号，还没有
创建远程 issue，也没有开始实现。每张工单都给出目标、边界、依赖、可验证验收标准和评审结论；待决事项
统一汇总在最后，避免边读边被追问。
建议的交付形态是一个可配置的 preview 插件：主对话接住用户，工作会话做事，事件唤醒推进未完成任务，
持久化保存任务与记忆，最后给出有证据的结果。整个开发与发布链默认 preview；只有 owner 明确指定的版
本才标记 stable。
已经确认的产品边界
复用 DSH 的执行循环、模型接入、工具、环境和权限系统。bubbles 负责助理产品层：任务调度、上下文连续
性、受控会话间消息、聊天适配、事件、记忆和结果呈现。插件不能替宿主绕过权限，也不能把模型的建议变
成用户授权。
DSH 完整退出后 bubbles 停止；本期不需要独立 daemon，也不要求完整退出后继续执行。关闭窗口与完整退
出是不同状态。重启后需要恢复可恢复的任务状态，但不能宣称离线期间一直工作。
复用 fishball 的记忆代码，不复用整个 fishball 应用；与 Hydrogen 独立。默认建立 bubbles 自己的数据空
间，不能自动接入或共享现有个人数据。远程聊天是控制入口，不意味着工作自动迁移到另一台机器。
owner 当前的执行偏好可作为可配置预设：agent prompts 用英文，不使用 Astra；编码用 Sol 6.1 且思考等级
不低于 high，根因分析 max，视觉验证 xhigh。模型不可用时明确报告，不能偷偷降级。
事实与尚未验证的部分
静态检查基线：已安装 Desktop 0.9.1、Harness 0.1.5-rc.2、CLI 0.1.1-rc.2；观察到上游 0.2.1-alpha.1。这些
版本并不等于已选定支持范围，也不能由上游文档反推旧版本具备所有能力。BUB001 必须用选定版本做运行
验证。
公开插件服务存在创建、恢复、消息、事件、流和取消等会话能力，但接口仍属稳定前阶段。父子会话消息有
作用域；不相关会话的通信需要 bubbles 自己的 broker 和明确授权。SDK stdio 路径会启动独立 runtime，不
能把它与原生插件服务混为一谈。
现有后台 jobs 只在内存中保存；webhook 不提供完整的持久队列、去重与回放。fishball MemoryStore 是可
注入持久化的 Kotlin/JVM 内嵌代码，尚未证明可直接作为 JS 插件依赖使用。Kotlin/JS ESM 是候选移植路
线，不是已验证方案。

产品结构与交付顺序
建议的产品结构
入口层接收 DSH 主对话、首个远程聊天适配器和已认证事件。记录来源、owner、workspace、对话、任务和
幂等标识；只保留最小必要、脱敏且可核查的证据与来源引用，原始 payload 不默认长期保存，不进入普通日
志或记忆。转发内容和 webhook 文本不能授予权限。
协调层维护主对话、任务状态、授权范围、调度和消息 broker。任务与审批账本是事实源；语义记忆只是可纠
正的辅助信息。工作会话从 DSH 创建或恢复，继承最小必要上下文，结果经过独立检查后才更新任务结论。
存储层保存任务与审批记录、事件收件箱与发件箱、会话关联、配置版本和隔离的记忆。可分别实现这些职
责，但每次状态变化都要能追溯；不存在一份模糊总结同时承担任务、权限和记忆的设计。
呈现层在主对话和任务面板展示进展、阻塞、产物及操作。accepted 表示服务已受理；sent 表示已向渠道发
送；delivered 仅在渠道提供可信回执时使用。创建会话、会话 ready、正在执行也必须分别呈现。
共享的交付门槛
每张工单都走同一条链：idea → triage 与验收标准冻结 → 开发 → 独立代码评审 → 独立 ISTQB 风格测试评审
→ 实际功能与视觉验证 → 报告。评审者不得由原实现者自签；发现问题回到对应工单，不拖到 BUB015 或
BUB016 才处理。
每个验收标准绑定可重跑的测试和证据：版本、环境、输入、预期、实际结果、日志或截图、失败原因。纯静
态阅读不能算成功运行；视觉截图也不能替代功能断言。发布时保存需求到证据的追踪关系。
全局红线是隔离与可解释：无身份或越权事件不调度；过期审批不沿用；取消不撤销已完成外部效果；不保证
任意外部动作 exactly once；没有渠道回执不保证送达；没有模型用量数据不报告精确成本。
依赖顺序与可并行工作
第一波做 BUB001、BUB003 和 BUB006 的最小底座，先确定宿主能力、隔离键、任务与审批事实源。
BUB007A 可并行做记忆抽取与移植验证；接口固定后，BUB010A 可并行研究一个聊天 provider。
第二波做 BUB002、004、005、008、011、012，组成主对话到受控工作会话的闭环。BUB004 与 005 用同一
组任务和会话标识；资源边界须在开放无人值守并发前生效。
第三波做 BUB007B、009、010、013、014、015，完成记忆、唤醒、远程入口、交付、控制面板和运行时独
立审查。接口明确后可并行，不能用并行开发跳过安全依赖。BUB016 贯穿证据收集，最后做全链发布验收。
首个可体验纵向切片建议是 DSH 内主对话 → 一个工作会话 → 本地产物 → 独立检查 → 对话与面板报告。之后
扩展到单一远程渠道及事件唤醒；这只是开发顺序，最终范围仍包含全部 16 张工单。

BUB001 原生插件启动与版本兼容
目标 让 bubbles 作为 DSH 原生插件可加载、可卸载、可诊断，并明确实际支持的宿主版本。
范围 包含依赖声明、配置校验、宿主能力探测、生命周期和兼容矩阵。排除自建 harness、独立 SDK
runtime、daemon 与 DSH-X 启动器。
依赖 底座工单；BUB003、004、005、009、011 依赖其可用能力。
预期行为 加载时核查必要服务，缺少能力则禁用对应功能或安全停止；卸载时注销监听、入口及资源。相同插
件反复重载不能增加重复 handler 或把旧配置保留成隐形权限。
验收标准
BUB001-01 在 owner 选定的基线版本安装、启动、重载、卸载均有运行证据；不支持版本显示具体差异和处
理建议，不半初始化后接受任务。
BUB001-02 连续 10 次重载后，一个输入只产生一个入口记录；无残留监听、重复调度或新增孤儿工作会话。
BUB001-03 缺失必要会话或权限服务时，不执行相关任务；诊断标明实际检测结果，不能只看版本字符串。
BUB001-04 关闭窗口后用宿主状态确认是否仍运行；完整退出后插件停止。重新启动由 BUB003 对账恢复，
不盲目重发外部动作。
BUB001-05 同一配置在 Desktop 与 CLI 上分别记录已验证、未验证或不适用；文档不以一端成功代替另一端
兼容。
异常与竞态 卸载与事件同时到达；升级与正在运行任务并发；配置解析失败；服务晚于插件出现；旧缓存与新
接口不一致。每种情况须有确定的停止或重新核查路径。
评审结论 可以进入 triage，但必须先选定一条真实运行基线。建议先验证当前安装组合，再评估是否需要升级
到上游 alpha；不把升级当成默认授权。
统一待决项 D1 支持版本与首发环境；维护兼容范围及升级策略。

BUB002 主对话接单与用户打断
目标 用户能随时提出新问题、纠正方向或停止任务，主对话持续可用，长任务不把交流锁住。
范围 包含请求归类、任务关联、澄清、优先级、打断和消息合并。排除用聊天内容直接执行未批准的高风险动
作，排除承诺瞬时中断正在发生的外部动作。
依赖 BUB001、003、006、008；工作执行接 BUB004、资源约束接 BUB012。
预期行为 收到新消息先登记再判断是新任务、已有任务补充或控制命令。能安全独立开展的工作继续；缺少必
要决策时只暂停依赖分支。优先处理用户的新消息，旧任务保持可见。
验收标准
BUB002-01 主对话接收同一 provider message id 的重复投递只建立一个入口；用户刻意重发但拥有新 id 的
消息保留，不按文本相同误删。
BUB002-02 同一任务运行时用户修改约束，任务版本递增；后续工作看到新版本，旧结果不得覆盖新要求。
BUB002-03 用户说停止时先停止新派发，再请求 DSH 取消；呈现已请求、已停止或结果不确定，不能在未确
认时写已取消。
BUB002-04 新问题与长任务并发时，无须等待整个工作会话结束才能接收输入和查询状态；响应性能在
BUB012 的选定环境下测量。
BUB002-05 确需澄清时，把相关决策一次汇总；可从已有上下文确定的事项不重复追问，也不把沉默当批
准。
异常与竞态 消息乱序；用户纠正与完成通知同时到达；多个远程入口同时改同一任务；删除了原消息；用户停
止后工作会话晚到的结果。
评审结论 保留为独立体验工单。关键不是一段欢迎语，而是用户能插话、能改方向、能看清停止是否生效。必
须测试并发消息与版本冲突。
统一待决项 D3 首发输入与响应性能目标；任务优先级是否允许 owner 配置。

BUB003 持久任务状态与恢复
目标 任务不因窗口关闭、崩溃或重启被遗忘，且恢复后能够区分事实、推断和待核查结果。
范围 包含权威任务账本、审批引用、状态版本、检查点、恢复对账、迁移、保留与导出删除。排除把记忆摘要
当账本，排除任意外部副作用 exactly once 保证。
依赖 BUB001、006；与 BUB004、005、009、013 共同定义关联标识。
预期行为 任务建议状态为待接单、排队、运行、待用户、阻塞、恢复核查、完成、失败、已取消。批准是另一
条独立记录，绑定动作、目标、数据、限制与版本。恢复时先查询实际宿主或外部状态，再决定可继续、需人
工确认或仅报告。
验收标准
BUB003-01 在登记前、登记后派发前、派发后回执前、动作完成后落盘前注入故障。持久受理后的任务必须
可恢复；受理前仅在来源支持回放时可补收，否则声明接收缺口，不确认已受理；回执缺失不盲目重做动作。
BUB003-02 两个入口或 worker 并发更新同一任务时，以版本检查拒绝旧写入；历史保留变化原因与证据，完
成态不得被旧进度倒退。
BUB003-03 磁盘不可写、存储损坏或空间不足时，显式进入受限状态，停止需持久保证的新操作并提示风
险。
BUB003-04 升级迁移前保存可恢复副本；新旧 schema、不完整迁移及回滚均有测试，不覆盖不能理解的数
据。
BUB003-05 导出包含状态、来源、时间与产物引用；删除后禁止重新调度，按确认的保留范围清理，不能把
无法控制的第三方副本宣称删除。
异常与竞态 终态通知乱序；外部动作成功但宿主断电；审批已撤销而队列尚未执行；备份恢复把旧任务带回；
同一 owner 多 workspace 数据碰撞。
评审结论 这是优先级最高的基础工单之一。建议使用明确可核查的状态存储和动作台账；存储具体选型可在
triage 比较，但一致性合同必须先定。
统一待决项 D4 保留期限、备份与恢复策略；导出格式和删除范围。

BUB004 工作会话创建恢复与控制
目标 把明确的工作交给 DSH 会话，并知道它是否创建成功、准备就绪、正在执行或已经结束。
范围 包含创建、恢复、发送任务、查询当前状态、流事件、取消、结束和孤儿会话处理。排除另起 SDK 执行
栈；不要求上游没有公开提供的单会话关闭能力。
依赖 BUB001、003、006、008、011、012；状态回报接 BUB013。
预期行为 任务与会话映射持久保存。创建成功不等于开始执行；ready 后才派发。恢复既有会话前确认
owner、workspace、任务版本及宿主能力。取消用宿主真实接口，并通过事件或当前查询核实结果。
验收标准
BUB004-01 分别显示创建请求已受理、会话已创建、ready、执行中、结束或状态未知；每一步都有真实服务
响应或状态证据。
BUB004-02 创建超时但随后发现会话存在时，关联已有会话，不重复创建第二个执行者；无法判定时保持核
查态。
BUB004-03 恢复既有会话后执行一项可观察工作并得到产物；不存在或不属于当前授权范围的 session 不恢
复。
BUB004-04 取消请求与完成并发时，保留实际已完成效果与晚到结果；不宣称已经撤销外部发送、文件修改
等既成效果。
BUB004-05 事件流断开后通过当前查询与账本对账；重新订阅不会把历史事件当新任务，也不会丢失终态。
异常与竞态 宿主繁忙或模型未就绪；创建后插件重载；会话在取消前已经完成；用户手动关闭工作会话；恢复
到不同环境。
评审结论 可以实现，但每个宿主版本要验证具体服务能力。SDK 缺少 promptcancel 或 per-session close 不
等于原生插件一定缺少取消；反向推断同样不可用。
统一待决项 D1 基线接口；孤儿会话的自动回收范围和 owner 控制入口。

BUB005 受控跨会话消息
目标 主对话、工作会话和独立审查会话能够交换需要的信息，不让任意会话读取或指挥其他任务。
范围 包含消息 broker、授权作用域、路由、关联、幂等、回执和可观测失败。排除默认开放所有会话互通；父
子通信能力不能当作无关 session 的通行证。
依赖 BUB003、004、006；输入上下文由 BUB008 控制，交付由 BUB013 控制。
预期行为 每条消息关联发送方、接收方、owner、workspace、task、消息 id、任务版本和用途。broker 从宿
主可信调用上下文核实发送方，不相信 payload 自报身份；按当前 grant 校验再派发。会话重建或标识复用不
继承旧 grant。
验收标准
BUB005-01 父子会话的状态回报可到达已授权父会话；无关会话未经明确 grant 发送消息时被拒绝，并留下
不含秘密的拒绝理由。
BUB005-02 grant 绑定任务或有界会话集合与消息类别；校验与派发记录绑定同一授权版本，定义撤销和派发
的先后判定点。撤销先发生则拒绝；已提交动作标为在途，不宣称撤回既成效果。
BUB005-03 按完整作用域和持久消息记录防止已知重复派发；消费状态未知时先核查，不盲目重发，不宣称
接收方 exactly once。乱序消息不能覆盖更高任务版本；无唯一 id 时明示降级。
BUB005-04 消息经过多个会话转发时保留原始来源和用途，并设置跳数或循环检测；出现循环时停止放大。
BUB005-05 accepted、已写入发件箱、sent、目标确认消费分别可见；超时只是状态未知或未确认，不自动
写成已送达。
异常与竞态 grant 撤销与发送竞态；session id 重用；向已结束会话发送；两个 owner 的任务 id 恰好相同；接
收方失联后重试。
评审结论 必须独立成票，不能隐含在工作会话工具中。建议默认只开任务内父子回报，跨任务消息作为显式有
界能力。
统一待决项 D5 首发允许的跨会话范围；消息保留期和超时后处理规则。

BUB006 身份授权与安全隔离
目标 任何入口都能核实谁在要求什么，外部内容和运行时审查都不能伪造 owner 授权。
范围 包含 owner 与渠道身份绑定、workspace 隔离、动作授权账本、凭据保密、最小出站数据、撤销与审
计。排除自建权限旁路；不把一次批准扩大为未来或其他目标的授权。
依赖 BUB001、003；本票是 BUB005、009、010、011 和外部交付的前置门槛。
预期行为 权限来自验证过的 owner 操作及 DSH 规则。审批绑定动作、目标、数据、金额或其他限制与上下文

范围 包含 DSH 内的任务列表与详情、状态来源、暂停继续取消、待用户决策、事件计划、审计和配置入口。排
除独立大应用与未验证的全实时控制台。
依赖 基础面板依赖 BUB001、003、004、006、013；事件与计划视图另依赖 009，远程交付状态另依赖 010。
入口使用真实宿主 UI 能力。
预期行为 面板从同一权威账本读取，显示更新时间和是否是快照；关键控制提交带任务版本。取消需要按真实
执行阶段反馈，暂停只保证不派发新工作，不能伪称已停止全部在途动作。
验收标准
BUB014-01 列表和详情对同一任务的状态、版本及阻塞一致；过时快照有时间标识，刷新会查询当前状态而
不是重画旧内容。
BUB014-02 对每个非终态提供适用控制；已完成、已取消、待审批和执行中任务的按钮符合状态转换合同。
BUB014-03 双击、旧页面和并发控制不会重复派发或覆盖新版本；错误提示解释失败与如何核查，不让 UI 自
行推断成功。
BUB014-04 真实 DSH UI 下检查窗口缩放、长中文、键盘操作、焦点、空列表、加载与错误状态；无截断关键
信息或遮挡操作。
BUB014-05 可直接查看任务相关会话、产物和授权范围；不展示凭据，不提供越权会话或其他 workspace 的
快捷入口。
异常与竞态 任务恰好结束时点击取消；插件重载后面板仍打开；网络或服务断开；大量任务；系统字体不同；
用户同时从远程修改。
评审结论 不能把面板放到发布前才补。建议先做朴素可用的列表和详情，功能与视觉都独立验收，避免把 UI 接
受点击误当控制生效。
统一待决项 D12 任务面板采用的宿主扩展入口；无该入口时的首发呈现方案需明示。

BUB015 运行时独立审查与流程
目标 重要任务的计划、结果和异常能得到独立、有限成本的检查，并把问题回传给正确的任务。
范围 包含运行时 reviewer 角色、触发条件、证据输入、问题分级、修复循环和结束条件。排除无限互相评
审，排除把 reviewer 当授权机关；各工单开发期独立评审从第一票开始。
依赖 BUB003、004、005、006、008、012、013；开发期质量门槛不依赖本票完成。
预期行为 主任务和检查会话有清楚的职责。reviewer 检查需求、产物和可见证据，不依靠原作者自称成功；提
出问题可触发有限修复，但不能自行发送敏感内容、扩大任务或批准原本未获批动作。
验收标准
BUB015-01 独立 reviewer 能看到完成任务所需的材料与证据，不能读取不相关私密信息；审核报告标出检查
覆盖和未检查部分。
BUB015-02 作者、代码 reviewer 与测试 reviewer 的身份可核查；同一作者自签不得满足独立开发评审门
槛。
BUB015-03 必须审查的任务在 reviewer 失败、超预算或结果未知时保持待审或阻塞，不能跳过后标记完成。
致命或按策略判为阻塞的问题未解决时也不能完成。证据绑定任务与产物版本，变化后旧审查失效。
BUB015-04 建议每项任务最多 2 轮自动修复与复查，达到上限仍有问题时交给 owner；具体阈值可配置且受
BUB012 总预算约束。
BUB015-05 reviewer 输出不能授予权限或修改审批账本；恶意产物要求其批准、泄露或跨任务发送时被拒绝
并留证据。
异常与竞态 reviewer 自己失败；作者与 reviewer 不一致；检查期间产物变化；多个 reviewer 相互触发；复查
超预算；审核结论晚于用户取消。
评审结论 有价值，但必须有界。建议高风险外部效果和重要产物强制检查，其余按任务类型配置；检查结果仍
需证据，不能形成模型互相背书。
统一待决项 D13 运行时强制审查类别、问题等级与循环上限；不影响各票已有质量要求。
