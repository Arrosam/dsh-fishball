# Preparatory design conflicts and resolutions

Status: candidate design resolutions, not runtime implementation or W2 acceptance. W1 browser HOLD and all source AC remain unchanged.

| ID | Conflict | Resolution and remaining proof |
| --- | --- | --- |
| PREP-01 | Worker actionDigest and resource normalizedSpecDigest could represent different approved subsets. | Use actionDigest everywhere for one complete immutable normalizedSpec, including resource/model/executor/environment/tools/permission bindings and target/data. Canonical serialization/digest computation and actual equality are future implementation/test gates. Message body and briefing digests retain their narrower distinct meanings. |
| PREP-02 | Including a newly created sessionRef in the original approved intent would change its digest after uncertain creation. | Fix generation/environment before create; bind known sessionRef only for resume. Link discovered created sessionRef by receipt/mapping to original actionDigest+claimRef+generationRef, without rehashing consent. Repeated/late receipt and wrong-generation runtime tests remain mandatory. |
| PREP-03 | Complete wire scope includes taskRef, but W1 ingress uniqueness excludes associated task identity. | Preserve owner+workspace+provider+source+event uniqueness. Changed taskRef cannot expand the key or rebind an existing entrance. No migration in prep. Future adapter/process dedup test must prove compatibility. |
| PREP-04 | Wire stored refs could accidentally be passed to W1 raw identity parameters and hashed again. | Document a trusted raw-ID/stored-ref mapping boundary; never infer or reverse hashes. Cross-adapter scope/lookup tests and any durable mapping schema remain future work. |
| PREP-05 | Native create source inspection offers no separately proven accepted/ready acknowledgement. | Candidate wrapper phases require their own persisted mapping and concrete native observations; they are not new DSH or schema2 task statuses. Real ready/create/resume/cancel proof remains unrun. |
| PREP-06 | A transient no-session query or worker timeout could incorrectly release resources. | Unknown/create-timeout/cancel-request outcomes hold claim/reservation ownership. Release requires confirmed_no_executor with a closed authoritative attempt or confirmed_stopped_and_settled plus exact generation/claim outcome evidence; no active executor or uncertain effects. Later native/process-race proof required. |
| PREP-07 | Ajv strictRequired lint rejects legal conditional required fields declared on an enclosing object. | Verifier explicitly uses strict:true with strictRequired:false; actual required validation remains enabled. Schema meta-validation, strict schema/types/numbers, no coercion/default/property removal, and all negative assertions remain. This option is documented, not a weakened acceptance criterion. |
| PREP-08 | Several conditional object/array fragments fail the planned strictTypes compile gate. | Authors add explicit object/array types in those fragments and retest with root's exact options; strictTypes remains enabled. |
| PREP-09 | Coordinator material classification reused sourceKind, colliding with recursive mock-evidence provenance validation. | Rename classification to materialKind, reserve sourceKind for evidence provenance and preserve the recursive mock-only guard. |
| PREP-10 | Root verifier's regex could coerce an array vector ID into a valid-looking string and evade stable duplicate identity. | Require typeof id=string before regex/uniqueness; independent metadata-negative retest required. |
| PREP-11 | Revoke-first messaging could carry outbox/claim/reservation fields; applied pause/cancel could report dispatch open. | Authors add narrow structural state contradictions and negative vectors; actual atomic ordering remains an unexecuted runtime gate. |
| PREP-12 | Requiring current recipient access for every delivered record could erase a confirmed historical delivery after permission revocation. | Separate receipt-time access/openability proof from current access, preserving confirmed effects while showing revoked/unknown current access. Future recipient/channel and time-of-observation tests remain required. |
| PREP-13 | Resource revoke_action had task/idempotency binding but no exact target action. | Require exact actionRef/actionDigest only for action-specific revoke; forbid them for task-wide controls. CommandRef identifies an immutable command and cannot stand in for the target. |

Independent reviewers will append/report additional findings through owned review files; root records accepted cross-lane resolutions here and returns corrections to each author.
