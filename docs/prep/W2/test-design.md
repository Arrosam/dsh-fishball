## Boundaries and data representation

- Common refs: lowercase hex length 63/64/65; empty, uppercase, non-hex, whitespace, Unicode and non-string. Test each owner/workspace/task/session/generation/command/evidence/artifact/recipient position, not one representative alone. Identical refs still require trusted runtime identity checks.
- Common task versions: 0/1/2 and safe-integer maximum−1/maximum/maximum+1; epochs/times: −1/0/1 and the same upper boundary; wrong type, fractions, null and omitted fields. Numeric JSON structural limits do not establish monotonic trusted clocks or causal order. A future expected version is a runtime conflict, not permission to skip versions.
- Contract version/shape: exact `bubbles.w2-prep/v1` versus missing/unknown version; missing/extra fields at every nested object; wrong discriminant/state-specific fields; arrays empty/single/maximum/maximum+1 and duplicate refs. Objects with getters/proxies, transport parser ambiguity and live capability identity are later boundary tests, not representable proof from parsed JSON vectors.
- Content limits: test encoded bytes, Unicode code points and chosen model tokenizer separately. JSON Schema `maxLength` does not count UTF-8 bytes or actual model tokens. Use ASCII, long Chinese, multibyte/combining characters and protected critical constraints at the front/middle/end. At the selected model's N−1/N/N+1 token boundary, compaction must retain current constraints, denials and source/version; otherwise reject before dispatch with an explainable reason.
- Expiry/freshness: actual trusted clock at expiry−1/expiry/expiry+1, including crossing expiry while blocked on the claim lock; summary/tool snapshot age at threshold−1/threshold/threshold+1. D8/D10 policies must be decided first; timestamp presence or recent-looking payload time is not freshness proof.
- Hop/relay depth, bounded recipient sets, artifact count/size, outbox/history/log lengths and attempt/unit/time/spend budgets: N−1/N/N+1 once the candidate bounds/policies are explicit. Test zero/unknown/partial usage distinctly; a missing cost value must not become measured zero. Candidate schema ceilings are structural proposals, not measured production defaults or hard billing caps.
- API/capability/model boundaries: exact current capability proof versus only version string, missing/lost service and unsupported operation; requested model/reasoning versus unavailable/different/unknown actual configuration. Owner preferences are not a verified native catalog mapping. No Astra, silent downgrade, installation or live model query is used here.

## State and fault transition design

Keep candidate worker/cancel/message/delivery labels separate from W1 schema2 task statuses. No prep document adds a task status, database table, native method, capability or production bridge.

| Axis and transition | Fault/out-of-order variant | Required later observable oracle |
| --- | --- | --- |
| Intake → durable accepted fact → classify/correct/control | Crash before commit; after commit before classification; duplicate/new provider ID; correction versus old completion | No precommit ACK; committed intake survives reopen; full scoped identity dedup; version advances once; old completion cannot restore old requirements. |
| Create requested → created → ready → running → terminal | Timeout before receipt; session appears later; ready duplicate; reused sessionRef/new generation; reload between create and mapping commit | One durable request/reservation; query/reconcile same native operation before another create; actual ready evidence required before work; exact owner/task/environment/incarnation retained. |
| Running → cancellation requested → observed stopped/unknown/completed effect | Cancel versus claim/completion; event stream disconnect; late receipt | Stop new dispatch first. Native cancel request alone never proves termination; known effects retained, unknown reservations held until valid proof. |
| Reconnect/reload → current query → durable reconciliation → subscription | Duplicated/reordered historical events, missed terminal, source cursor reset, unsupported query | Do not turn historical events into new tasks; higher version/incarnation wins; terminal facts survive; unknown current state stays unknown. |
| Context/source snapshot → assembly → briefing bound to current facts | Summary generated while task changes; stale completion/approval; deleted source; retrieval partial; compaction trims denial | Re-read authoritative facts; keep conflict provenance; minimal actual model input; no summary-authority/completion, no repeated completed work, reject if protected constraints cannot fit. |
| Message accepted → outbox committed → sent → consumption confirmed | Crash at each boundary; missing receipt; control races; recipient ended; relay loop | Durable scoped dedup/immutable spec; distinct visible states; missing receipt means unresolved consumption, not delivered/unsent; preserve origin/purpose and halt bounded loop amplification. |
| Artifact produced → independent verification → report → per-item delivery | Partial write, overwrite/new digest, wrong recipient, expired URL, ambiguous send, cancellation after effect | Review/report/delivery bind one task/version/content/recipient. | UI snapshot → current refresh → versioned control → observed outcome | Double click, stale page, concurrent remote control, reload/disconnect, terminal transition during click | Refresh current facts, not cached repaint; exactly one logical accepted control; display conflicts/unknown instead of inferring success; no overprivileged link. |
| Budget reservation → dispatched work → observed usage/release | Crash, timeout, unknown create/effect, repair/reviewer expansion, budget downshift, missing usage | Atomic accountable units/attempts/time; unknown keeps slot, no hidden extra agent; actual/estimated/unknown provenance retained; no invented exact price or hard cap. |

### Later independent-process/crash harness requirements (not executed)

Use fresh synthetic stores and at least two real OS processes, independent connections and explicit readiness/transaction barriers. Do not substitute sequential API calls or two promises on one connection. Capture serialized durable histories and both contenders' stable results. Add a bounded watchdog/cleanup for only owned processes; denied runtime-policy actions stop without bypass.

- RACE-01: two intake processes with same complete source identity; exactly one original/one dedup and one durable entry. New IDs with identical text remain two intentional inputs.
- RACE-02: two current-version constraint/control mutations; one CAS winner, the loser conflicts, newer requirements remain authoritative. Race a version change against result/verification/delivery publication; retain old result as stale evidence, never current success.
- RACE-03: two claims for the final weighted slot, including repair/reviewer/create/message/delivery work. Exactly one winner; transaction rollback leaves no second intent or reservation. Repeat after a budget downshift with held unknown work.
- RACE-04: revoke/cancel versus create/send/work claim in both barrier-controlled orders. Control-first prevents native callback/outbox dispatch; claim-first remains accountable with current revoked epoch and late effect evidence. Do not assume arrival timestamps imply order.
- RACE-05: two relays/retries for the same full message or delivery identity; identical content returns original record, changed content conflicts; receiver consumption unknown never yields two automatic sends. Test cyclic A→B→A and bounded acyclic chains separately.
- CRASH-01: abrupt child exit before durable intent, after intent before native response, after actual mock effect before receipt settlement, after receipt before progress/delivery report. Verify surviving facts from a separate process; a filesystem marker/counter makes effect count independently observable. These future mocks establish local causal handling, never arbitrary provider exactly once.
- CRASH-02: create callback reports success but mapping write crashes; later current native-query proof binds the existing session/incarnation rather than allocating a second. If association cannot be established, hold unknown and retain its slot.
- RECONNECT-01: disconnect stream before/after ready/terminal; replay historical cursor events, reuse IDs and reorder progress. Current query plus immutable operation/incarnation/version wins; no lost terminal, duplicate task or stale grant.
- UNKNOWN-01: permission/query unavailable or recipient consumption/delivery unknown across restart. No worker recreation/send/delivery replay until trusted reconciliation proves a permitted transition; unresolved capacity remains held.
