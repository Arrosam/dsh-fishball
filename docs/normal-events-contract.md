# NI4 normal installed events and schedules contract

Status: docs-only design candidate at owner-authorized baseline d91d749. Separate root contract/design GO is required before source/test/library/Git/native-host changes. This required normal implementation follows [normal integration](normal-entry-integration-plan.md) and [owner continuation](owner-normal-entry-continuation-2026-10-04.md); it preserves all82 original AC and5 current DF010 contract AC. It does not resolve the blocked independent CODE session or unavailable browser gate, and cannot be used to reroute either.

## Supported carrier and concrete scope

Pinned DSH Web0.2.1-alpha.1 exposes `HostConnectionService.rpc.handle(channel,handler)`; the handler receives the actual admitted OperatorPeer, and the registration supplies an asynchronous disposer. The normal product already uses this carrier with `/df-rpc` and checks the peer by object identity before reading command data. Cordis `ctx.on` registrations belong to their fiber and automatically dispose. The host exposes scoped `session/created`, `session/event`, `session/disposed` and awaited `session/flush`; session events are observations of an owned native session, not authenticated arbitrary webhook requests or task grants. No generic scheduler service is supplied by the inspected public host interfaces.

The concrete first normal ingress is **authenticated native owner ingress** over the existing `/df-rpc`, with a product-owned private slot registration and a typed atomic local ingress method. Schedule ingress retains the existing private EventRouter registration. It is an internal source, not a public webhook endpoint. The owner supplies an event ID and intended goal as data; product code derives source/provider/owner/profile identity and trusted receive time. A private schedule registration uses existing ScheduleDriver plus ordinary Node setTimeout/clearTimeout, bounded minimum poll60000ms and maximum86400000ms, unref where supported. Its clock is product Date.now, not JSON. Timers only register durable task ingress; they never grant, dispatch, drain a queue, wake a model or send a result. No listener/server/daemon or additional scheduler store is introduced.

Normal owner ingress is not a provider authentication oracle. Actual chat software/account/provider and externally signed webhooks remain out of this phase. The existing provider-neutral adapter contract and complete source/event identity remain required. A future native session observation source requires a separate exact owned session/generation mapping from NI2 and original scoped public event registration; it is not silently substituted for the concrete owner ingress below.

## Closed selections and explicit activation

Installed-only optional `automation` is omitted/disabled by default. Disabled accepts exactly `{enabled:false}`. Enabled accepts exactly `{enabled:true,ownerIngress,schedules}` with bounded distinct keys: at most16 owner ingress choices and16 schedule choices, maximum32 total private schedule slots. Each key is a bounded local selection label, not a handle or proof. The validator rejects unknown, inherited, hidden, symbol, accessor/proxy/nonplain values, callbacks, identity claims, service constructors, keys, signatures, verifier flags and supplied adapter/provider/source/clock digests.

Each owner ingress choice is closed `{key,maxEventAgeMs,rate:{windowMs,maxEvents},route}`. Route is the existing `new_task` or `supplement` selection; supplement target is selected explicitly at owner source configuration, with current scoped task validation. Each schedule choice is closed `{key,maxEventAgeMs,rate:{windowMs,maxEvents},route:'new_task',spec,startAfter,pollMs,goalTaskRef,goalRecordRef}`. Normal schedules create queued tasks only; supplement is permitted only for explicit owner ingress. Goal references select an existing encrypted owner-scoped goal template; they are not claimed authenticity. Product code reads the exact selected immutable encrypted record, requires kind goal, validates owner/workspace/task/bytes/digest and rejects raw secrets. This is an explicitly selected template, not a claim that an earlier task goal remains its latest instruction. No plaintext goal is written to profile settings. It captures actual goalRecordRef/digest in the private recipe and its permissionPolicyRef; changing the selected template requires fresh source/subscription configuration. Later unrelated task procedural CAS does not silently rewrite the selected immutable template.

`spec` is the existing closed scheduleSpec, with all fields explicit:

- interval: kind,timezone,catchUp,maxAgeMs,maxScanMinutes,anchorAt,intervalMs;
- daily: kind,timezone,catchUp,maxAgeMs,maxScanMinutes,minuteOfDay,weekdays,dstRepeat,missingTime.

Intervals are at least one minute. Daily DST policy is first/both/skip for repeated minutes and skip for missing minutes. Catch-up is skip/coalesce/verify; age and scan bounds are chosen explicitly. These constraints inherit the current event-clock validator, not example production defaults. Source event age and rate limits use the existing RuntimeStore bounds. Enabling selection config installs private capabilities and read-only readiness only. It does not create a source/subscription/clock, start a timer or grant an action on boot.

Selection keys match `[a-z][a-z0-9-]{0,31}` and are unique across both lists. Event IDs and new task IDs use existing reference's `[A-Za-z0-9][A-Za-z0-9_.:-]{0,127}`; raw strings are data, never source proof. Define private namespace `N=canonicalDigest(['df.installed-events/v1',identity.ownerId,identity.workspaceId,profile.dir,profile.name])`. For slot kind K and selected key X, derive sourceRef=canonicalDigest([N,K,X,'source']), subscriptionRef=canonicalDigest([N,K,X,'subscription']) and sourceIdentityRef=canonicalDigest([N,K,X,'origin']). ProviderRef is reference('df.native-owner-ingress/v1') or reference('df.native-schedule/v1'); adapterRef is the corresponding reference('df.native-owner-adapter/v1') or reference('df.native-schedule-adapter/v1'). PermissionPolicyRef is canonicalDigest of the immutable actual slot recipe, including selected route/target or exact template record/digest, source age/rate and schedule spec where applicable. These are product-derived references, not user-entered selections or proof hashes. SourceRef/subscriptionRef identify durable configuration; providerRef/sourceIdentityRef identify the complete private origin. AdapterRef/permissionPolicyRef identify the product implementation and exact current allowed route recipe. Runtime owner RPC cannot manufacture these facts by supplying hashes. Retained setup namespace/key/ledger schema and advanced factory options remain unchanged.

## Additive private installed seam

The NI4 author owns new src/installed-events.mjs and dedicated tests; NI2 owns shared installed-config/installed-plugin/runtime-plugin/client imports and wiring after its own source hold. Export exact `validateInstalledEvents(input)` (undefined→detached disabled selection) and `createInstalledEvents({selection,identity,profile})`→`{installedAutomationInstaller}`. Identity/profile are verified activation values, not config/RPC. Composer does not register/write/start before the returned installer is called. The named installedAutomationInstaller is separate from advanced automationInstaller and is a product-private function, not a DSH native method.

Runtime calls installer with a closed private object containing ctx,isAlive,configureSource,configureSubscription,source,subscription,ingestLocalOwnerEvent,eventReceipt,listEventReceipts,readGoal,registerSchedule,tickSchedule,statusSchedule,startSchedule,stopSchedule,unregisterSchedule,approveSchedule. Every method is a narrowly bound typed closure for that same authoritative store; no raw SQL,owner/host handle or alternate ledger is supplied. readGoal({taskRef,recordRef}) reads permitted exact encrypted data and returns actual scoped metadata/content for kind goal only. Installer returns exactly configureLocalAutomation,ingestLocalEvent,localAutomationStatus,startLocalSchedule,stopLocalSchedule,dispose. Runtime maps only those named closures into the existing original authenticated bridge and validates return shape. Readiness returns selected key/reference metadata and stable reasons, never identity/profile paths, callback objects or echoable proof flags.

`configureLocalAutomation` takes `{key,commandRef,expectedSourceRevision,expectedSubscriptionRevision,enabled,targetTaskRef?}`. A supplement target is required iff the selected owner slot route is supplement; it must be a current scoped existing task. Normal schedule/new_task slots forbid it. Source expectedRevision is expectedSourceRevision, subscription expectedRevision is expectedSubscriptionRevision, and configureSubscription.expectedSourceRevision is the acknowledged actual configured source revision. The private recipe derives source kind internal/schedule, identityMode unique_id,adapterRef,permissionPolicyRef,maxEventAgeMs,rate and enabled. Subscription derives sourceRef,enabled,triggerRef,route and exact target; owner triggerRef hashes ['owner-ingress',key], schedule triggerRef is canonicalDigest(scheduleSpec). These are separately acknowledged CAS writes. A partial pair is explicitly not ready and admits nothing; no compound configuration success is invented. Disable/reconfigure seals prior registration before replacement.

`ingestLocalEvent` is closed `{key,commandRef,eventId,goal,taskId}` for new_task, or `{key,commandRef,eventId,goal,expectedTaskVersion,expectedAuthEpoch}` for supplement. The module validates goal UTF-8/65536 bytes/nonblank/registered secrets, derives provider/source/adapter/permission/event refs, obtains exact current configured source/subscription revision and selected target, and invokes the typed private host method below only while the original admitted peer/parent/child/profile remains live. Supplement expected task/auth values are explicit CAS, not caller proof; core verifies before first ingestion. No caller received/observed time,signature,owner,route,role,provider digest or permission is accepted.

Required minimal core seam, coordinated with ledger_core: `ingestLocalOwnerEvent(host,{commandRef,sourceRef,subscriptionRef,expectedSourceRevision,expectedSubscriptionRevision,adapterRef,permissionPolicyRef,providerRef,sourceIdentityRef,eventIdRef,goal,taskId?,targetTaskRef?,expectedTaskVersion?,expectedAuthEpoch?})`. Exactly taskId is required for new_task; exactly targetTaskRef/expectedTaskVersion/expectedAuthEpoch are required for supplement. In the SAME existing ingress transaction, current source/subscription enabled/revisions and exact privately registered adapter/permission/route predicates are checked before dedup. Stable event identity covers actual provider/source and event ID; stable eventDigest covers complete immutable origin+goal+route+new-task ID or supplement target/taskCAS. Authorization/config revision and receive-time observations are excluded from event identity/digest. First accepted ingress stamps trusted server time and persists it with encrypted goal/receipt. An identical retry across time/restart reads only the signed durable original occurrence/association/timestamp, never refreshes it; a changed body,target or supplement CAS conflicts. Concurrent identical candidates share one admitted original timestamp/association. No pre-ingress staging timestamp, cache or memory-only dedup is introduced. The advanced EventRouter/ingestEvent digest meaning is unchanged: this private typed normal method reuses its ingress implementation/lock, not a second authority.

Historical acknowledgement is metadata only and grants no action. Dedup retention for this normal wave is the existing complete event/ingress history with no timed eviction; event4096 cap refuses without losing knowledge. maxEventAgeMs is new admission age, not a dedup TTL. A known original event remains deduplicated rather than receiving a fresh time to bypass age. Explicit retained-state deletion/uninstall is a separate owner operation; silent restart/config expiry never creates replay authority.

`startLocalSchedule` is `{key,commandRef,expectedSourceRevision,expectedSubscriptionRevision}`. It resolves the exact template/recipe and creates one private ScheduleDriver registration, then starts using selected pollMs. It is process-private lifecycle mutation with a bounded per-lifetime immutable command receipt; changed same command conflicts, duplicate start creates no second timer. Restart does not replay a start command; it reads durable clock status and requires explicit new start. `stopLocalSchedule` is `{key,commandRef}` and seals poll epoch, clears timer and unregisters exactly that registration. `localAutomationStatus` accepts `{}` or `{key}` and derives source/subscription ready state,timezone,schedule digest, bounded next proposed occurrence, durable cursor, pending plan and polling. It displays known gaps; no status read changes cursor or starts a timer.

Owner `approveSchedule` remains closed `{commandRef,sourceRef,subscriptionRef,expectedSourceRevision,expectedSubscriptionRevision,clockRef,expectedCursor,planDigest}`. Normal panel obtains these exact refs/revisions/cursor from actual status; approval does not accept a guessed verified flag,through value,clock callback or event timestamp. Current plan/revision/cursor must match under owner core lock. A successful approval permits only that task ingress proposal, not any action/model execution. Public approval route is reused without an invented native scheduler API.

## Clock and missed-plan authority

Core source/subscription revisions, route CAS, rate/event dedup and schedule cursor remain the sole transactional authority. Schedule EventRouter's final private currentness guard has no await before RuntimeStore.ingestEvent; local owner ingress uses its private lifetime guard plus typed atomic current predicates. Timer callbacks re-read current durable revisions; disconnect, profile change, disabled/revoked source, updated goal or disposed lifetime refuses. Source/subscription changes are admission predicates, never part of provider event identity that could permit replay.

ClockRef hashes sourceRef/subscriptionRef/scheduleDigest. ScheduleDriver records missed skip/verification-required plans with exact cursor, after/through, due occurrence identity and source/subscription revisions. Only original authenticated owner `approveSchedule` may approve an exact stored plan digest/cursor/revisions; an approval is permission to admit that proposed task ingress, not any external effect. `externalEffect` is fixed true for the normal missed-plan registration so restart/catch-up requires explicit owner verification before any due admission; this conservative local mode is implementation semantics, not caller evidence or a promise that the timer executes effects. Live starts also display and require that exact occurrence plan when the driver classifies verification required. No missed occurrence is automatically replayed on restart.

Clock rollback fails closed; oversized gaps report review required without losing cursor/dedup facts. Local dates/minutes, UTC occurrence instants and owner IANA timezone are displayed separately. Repeated DST folds preserve distinct exact instants under the explicit first/both/skip policy; missing times skip. No timer promises delivery while DSH is fully stopped. Restart reads durable state and shows known missed plans before explicit start/approval; an unknown external effect elsewhere is reconciled, not timed out into a grant.

## Disposal and implementation proof

Before awaiting cleanup, seal the installed parent, named owner closures, private registration, verifier/currentness callbacks and poll epoch. Clear owned timer; unregister native RPC/listeners and EventRouter tokens; then await child disposal/worker/native flush and close the existing store. A callback already queued or resolving late cannot admit, publish status, clear another lifetime's timer or reschedule. Disable/reload/full quit preserve durable clocks/events/receipts and setup-vault bytes; restart creates fresh private tokens and reads existing durable facts. Borrowed prior services and copied/JSON tokens remain powerless.

Synthetic callbacks and native loopback ingress are functional evidence only. Final CODE and actual browser control remain HOLD. No newly prepared source is implemented or accepted by this document.
