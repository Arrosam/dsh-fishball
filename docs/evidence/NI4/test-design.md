## Required product boundary and current challenges

Normal capability uses original admitted native owner RPC, a private owner slot with typed atomic `ingestLocalOwnerEvent`, and separately the existing private EventRouter plus bounded owned Node timers for ScheduleDriver. Its clock/source/provider/owner/profile facts come from product code and original native context. Configuration selects values, never proofs. Owner CAS configuration, ingress, schedule start/stop and exact missed-plan approval remain separate explicit operations. Events/timers can admit a durable task; they never plan/grant/claim/wake/send an action automatically. No anonymous webhook server, new daemon, chat provider, extra database or scheduler service is invented.

Observed design challenges were sent to root/author before code:

1. EventRouter hashes `proof.observedAt` into `eventDigest`. Native owner ingress that derives a fresh Date.now timestamp for every retry would conflict for identical eventId/goal after time advances or restart. Freeze a stable original observation/content association with a typed durable replay lookup or another explicit equivalent that preserves current receive-time checks. No payload timestamp/proof is accepted to fix this.
2. BUB009-01 requires a frozen dedup retention window. The current store retains complete event/ingress history and refuses at4096; `maxEventAgeMs` is admission age, not dedup TTL. Freeze retention through explicit retained-state deletion with no timed eviction/replay for this wave, or specify another authoritative safe contract before GO.
3. The schedule choice currently selects spec/start/poll/template refs but not its complete source age/rate/route recipe. Freeze that exact recipe, template kind/current-digest checks and private ref derivation before implementation. Source/subscription revisions are predicates, never a changing origin that can admit the same old event again.
4. `installedAutomationInstaller` return/operation signatures are proposed. Freeze the named closed operations, original lifetime/currentness guard and exact partial source/subscription CAS behavior with NI2/NI3 before author GO. A caller-selected operation map or owner-provided verifier remains forbidden.

The revised candidate resolves those four challenges. Owner ingress uses a typed same-lock method with stable complete origin/content/route/target-CAS digest and one first trusted occurrence timestamp retained in its signed durable association; authorization revisions and receive time are excluded from immutable identity. The advanced EventRouter/ingestEvent meaning is unchanged. Normal history has no timed eviction and refuses at4096. Schedule config explicitly selects source age/rate, fixed new_task route and exact immutable encrypted kind-goal template. The named closed installer/operations/ref derivation/approval shapes are listed below. No unresolved NI4 design challenge remains. Root must hold this design before author GO; serial core/shared NI2 wiring and held author implementation remain required dependencies. These are code/interface work, not pending production configuration decisions. Existing historical source/tests/evidence remain untouched.

The held exports are `validateInstalledEvents` and `createInstalledEvents({selection,identity,profile}) -> {installedAutomationInstaller}`. Installed-only automation is omitted/exact disabled or exactly enabled with ownerIngress/schedules; each list has at most16, keys are globally distinct `[a-z][a-z0-9-]{0,31}`. Owner choice is `{key,maxEventAgeMs,rate:{windowMs,maxEvents},route}`. Schedule choice adds exact fixed `route:'new_task'`, spec/startAfter/pollMs/goalTaskRef/goalRecordRef. Template is explicitly selected immutable material, not a claim that an old goal is latest. A later procedural task CAS does not replace it; changing its selected record/digest needs fresh exact source/subscription configuration.

Installer input is exactly ctx,isAlive,configureSource,configureSubscription,source,subscription,ingestLocalOwnerEvent,eventReceipt,listEventReceipts,readGoal,registerSchedule,tickSchedule,statusSchedule,startSchedule,stopSchedule,unregisterSchedule,approveSchedule. It returns exactly configureLocalAutomation,ingestLocalEvent,localAutomationStatus,startLocalSchedule,stopLocalSchedule,dispose. All closures are private/narrow/same-ledger; no SQL, owner/host handle or caller operation map. Configure is `{key,commandRef,expectedSourceRevision,expectedSubscriptionRevision,enabled,targetTaskRef?}` with target iff supplement. Ingress is `{key,commandRef,eventId,goal,taskId}` for new_task, or task/auth CAS instead of taskId for supplement. Start requires key/command/current source/subscription revisions; stop requires key/command. Per-lifetime start receipts never replay after restart. Status takes `{}` or `{key}` and never moves cursor.

Owner approveSchedule remains the exact original `{commandRef,sourceRef,subscriptionRef,expectedSourceRevision,expectedSubscriptionRevision,clockRef,expectedCursor,planDigest}`; it approves only the current proposed task ingress. Private source/subscription/origin refs derive from `canonicalDigest(['df.installed-events/v1',ownerId,workspaceId,profile.dir,profile.name])`, fixed slot kind/key and documented suffix. Provider/adapter refs use the fixed native-owner/native-schedule versioned labels. Permission ref includes immutable route/target/template digest/source policy; config revision is not origin. A duplicate unchanged event association returns historical metadata only, never new grant/current action authority.
