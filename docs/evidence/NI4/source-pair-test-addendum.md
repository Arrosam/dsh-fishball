## Actual baseline gap and exact additive boundary

The inspected `configureSubscription` checks expectedSourceRevision under its write lock but retains only sourceRef,subscriptionRef,subscription revision and spec. A separately committed source update followed by subscription failure therefore leaves no durable record of which source revision the old subscription acknowledged. The current normal scaffold compares actual specs and process-private state; unchanged recipes can look ready again after cold restart. A cache, equality of recipe prose or a new receive-time digest cannot prove that a complete configuration pair succeeded.

Typed `configureLocalSubscription(owner,{commandRef,subscriptionRef,sourceRef,expectedRevision,expectedSourceRevision,spec})` uses the existing closed input and returns exactly `{subscription,pair}`, detached actual stored projections. One existing Ledger transaction checks current source/subscription CAS and original scope/spec/capacity, writes the subscription, signed `local_source_pair`, its inverse marker and registry update with the authoritative receipt. The first source CAS remains a separate acknowledged write. Failure of the second transaction preserves the old stale pair; it never rolls back or fabricates the source acknowledgement.

The exact signed pair is `{contractVersion:'df.local-source-pair/v1',pairRef,sourceRef,sourceRevision,sourceSpecDigest,subscriptionRef,subscriptionRevision,subscriptionSpecDigest}`; pairRef is `canonicalDigest({sourceRef,subscriptionRef})`. References/digests are hex64 and revisions positive integers. Complete spec digests derive the actual locked source/subscription specs. The existing signed envelope scopes owner/workspace. Subscription.localPairRef is the signed forward pointer, preserved by every generic update. Generic updates can stale the pair but cannot refresh or remove normal ownership.

The mandatory scoped signed `normal_provenance_registry` is exactly `{contractVersion:'df.normal-provenance/v1',localPolicyCount,localPolicyDigest,localPairCount,localPairDigest,localReportCount,localReportDigest}`. Policy/pair digests hash canonically sorted marker IDs; report digest hashes canonically sorted scoped `{taskRef,progressRef,localReportRef}` triples, with localReportRef=`canonicalDigest({taskRef,progressRef})`. All counts use existing aggregate automation/record bounds. Pair ID is stable across revisions. Registry initialization happens only in authorized migration or first scoped mutation; status/boot never initializes it. Exact both-direction checks precede read/mutation/recovery: pointer→pair, pair→subscription, actual registry count/digest→all markers/reports and all markers/reports→registry. Deleting pair+subscription still conflicts with sticky ownership. The unkeyed progress pointer/digest is not authentication: deleting report+stripping/recomputing that pointer also fails the signed membership inverse. A stripped pointer, deleted marker/registry, contradictory inverse, wrong scoped tuple/digest or unsupported closed version refuses STORAGE_INVALID; it never downgrades normal facts to advanced/unmarked data. Report/registry update commits atomically in the separate NI5 typed progress transaction.

The private installer replaces configureSubscription with configureLocalSubscription and adds `readLocalSourcePair({sourceRef,subscriptionRef})`, bound to the original scoped typed core read. It returns exactly `{pair,currentness}` where currentness is current|stale|missing. Missing/pair:null is permitted only for a never-marked slot. Current requires the actual enabled exact module recipe plus complete signed pair/spec/revision/pointer agreement. Missing/stale module readiness is EVENT_PAIR_MISSING/EVENT_PAIR_STALE. Pair failure does not erase independently read clock history.

Both normal `ingestLocalOwnerEvent` and original scheduled ingress repeat the current normal pair predicate inside the authoritative intake transaction before dedup/task/clock writes. Generic ingestion on a retained normal-marked subscription cannot bypass it. Private timer callbacks recheck exact bindings/lifetime after async work; no process cache is authority. Original `approveEventClock` additionally compares retained clock source/subscription revisions with the actual locked bound pair before marking pending approval. Mismatch refuses STALE_EVENT_CLOCK and creates no command/clock/task change. The former later-tick-only rejection is insufficient.
