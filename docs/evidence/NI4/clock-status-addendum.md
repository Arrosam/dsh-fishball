Status: docs-only addendum to the held [NI4 contract](../../normal-events-contract.md) SHA6d3a6800ddaede4d0d9242bc8dabed33bfa5cd5425ffceb128e1d0c13f5ab405 and [freeze](contract-freeze.md). Independent design binding and root affected-source GO are required before implementing this addition; no core write/source lease is implied.

Add exactly one private installer input closure `readScheduleClock({sourceRef,subscriptionRef,clockRef})`. The runtime binds it directly to the original scoped `RuntimeStore.eventClock(host,input)` and detaches the resulting record or null. It exposes no owner RPC, host handle, SQL callback or alternate authority. The module derives sourceRef/subscriptionRef from its scoped slot and clockRef=canonicalDigest({sourceRef,subscriptionRef,scheduleDigest}), where scheduleDigest is the exact normalized selected schedule specification.

Each existing schedule status adds exactly `clockRef,clockCurrent,clockSourceRevision,clockSubscriptionRevision,clockDecision,clockReason`. clockRef is the module-derived hex64 reference; clockCurrent is boolean|null; revisions are positive integers|null; clockDecision is `{decision,planDigest}`|null, with decision skipped|verification_required|ingested and planDigest hex64. clockReason is null|CLOCK_MISSING|CLOCK_NOT_CURRENT|CLOCK_UNAVAILABLE. The existing cursor is a nonnegative bounded instant|null. pendingVerification is null or `{through,planDigest,approved,approvedAt?,approverRef?}`, with through a nonnegative bounded instant,planDigest/approverRef hex64,approved boolean and approvedAt a nonnegative bounded instant; actual approval fields are projected only when present. Owner slot statuses use null for these clock fields.

`localAutomationStatus` invokes this read for each selected schedule whether stopped, booted or running, independently of source/subscription/template read success. It projects the actual retained cursor,pendingVerification and clock source/subscription revisions independently of live registration. Configuration-read failure still attempts clock read and preserves successfully read history; currentness is false/CLOCK_NOT_CURRENT. A missing clock projects null facts with clockCurrent:null/CLOCK_MISSING. Only failed/corrupt clock reads project unavailable history, null clock facts and CLOCK_UNAVAILABLE. An existing clock's revision match against the actual enabled/current exact source/subscription recipe projects clockCurrent:true/clockReason:null; a mismatch, disabled/missing configuration or changed recipe projects clockCurrent:false/CLOCK_NOT_CURRENT while preserving historical cursor/pending/decision facts. A pending approval from older revisions is never current approval for the new pair. These historical decision fields are not current permission; no summary or cached timer state provides them.

Status performs zero register,start,tick,ingress,clock writes,approval or timer operations. It neither repairs stale records nor consumes/clears pending plans. Stopped/running polling metadata derives the exact current private registration separately. Source/subscription/clock read failure fails closed with a bounded unavailable reason, never fabricated missing history. On disable/reload/full quit the module seals the original lifetime; a late read cannot publish into a replacement installer. Durable records survive while callback tokens do not.

Required independent oracles after affected-source GO: existing clock visible with zero registration at boot; stopped and restarted status retains cursor/pending/revisions/old decision; missing clock returns null; configuration drift/read failure preserves successfully read old facts and labels not-current; stale pending approval cannot approve new revisions; getter/proxy/extra key refusal before closure calls; unavailable/corrupt clock read yields unavailable rather than no-history; status counter proves zero writes/timers/admission before and after disposal.
