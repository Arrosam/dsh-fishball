## Implementation audit

The final code preserves one synchronous SQLite transaction domain for intake, task CAS/history, grants, actions and resource reservations. Grant now requires both task-version and authorization-epoch CAS. Claim validates exact scope/task/action/target/data/kind/units/version/epoch/expiry and host permission under the database lock, then commits irreversible intent before a fixture callback. Unknown results hold reservations and never replay; known action settlement is separate from explicit task completion. Export reads one snapshot. Revoke/cancel/recovery and settlement have protected bounded history capacity.

The trust boundary is explicit: `Foundation` is a trusted in-process integration API, so a direct scope argument is not authentication. Approval/deletion authority requires an exact constructor-injected object identity in a private WeakMap; there is no minting export. Native service operations use an immutable activation-bound scope, reject caller overrides, and default to identity unavailable/operator unavailable/dispatch denied until real host bridges exist. No model-facing tool, worker, transport or raw Foundation handle is published.

Schema validation includes supported table topology, foreign keys, reference/status/integer/provenance/history semantics and reservation consistency before recovery or migration. The schema-1 DELETE-journal migration validates before mutation, exclusively copies and fsyncs the backup and its directory before DDL, and validates the target inside the transaction. Filesystem-only header/WAL-sidecar checks run before any SQLite open; schema/journal are rechecked inside migration/validation/runtime locks. Rejected crash-left WAL stores at versions 1, 2 and 99 preserve exact main/WAL/SHM bytes and presence. Supported DELETE hot-journal recovery deliberately restores acknowledged logical facts; successful recovery can change supported main/journal bytes, so byte-for-byte preservation is not promised for that recovery operation. Persisted identifiers are hashed references; exact field allowlists and configured row/byte caps prevent raw payload and exception retention. Deletion retains a durable local tombstone.

The supported journal boundary is explicit: current schema 2 and bounded task-only schema 1 use DELETE rollback journals; WAL and WAL/SHM sidecars, future/unsupported versions and ambiguous headers are rejected before SQLite opens them. Real crash-left files, logical oracles on copied file sets and a second-connection future-schema commit under contention substantiate preservation and lock checks. This does not certify arbitrary external filesystem mutation, live DSH effect reconciliation or arbitrary-effect exactly-once execution.
