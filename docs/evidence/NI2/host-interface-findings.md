## Public persistence and native addon bounds

`SessionPersistence` is the abstract public service; its `identity` symbol distinguishes instances even through Context shadows. Public `create/open/flush/stat/list` and handle `read/append/flush/close` supply the supported storage boundary. `open(id,'write')` has single-writer ownership; a read handle acquires no writer. `stat` revision is opaque and comparable only for the same instance/session, not a universal resume token. A created but unmaterialized session is visible in-process; other processes see it only after materialization. Append is best-effort; handle/service flush is the durability barrier. Event sequence is contiguous from0; torn tails are excluded from reads, write recovery truncates before append, and unknown vocabulary refuses.

The JSONL provider installs its own current-fiber live event/flush/disposal routing (`lib/index.js:407–435`), finding an owned writer by the published session id. AgentLoop takes that writer before publication and closes it on teardown; SessionStore itself is in-memory and does not persist a session published outside this lifecycle. Thus a persistence roster/stat check alone does not establish actual current context durability. Verify the public flush barrier and the exact owned stored events, including background-write failures remaining buffered/unknown.

Original `JsonlSessionPersistence` config requires explicit `root`, with optional compression defaulting to checksummed Zstandard. It may create an absent root only on materialization. The normal-entry contract requires a separately consented, canonical profile-owned sibling directory, never another setup-vault file. NI2 must check ancestor/path/mode/identity/root before taking write ownership and preserve partial/unknown facts after errors. It must not silently adopt a personally rooted or existing unrelated backend.
