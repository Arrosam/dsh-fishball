# NI2 private original-preview invocation seam

Status: finding-driven additive implementation clarification; original held worker contract/design remain unchanged. The primary author identified an actual omission before coding the composer: the frozen installer returns workerPreview/workerGrant, but its exact input exposes neither of the runtime-owned original ApprovalPreview operations. The six manager operations cannot provide those functions, and JSON/configuration cannot supply them.

Add exactly two narrow private installer input functions, `prepareOwnerPreview(value)` and `grantOwnerPreview(value)`. The other installer fields and its exact return remain unchanged. Runtime binds them lazily to its one original owner-scoped ApprovalPreview after the valid installer returns its resolver/TTL and runtime constructs that service. Calling either before valid preview construction refuses PREVIEW_UNAVAILABLE without effects. Installation/boot never invokes either function and creates no preview, grant, session or policy. No store/owner/host handle is passed into configuration, RPC, the model or a public service.

`prepareOwnerPreview` takes exactly the existing original prepare fields `{taskRef,actionRef,actionDigest,recordRef,expectedTaskVersion,expectedAuthEpoch}` and returns its unchanged awaited immutable preview envelope. The installed workerPreview first validates the current exact normal derived action/context/policy/native facts; the original service independently rechecks scoped data, actual resolver meaning, CAS, capacity, expiry and lifetime across awaits. Preview preparation grants nothing.

`grantOwnerPreview` takes exactly the existing original grant fields `{taskRef,actionRef,actionDigest,commandRef,expectedTaskVersion,expectedAuthEpoch,expiresAt,previewRef}` and returns the original awaited immutable grant receipt. workerGrant validates literal accept:true, selected grant TTL/current time and exact normal action/private preview, then removes accept before invoking it. The original service retains token ownership, simultaneous-confirm fence, displayed-data/current-resolver equality, current task/auth/policy and atomic store grant CAS/expiry predicates. No supplied callback or matching digest can substitute for the original preview.

The runtime private receipt observer emits grant only for the actual successful original grant mutation. Its input is the exact original store grant input with previewRef removed and its receipt is the actual frozen committed receipt; never caller proof or a fabricated preview label. Emit once synchronously to the existing private receipt fanout before returning the unchanged receipt. Failed/refused preparation or grant emits no committed grant. Observer failure seals installed admission and preserves committed uncertainty; it cannot roll back or repeat a grant. Existing direct owner/advanced preview behavior remains compatible, while the normal composer only accepts its exact action/policy/input/lifetime lineage. No extra receipt vocabulary, automatic consent or recursive store call is introduced.

Required independent design before affected source GO: exact closed installer input and unchanged manager union; lazy construction/no boot invocation; absent/unconstructed service refusal; original preview versus grant distinction; extra/hidden/accessor/proxy/accept stripping; simultaneous grant, stale resolver/data/CAS/TTL/lifetime refusal; actual one-time committed receipt before return and zero fabricated/replayed authority; unchanged advanced route and observer-failure uncertainty. Existing independent first-unit families and all source criteria remain intact. Standalone closures do not establish original installed physical native behavior. This addition changes no schema/vault/key/context/native-result version and does not unblock CODE/browser/full acceptance.
