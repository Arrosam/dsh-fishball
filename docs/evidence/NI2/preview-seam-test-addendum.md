The installer receives exactly two additional private functions: `prepareOwnerPreview` and `grantOwnerPreview`. Neither enters Config/RPC/services/model/UI as a callable capability. Runtime binds them lazily to its original owner-scoped ApprovalPreview after validating the returned resolver/TTL. Retain the existing installer return shape, manager union, owner operation shapes, schema/vault/key/context/native-result versions and advanced behavior.

The original prepare fields remain `{taskRef,actionRef,actionDigest,recordRef,expectedTaskVersion,expectedAuthEpoch}`. The original grant fields remain `{taskRef,actionRef,actionDigest,commandRef,expectedTaskVersion,expectedAuthEpoch,expiresAt,previewRef}`. `workerGrant` validates its separate literal `accept:true` and bounded selected TTL, then removes accept before invoking the original grant. The private grant observation carries only the actual original store grant input (previewRef removed) and actual frozen committed receipt. Matching JSON/digests/caller labels cannot manufacture it.
