## Narrow proposed safety boundary

For a meaningful positive initial continuation, finish the first approved worker through actual captured result, usage, stopped/drained evidence and authoritative reservation release. Preserve its task/action/claim/generation/session/history/result facts. Keep maxActive1. The same owner then explicitly accepts a new bounded cumulative policy, prepares current instructions again, approves a new resume action, resumes the same native session ID into a fresh owned generation **idle with0streams**, and explicitly executes one continuation to one new observable local artifact. No first-action spec/digest/grant/claim/generation or result is rewritten. A source-owned local deterministic result proves plumbing/provenance; useful real-model continuation remains unproved.

An already live handle with in-flight/unknown work is an observation/reconciliation case, not permission to create a second incarnation. An old held reservation must remain held; maxActive1 naturally blocks a second claim until factual reconciliation. A new native session beside an inaccessible old ID, force-close through a guessed ID, duplicated backend or automatic regrant/replay is forbidden. The future contract must state whether exceptional same-claim recovery exists; this proposal grants no such exception. Model/policy/source/environment or task changes require fresh displayed choices. Existing generic pricing remains COST_UNKNOWN; no special resume pricing bypass.

The minimal eligible source should be an original installed NI2-created mapping for this same owner/workspace/task, with an authenticated immutable action and trusted historical native observations/result, a known resolved old outcome, real stop/drain and ledger release. Trace to the actual original supplying factory/backend/configuration. A native header lacks DF owner/task authority. A matching sessionRef, prefix, path, stat, model assertion or owner JSON lineage is not sufficient. Root/author must identify the exact currently authenticated durable origin records; if the existing read API cannot establish the required provenance, freeze a safe additive contract rather than infer it from an untrusted raw metadata row.

The sessionRef remains the old native ID hash; the new generationRef is different. Resolve raw ID only from that trusted original mapping/origin: do not derive `df-${newGenerationRef}`, accept owner-entered resumeSessionId or enumerate/adopt another native session. First-unit current creates use df IDs; branded legacy bubbles IDs cannot be silently guessed/adopted. Their eligibility needs an explicit same-source compatibility disposition. Crypto/storage legacy rejection remains independent of branding. Missing/wrong-scope/unowned native session refuses, with no fallback create.

The first create-only two-message rule remains intact. Resume adds a separate exact history predicate for the same source-owned session, not a wildcard permission for all persisted messages. Protected current constraints/pending decisions may not be truncated to fit retained history. Summary text cannot confer new grants, completion, side-effect permission or reviewer authority.

Persisted reasoning/options/header cannot silently override current accepted facts. 5. Rendered NI1 context UTF-8/heuristic budgets separately from native complete ordered messages JSON bytes, selected synthetic context/input/output units and conservative reservations. Include JSON escaping, separators and old history. Missing native capacity/pricing/accounting remains unknown. Recheck after agent/request, prepareCall and delayed downstream middleware; no admitted counter/output before inner consume. Adapter-projected object identity need not match the outer envelope, but all relevant fields/content must. Old native frames or requests from the old incarnation do not consume the new permit despite the same session ID.

The smallest safe history policy can reject non-current formats, fork/parent lineage, replaced/compacted surfaces, unresolved tool effects, unknown outcomes or nonempty pending inbox until separately specified. This is a proposed boundary, not deletion of original broader continuity obligations. If the future contract accepts any of those cases, it needs explicit source validation, current-instruction/conflict behavior and independent tests. Do not manufacture a resumed session via create(seed), SessionStore fork, JSON replay as owner authority, private factory paths or replacement persistence services.

Public native resume loads the full persisted log before product setup and has no maximum-events/decompressed-bytes option. Prior read/stat/count admission and exact final recheck can bound supported own histories, but cannot promise an atomic native bounded decode against concurrent same-UID modification. Compressed physical bytes also do not bound decompressed body/message bytes. State the exact supported physical/decoded event/request/capture limits and refusal point; no invented hard disk quota, age retention or fixed-memory guarantee. If the original host cannot supply the required atomic guarantee, retain that limitation rather than introduce another harness.
