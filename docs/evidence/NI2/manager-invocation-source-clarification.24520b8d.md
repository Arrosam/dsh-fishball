# NI2 exact owner mutation versus original owned observation guards

Proposed affected runtime refinement of the frozen transport guard. No wire/config/installer-input/schema change. Runtime/native/manager held sources remain unchanged pending root freeze and independent design binding. This note is an implementation proposal, not a source verdict or executed test.

Use one source-private AsyncLocalStorage carrier keyed by exact admitted child Context identity. A normal installed operation enters `{ctx,assertCurrent}` using its immutable bridge second argument; the original captured callback must return literaltrue. The source-private carrier is detached from input JSON and persists across only that invocation's asynchronous work. Current source/ledger/permission predicates remain separate. A later explicit execute/capture/finish creates a different carrier from that operation's current peer/signal, never the previous create callback. At bindExecution, retain that exact execution carrier privately; the outer and inner request gates explicitly re-enter it before their synchronous checks. Public agent markers/prefixes or inherited latest tokens do not enter the carrier.

For the installed lazy manager only, a narrow same-original-store facade preserves original method receivers, private owner/host handles, validated inputs and unchanged receipts. Synchronously assert the exact matching current invocation immediately before `claimAction`, `beginContextExecution`, consuming `assertExecutionCurrent`, `writeArtifact`, `settleAction`, `control` and `putHandoff`. Absence, wrong Context, expired bridge/peer/lifetime or aborted native signal refuses with the existing bounded guard code. No await separates that assertion from the original method. This closes manager prepare→claim, validation→artifact and actual stop→settlement waits. The advanced manager retains its existing direct original store and behavior.

`snapshot`, `readData` and read-only `assertClaimCurrent` still forward to that same store. They create no admission/consume/artifact/settlement. Normal owner wrappers continue checking their own exact guard around those reads. A source-owned native request must use the captured execution carrier at the read-only current assertion; readonly activity alone never authorizes work.

`workerObservation` is distinct. Explicit owner operations require their exact current carrier before this mutation. Background actual original lifecycle observations are not new owner work: they may persist only an exact privately captured original NativeAdapter receipt for the owned manager/ticket/generation/current runtime lifetime. The runtime wraps the original adapter's `observe` callback and factual create/query/cancel/dispose/shutdown receipts to capture this source association; it never accepts an owner payload or establishes receipt origin from a digest. Before forwarding a background observation, compare exact task/action/digest/claim/reservation/generation/session/phase/cursor/evidence fields against that private actual receipt. Its disposition is only the existing workerObservation; it cannot claim, grant, consume, capture, settle, release or launch another worker. Private recorded stopped/not_created observations remain actual facts across owned shutdown while admission is sealed. No absent-session assumption, fabricated zero-work or auto-finish occurs.

An active but aborted owner invocation does not fall back to background authority for its explicit mutation. A callback explicitly executing inside the original adapter observation carrier has the independent owned-receipt path; an arbitrary manager write without such a private source receipt is denied. Owned background events never inherit permission from another active request. Losing transport after actual native stop leaves physical stop plus unknown/held ledger outcome when its explicit settlement is denied; no retry/rollback or erased stop is promised.

Required authored/independent oracles: blocked original prepare→claim and validation→capture abort/peer loss; stop→settle abort with physical stop but held reservation; distinct concurrent Context/request carriers; no carrier denies explicit methods; old create aborted while later fresh explicit query/execute uses its own carrier; actual original background ready/stopped observation with lost old request; forged/mismatched observation rejection; cleanup admission sealed before original shutdown; same original store/receiver/handle/receipt forwarding; unchanged advanced ignored-context behavior. Physical native authenticated transport and CODE/browser acceptance remain separate HOLD.
