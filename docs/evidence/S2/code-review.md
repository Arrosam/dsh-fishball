## Initial API assessment

The published `bubbles.runtime/v1` proposal distinguishes raw constructor/intake IDs from stored references, opaque trusted handles from serialized claims, encrypted scoped content from ordinary metadata, action outcome from task completion, and native effects from synchronous transactions. It retains default-deny permission and explicit unverified native/model/usage/UI gates. These are the right design boundaries; code must establish them.

Three preliminary API risks were reported to root/core, with messaging details also sent to its author. They are **implementation questions, not confirmed code findings** while those units are being written:

1. Explain and enforce the supported legacy Foundation path on the extended schema. Legacy claim/settle/control must either participate in the complete runtime authority/resource/outcome invariants or reject safely; a second writer cannot release newer unknown obligations or bypass runtime pause/policy.
2. `enqueueMessage` currently has optional claim/generation fields and a narrow recipient/body signature. Clearly distinguish accepted metadata from dispatchable outbox; exact immutable source/purpose/category, recipient incarnation and message action/grant binding must be enforced before host send. No unbound payload can create a dispatchable effect.
3. Specify execution-handle read/write permissions and independent reviewer provenance. Task/ref equality cannot substitute for the trusted role/generation/record boundary, and no reviewer/model/native facade may expose or change authority.

The first context utility was read provisionally: plain/enumerable descriptor validation, proxy/accessor rejection, finite string/list limits, known-secret guard, whole optional-record removal and refusal when protected input exceeds limits. The final reviewed coordinator/assembler integration implements and tests these boundaries with actual encrypted records, immutable asynchronous requests and final CAS checks; real selected-model input/token validation remains deferred.
