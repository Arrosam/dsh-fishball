## Boundary values and representation

- Raw identifiers are validated and hashed exactly once at intake/configuration; RuntimeStore methods consume stored refs. Exercise63/64/65 hex refs at every scope/task/action/claim/session/generation/command/data/artifact position, lowercase/uppercase/non-hex/non-string, and raw hex-looking IDs that are legitimate raw input. A raw/ref bridge must preserve lookup rather than rehash returned refs.
- Task/policy versions use1/2 and maximum safe integer−1/maximum/maximum+1; epochs/times use−1/0/1 and the same ceiling. Test fraction/string/null/omitted/unknown fields and live objects with accessors/proxies/symbol/non-enumerable properties. If no successor is representable, fail closed without wrap or partial mutation.
- Expiry uses trusted time immediately after the SQLite mutation lock: expiresAt−1/expiresAt/expiresAt+1, including an expired request that waited for that lock. Wall-clock callback ordering never replaces transaction order.
- Configured queue, weighted active units, per-group/total attempts, runtime/usage/cost, record count/bytes, messages/events/history, artifact count and relay hops: N−1/N/N+1 plus0/unknown/unlimited-lookalike/unsafe-integer/type partitions. Trusted policy derives/checks charges; payload role/unit/group cannot mint a free reviewer, repair, worker or second pool.
- Content boundaries distinguish UTF-8 bytes, Unicode code points and the injected tokenizer. Test ASCII, Chinese, combining/multibyte text and protected denials at front/middle/end. Reject lone high/low surrogates at both ends of their ranges, embedded/reversed pairs and malformed canonical object keys before hashing/persistence. Valid supplementary pairs, scalar values adjacent to the surrogate range and explicit U+FFFD roundtrip exact strings, UTF-8 byte lengths and digests. Module N−1/N/N+1 token/byte tests prove the chosen deterministic callback only; selected-native model limits remain final debt. Reject instead of truncating protected records.
- Encryption key length31/32/33 and type/immutability; scoped authenticated-encryption AAD; wrong key, modified tag/ciphertext, moved record/ciphertext to another owner/workspace/task/kind/version and failed decrypt. Current `cryptoVersion:2` uses unbranded `runtime-data/v2` and binds every immutable metadata field. Genuine decryptable schema3 v1/no-marker rows fail `CRYPTO_LEGACY_UNVERIFIED` before recovery or writes; empty/W1-only stores remain supported. No plaintext/key/error dump, silent rewrite, automatic legacy reseal or mixed-key overwrite. Rotation/import/retention and any separately authorized legacy provenance recovery remain explicit decisions.
- Actual DELETE crash journals partition rejected legacy, wrong key and edited metadata versus valid current ciphertext. Force dirty main pages and the exact SQLite hot-journal header with an abrupt child exit. Rejection preserves main/journal bytes and entries, while a separate recovered copy proves acknowledged logical facts. Verified current stores may roll back the journal and reconcile the original held claim without replay. The isolated validation copy is bounded at256MiB; this is an implementation resource ceiling, not a selected product retention policy.
- Usage actual zero versus missing/estimated/unknown; source/error-bound absent/finite/unknown, stale policy/price and unavailable model. No estimated pre-effect charge becomes actual consumption; dispatch limits are not a hard-bill cap. D3/D10 thresholds and native model mapping are not selected by a numeric test fixture.

Use fresh synthetic temp stores, at least two actual OS processes and independent connections. Readiness/transaction barriers, not sleeps/timestamps, establish contention and both linearization orders. Children use inline code from the owned test, bounded watchdog/cleanup and no native/model/browser call. Capture both stable outcomes and a third-process durable readback. Counters/markers are independently observable mock-effect evidence, not exactly-once external claims.

- `S2-P-INTAKE`: simultaneous duplicate full ingress; one entrance/original outcome, one dedup; changed task association/digest conflicts; intentional new source event remains separate.
- `S2-P-CAS`: two writers with the same expected task/auth versions; one successor, one stale/conflict, consistent snapshot/history. Repeat correction versus completion/report publication.
- `S2-P-SLOT`: two accounted worker/review/repair claims for one remaining weighted slot; at most one claim/reservation/native submission. Repeat with total attempts and policy downshift while unknown is held.
- `S2-P-ORDER`: revoke/cancel-before-claim and claim-before-revoke/cancel with barriers; compare auth versions, held records, effect count and late settlement, not request arrival times.
- `S2-P-CREATE`: abrupt exit after committed create intent and after observed mock native create but before mapping write; reopen/reconcile reveals same generation or stays unknown, never recreates from missing receipt.
- `S2-P-SEND`: actual mock receiver effect before missing receipt/persistence; reopen and unavailable query retains unknown/held and no resend; confirmed failed item alone may receive a separately admitted retry.
- `S2-P-MIGRATION`: exact schema2 and interrupted/future/WAL/corrupt stores, backup readback and cuts; concurrent version upgrade after preflight but before lock must reject without downgrade.
- `S2-P-ISOLATION`: independent scoped actors/processes sharing raw/native IDs cannot access another owner/workspace/task/claim generation or encrypted data; scan exports/logs/files/ciphertext copies with unique synthetic canaries.
