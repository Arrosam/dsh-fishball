## Implemented module contracts

`Coordinator` accepts the actual store and host-injected optional classifier/cancellation closure. Methods take an opaque core caller handle; serialized refs/roles cannot authenticate it. `register` persists before interpretation and `receive` returns the receipt immediately with a separate classification promise. Classifier failure/old CAS cannot overwrite current state. `revise` uses exact version/epoch through core. `stop` commits core cancellation/dispatch blocking before scheduling the adapter callback; its return value cannot establish stopped. Only an authoritative reread can show confirmed cancelled, otherwise requested/unknown remains explicit.

`clarify` writes one encrypted immutable batch of necessary questions/dependent branches; existing answered/outstanding decisions are not asked again. `answer` requires a nonempty complete attributable reply, exact current version/epoch, a current awaiting batch and bounded digest refs; core CAS increments taskVersion for these writes. No answer, even prose saying approve, calls a grant method. `withdraw` removes an obsolete awaiting batch through exact CAS; `branchReady` checks only unresolved dependencies and actual snapshot control (including paused while task status stays queued); it does not confer dispatch permission. Every actual action still needs current core claim/permission/budget checks.

`ContextAssembler.assemble` reads a scoped core snapshot and resolves encrypted goal/constraints/context/clarification records through authorized core reads. Latest goal/constraints and factual ledger status/actions/workers form protected text. Older summaries are omitted with conflict provenance; summaries cannot set approval/completion. Context material requires scoped source refs, task/epoch/time provenance and optional exact generation. Unrequested unrelated artifact/message records are not resolved. Host facts are labelled snapshots; stale facts can trigger an injected trusted host query and are never labelled live. Final task/epoch/generation checks follow asynchronous queries and tokenizer callbacks.

`compactContext` measures the entire final string using UTF-8 bytes plus an injected synchronous tokenizer, including headers/separators. It removes complete optional records in priority order, retains protected text at front/middle/end, and refuses if that minimum cannot fit. It never truncates or rewrites critical constraints. Known synthetic secret canaries and configured/common credential forms are rejected before persistence or context output. This is a bounded guard, not a claim to recognize every possible secret. Errors expose stable codes only.
