## NL01: original constructor without class activation

The single hunk matches the helper's current line 91. It replaces `await install(WebServer, { host: '127.0.0.1', port: 0, compression: 'none' })` with `new WebServer(ctx, { host: '127.0.0.1', port: 0, compression: 'none' })`. The public default export is the original WebServer class, not an independent `apply` callback (WebServer source line 366; public declaration line 79).

The original helper `install` calls `ctx.plugin` and awaits its fiber (helper line 82). The Cordis class runner constructs the class, runs any init hooks and invokes the instance's `Service.init` method (Cordis lines 1067–1070). The original WebServer constructor calls `super(ctx, 'webServer')`, saves the supplied config and creates gzip middleware only when compression is `'gzip'` (WebServer lines 157–162). The original Service constructor registers the real instance through `ctx.reflect.provide` and does not call `Service.init` (Cordis lines 1770–1783). Original service provision records fiber ownership and a removal/disposal effect, then notifies dependents (Cordis lines 800–823); notification does not initialize the WebServer instance. The root fiber is already active (Cordis lines 1102–1113, 1678–1690).

WebServer's HTTP creation is inside its `Service.init` body: `createServer` at line 246, `server.listen(config.port, config.host)` at line 297, and the `webServer.listen` server-shutdown effect after successful listening at lines 306–320. Direct construction does not enter that body. Thus the changed construction path removes the WebServer class-plugin activation, `Service.init`, HTTP creation, denied listener operation and associated listener-shutdown effect altogether. It does not retry EPERM, select another port, reroute/proxy traffic, request permissions or replace an original method. The unchanged host/port literals remain config data and are unused by this construction path for socket binding.

The imported class and import edges remain unchanged, including WebServer's existing `node:http`, compression and negotiator imports. This is a call-path conclusion, not a claim that `node:http` is no longer imported or that every transitive module initialization effect was audited. A targeted source search of the nine other directly imported public plugin indexes found no `webServer`, `createServer` or `.listen(` reference; Loader has its own unrelated original `Service.init`. ## ER08: transport-compatible missing retained binding

The literal patch has three hunks, all confined to the synthetic execution-recovery client fixture. It adds an optional `omitBindingDigest` flag defaulting to false, deletes exactly `input.bindingDigest` before the synthetic `prepareAuditInput` response, deletes exactly `stored.bindingDigest` before publishing/cloning the synthetic task execution wire, and uses that flag for the existing ER08 missing-binding member. The adjacent invalid-material member retains its `inputChange: { materialDigest: 'invalid' }` form. No product code, authentic execution record, receipt or serializer is modified.

The current fixture spreads `{ bindingDigest: undefined }` into `input` (current fixture lines 27–31, 206–207). Its RPC double returns that object directly; its `clone` is `structuredClone`, not JSON serialization (fixture lines 17–18, 49–51). The current client applies `plainRpcReply` to the RPC reply (client line 549). That validator enumerates own descriptors and recursively inspects every value; `undefined` reaches its rejection branch (client lines 281–297). The failure is therefore before the intended retained-input recovery check, consistent with the delegated first raw UI-fixture result of 11 PASS / 1 FAIL. That historical result was not re-read or recomputed and remains unchanged by this review.

The authentic HostConnection RPC route calls `fullResponse` (HostConnection lines 694–696). Successful non-attachment replies use `Response.json(body)` (lines 723–738); multipart metadata uses `JSON.stringify` (lines 739–753). JSON object serialization omits own properties whose values are `undefined`. The proposed explicit deletion faithfully represents that wire-level missing field instead of adding a non-JSON own value to the synthetic RPC reply. The stored synthetic task row needs the same deletion because its object literal otherwise recreates an own `bindingDigest: input.bindingDigest` field after input omission. The fixture is still an explicit wire double; no serializer or native storage operation was executed.

The client source keeps semantic rejection distinct from wire admissibility. `prepare` still checks record/digest/purpose (client line 588), while retained execution recovery requires a valid input `bindingDigest` among the input references (line 568) and later requires the execution-row binding field (lines 575–579). The omitted input reaches the retained-input guard and must be refused there according to the source. Because that guard precedes row validation, this ER08 member does not separately demonstrate the later missing-execution-row guard; deleting the row field matches JSON representation and the new own-absence assertion, not an independent runtime proof of that later branch.

The literal keeps `assert.equal(await audit.prepare(input.purpose), true)` (current fixture line 79), subsequent plan/preview/grant/create setup assertions, lost-execute-response assertions (line 90), and the `unchangedRecovery` negative oracle (lines 94–103). That oracle still requires `canRecoverExecution()` and `recoverExecution()` to return false, zero additional RPC/task-refresh calls, retained stale/uncertain/worker/collection state, null preview, false accepted authority, and a deep-equal unchanged model snapshot on refusal. The two added `Object.hasOwn(..., 'bindingDigest') == false` assertions strengthen the fixture's representation check. The client protection and negative expectations are not weakened.

Only the flag's true member changes the synthetic wire shape. All current callers that omit the option keep its default false behavior. No extra RPC, retry, task refresh, private model-state write, native service, file/profile/DB, DOM, model or provider operation is added by the literal.
