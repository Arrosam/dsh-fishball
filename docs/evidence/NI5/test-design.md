## Required normal result boundary and design challenges

The concrete supported local route is the existing native df panel over original admitted `/df-rpc`, using exact scoped encrypted Ledger artifacts/results. Product code derives durable recipient/channel/policy/group refs from retained owner/workspace/canonical profile and binds live admission to actual current native Connection/OperatorPeer/lifetime. Configuration cannot supply recipient/proof/callback/permission or digest authority. The module, normal owner operations and native panel must be implemented even though rendered opening cannot yet be observed.

The inspected public host has no generic trusted opened/read receipt. Local publication can truthfully produce sent or unknown; actual available bytes/current permission are distinct from recipient delivery/rendering/opening. HTTP200, JSON/digest echo, callback success, a path, queue append, idle worker or model/client boolean never gives delivered/openable proof. Local opening remains unknown.

Baseline observations and their required contract resolution:

- A pre-send outbox_committed row is not publication. Freeze private `publishLocalDelivery` to atomically recheck current exact claim/grant/auth/control/policy/material/recipient/notification and commit sent/opening-unknown before the adapter returns its committed receipt. Separate assertClaimCurrent then deliveryObservation is raceable.
- `ResultPipeline.currentAccess` requires delivered. Preserve that advanced meaning and add private `recordLocalDeliveryAccess`/normal local branch for sent/unknown/current availability, with no supplied opening field and no synthetic delivered workaround.
- Normal report verification must derive from actual current source-bound artifact/audit/verification facts. Existing `writeProgress` and NotificationService normalization can carry caller-written passed/evidence text. Freeze the exact normal report wrapper and how normal pending/prepare/accept reject or truthfully classify raw/advanced progress without trusting those values. The independent challenge was sent to root/core/author before GO.
- NI2 initially admits worker-create only. NI5's disjoint local executor:none plan/preview/admission contribution, complete target and charges must be frozen explicitly; merely enabling results cannot broaden host permission.
- Generic authenticated automation envelopes and command receipts alone do not make older schema5 readers understand normal report/policy ownership. Freeze genuine schema6, strict signed normal kinds/forward and inverse associations and old5 refusal before recovery, with authentic5→6 backup/preservation. A deleted normal marker must not silently downgrade data to raw advanced authority.

The final6b6e2e75 contract resolves these challenges with named report/progress operations, closed signed exact source associations, retained normal-only policy invariant, private atomic publication and separate unknown-opening access branch. It defines explicit local admission selections, disjoint executor:none planner/resolver/admission, source-owned byte/monetary accounting and genuine schema6 provenance with inverse registry validation. Core refinements make native proof, aggregate/source-state precedence, factual digest identity exclusions, claim/publication byte checks and single existing notification ownership/charges explicit.
