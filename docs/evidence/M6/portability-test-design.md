## Boundary and observed starting condition

The reviewed development baseline resolves `src/host-probe.mjs` to plugin-relative `.runtime/dsh-web`, reads its entire lock and imports its pinned public Context/SessionStore/ApprovalService classes. RuntimePlugin imports Connection from that same anchor; NativeAdapter imports agent/LLM/scope/tools/JSONL modules there. A normal package without ignored `.runtime` cannot be assumed equivalent. Merely repairing the probe would not repair the other exported runtime imports.

Public package metadata inspected without execution confirms that official `@deepseek-ai/dsh` exports `./package.json`; the inspected public native service packages export their bare entry and package.json. Root accepted one exact frozen flat npm host tree through normal public Node peer resolution. Installation in a separate native profile preserves the complete host lock byte-for-byte; even harmless root metadata edits are unsupported. The held resolver is commit `154c31a`, [10-entry author manifest](portable-resolver-author.sha256), SHA256 `8e0a530a571bb25419fa5ae8ae462e009f3d36d399c6461f2cf39b00ee09bde4`. pnpm, other package managers, nonflat/multiple-host layouts, changed locks and future versions are not accepted by inference.

The actual package tarball, fresh native host installation, profile/CLI selection, HTTP and process stop/restart belong to root. This lane uses only ordinary module imports, disposable synthetic directories, public package metadata/source, genuine public service classes with no listener initialization, captured transport streams and temporary synthetic encrypted stores. It never copies or reads host-home/auth/key/access/YAML contents. No install/network/listener/browser/HTTP/provider/inference/tool body is permitted here.

## Risk priorities and equivalence partitions

| Priority / risk | Partitions and observable failure boundary |
| --- | --- |
| P0 hidden checkout dependency |Actual extracted package under a different regular directory versus source link, accidental `.runtime`, original absolute path or NODE_PATH fallback. Success must use installed public peers and cannot import the original checkout's implementation. |
| P0 authority from another package copy |One coherent official host tree versus another copy with the same versions/hashes/global Cordis brand, mixed Context/session/approval/Connection origins or structural lookalikes. Exact live native class identity must hold; metadata alone cannot authorize. |
| P0 partial initialization |Missing/mismatched peer, unsupported source/hash, wrong service copy or absent native Web carrier before identity/key callbacks, ledger creation, route publication or task admission. Diagnosis is allowlisted and failure causes zero work. |
| P0 install changes security defaults |Default foundation diagnostics versus explicitly trusted runtime factory composition. Package relocation must not mint identity/operator authority, enable dispatch/tools, accept payload scope or turn absent key/policy callbacks into defaults. |
| P1 lock/provenance false positive or false negative |Exact host versions/sources/dependency graph and complete unchanged host lock versus any root/plugin metadata edit, host-package edits, duplicate native copies or incomplete lock. Separate profile installation is the supported positive; changed host lock is an explicit negative. |
| P1 lifecycle and durable recovery |Own plugin unload, dependency disappearance/remount, ten reloads, separate-process reopen and root full quit/restart. | P1 artifact/source mismatch |Preview/MIT/export/client metadata and built bundle within the actual tarball; private development paths, stores/credentials/cache or missing export targets. Normal installed entry resolution is distinguished from importing checkout files. |

The supported positive version partition is DSH/Web/native0.2.1-alpha.1, Cordis4.0.5-alpha.1 and actual Node22.22.2. Negative package metadata partitions include adjacent alpha versions, unrelated versions, missing/truncated/future package metadata and one-byte source differences. Simulated metadata never supplies evidence for running a different Node version. Service late-arrival/loss cases use genuine public Cordis lifecycle; plain context mocks are negative only.

## Root-owned actual installation and lifecycle gates

Root records the actual emitted tarball's SHA/integrity/file manifest, exact clean install command/lock/peer tree, source/export resolution and no checkout symlink/NODE_PATH fallback. A fresh private profile must select the installed package's normal entry/factory through original official loader/package metadata. Readbacks must identify actual provider/class/service origins, feature readiness and default-deny state, never a literal readiness label.

Root alone performs native process load/reload/HTTP/full stop/restart, retaining first failures and the same synthetic key/database when applicable. Require task/context/receipt identities and held unknown facts across restart,0 unrequested provider/model/tool/recipient calls, no residual listener/access after full quit, no personal profile/settings change and no private contents in retained logs. Same-source development fixture success cannot satisfy this gate. Browser/window-close/rendering, useful model/tool/audit quality and full applicable functional scenarios remain separately HOLD, not silently passed by these install checks.
