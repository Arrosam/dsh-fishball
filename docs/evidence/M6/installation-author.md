## Consent, storage and lifecycle facts

Load/status/prepare and rejected confirmations create no persistent setup entries. A plan binds exact empty target/sidecars/vault and current canonical profile/parent facts. Recheck live owner generation, unchanged empty facts, abort and monotonic expiry immediately before the first persistent syscall. The first described missing-parent `mkdir` begins consent commit; when parents exist, the exclusive vault `mkdir` does. There is no intervening await. After that point later partial writes remain accountable to that accepted consent; expiration cannot retroactively undo them. The `namespace_claimed` notification is after vault plus marker publication, rather than the first possible structural parent write.

The winner creates private parent/vault entries, persists its exclusive marker, initializes the unchanged schema4 RuntimeStore on its staging file, closes it and rejects unresolved staging sidecars. A hard-link publication cannot replace a competing target. The code then removes its staging link, publishes key/authenticated metadata exclusively and activates the unchanged native runtime. Database/key/metadata/parent/path/inode/bytes are rechecked before and after activation await. Only actual child readiness permits removal of the same owned marker and a ready response. Failures preserve partial entries; a consumed preview cannot replace/reset them. Abort before commit writes nothing; abort after commit preserves facts and status readback reconciles the missing response.

Retained load verifies authenticated exact state and resumes the same generated namespace/key. Status alone never repairs or resumes it. Missing key, future/corrupt metadata/schema, sidecar/marker, same-byte inode replacement, symlink, changed binding or unsafe mode fails closed. Detecting corrupt active retained state seals the owned child admission, without creating new files. Unsupported repair, rotation or deletion is not implemented.

Internal async startup permits own fiber states1/2 with non-null UID; external setup RPC requires own state2. Readiness uses declared public `Fiber.ctx` in the child's own provider scope. The documented synchronous `internal/status` event initiates child disposal when this installed fiber leaves startup/live states. Both borrowed setup and child diagnostics deny immediately at **this own fiber** closure, before awaited public cleanup; awaited disposal removes both routes. No immediate arbitrary-ancestor teardown ordering is claimed.
