## Scope correction and authentic origin

Original `RuntimeStore.memoryBinding(handle)` (`runtime-store.mjs:1368`) resolves the original private principal through `#ctx` and returns only ownerRef/workspaceRef/role. Original `taskRecord` (`runtime-store.mjs:25`) and `listTasks` (`runtime-store.mjs:397`) return owner/workspace references on every task. Original `MemoryAdapter` captures `store.memoryBinding(handle)` at construction (`memory.mjs:47`), uses the supplied namespace, and repeats exact binding on reads (`memory.mjs:59`). `prepareInstalledMemory` derives the actual namespace only from verified setup identity/profile inside its trusted binder (`installed-memory.mjs`). None of these original modules is changed.

The proposal uses original runtime diagnostics to read `store.memoryBinding(owner)` through the actual original store receiver and private owner handle. It checks original live/unsealed lifetime before and after and validates exact owner metadata/role. It projects owner/workspace and, when projection exists, the same `memory.namespaceRef` used in original `MemoryAdapter` construction. It does not read a memory body, enumerate another namespace, calculate scope from RPC inputs or replace the original principal. Raw identity, profile, key, tokenize closure and authority handles do not enter the projection. Only already used digest references are exposed.

The original `/df-setup` handler retains its authenticated `admittedPeer === peer`, `admitted()`, signal, empty-payload and size checks. Feature handling now captures the actual child, reads diagnostics once, and repeats admitted state, exact child identity, child ready fiber and confirmed setup state before forwarding. An unavailable/closed child contributes no diagnostics. No model-facing capability is created.

The feature response has exactly `scope,memory,automation,results`. Top-level `scope` is an exact `{ownerRef,workspaceRef}` or null. It is null when no enabled memory/automation/results capability is ready. Memory adds exact `scope:{ownerRef,workspaceRef,namespaceRef}` when ready, otherwise explicit null. Disabled memory keeps null accounting/bounds and all readiness false. Enabled but not-ready memory has null scope; continuity readiness implies memory readiness. Existing automation/results fields and disabled defaults remain.

The client closed feature parser checks exact keys, SHA256 references, readiness/enablement relationships and memory/top-level owner/workspace joins. When a fresh selected task exists, it joins the feature scope to that genuine selected task before retaining any binding. The first successful authenticated feature response pins owner/workspace, and ready memory pins its namespace. Later feature reads must match both initial bindings until disconnect. Unavailable or malformed feature reads clear usable feature/memory state; they do not silently rebind owner scope.

Every memory operation now requires the authenticated feature scope. `memoryRead` must have the pinned namespace; projection.scope must match pinned owner/workspace; core.scope must match the validated projection scope. Existing closed projection, core, metadata, fact, size, revision, import and receipt parsers remain. Memory command/mutation metadata checks the pinned namespace as well. A returned memory body never establishes the first owner or namespace binding.

`featureScope()` requires a fresh ready parent model. If a selected task exists, its taskRef must match the current selection and its owner/workspace must join the pinned feature binding. If no task exists, selected must be null and detail absent; this deliberately retains valid no-task private memory after a fresh empty task list, including after task disappearance. A stale/loading/offline or foreign task blocks scoped admission/UI until authoritative refresh. Scope stays independent of the selected task: selecting another task in the same owner/workspace does not change the memory binding. No selected task is manufactured to permit reading memory.

The normal model's existing epoch checks are repeated before request publication and every update. Parent offline transitions now invoke its disconnect helper as well as explicit connection resets, clearing scope bindings and memory views, aborting pending requests and retaining an already sent mutation as uncertain. A malformed/mismatched mutation success remains uncertain; no automatic resend occurs. MemoryControls requires `canMemory()` and continuity readiness; a current authenticated no-task state satisfies it. Loading features is explicit, as before.

No module substitution, global timer patch, exported owner authority or timer auto-start is proposed. Generic non-normal automation wiring is untouched. Reviewers must account for real store timestamp/age policy when designing finite functional evidence, without claiming all clocks were replaced.
