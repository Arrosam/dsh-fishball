# Provider-neutral manifest-byte oracle: source-only feasibility proposal

Positive normal publication remains HELD under the current closed source/config. Current original review model `df-testing-review-v1` returns unknown, coverageRefs empty and every material record unexamined. Changing that verdict to passed, attributing fixture JSON to a native collector, accepting an old advanced reviewer, or switching models implicitly cannot satisfy the publication gate. This proposal changes no source, model registration, config, stored facts or acceptance state.

The original public native audit envelope can carry bounded manifest bytes and a protected context that includes an explicitly limited original task goal. Core prepareAuditInput binds the whole current material set, exact artifact identity, protected context, semantic revision, policyRef, bindingDigest and materialDigest. submitAuditResult validates the original captured session/stream result and exact whole-material coverage, and core claimLocalDelivery repeats native provenance, current audit/material/semantic/coverage and grant checks. These mechanisms can support a genuine byte-defined task if a separately approved source actually performs those checks and is admitted through the original native chain. They do not currently select or implement such a source.

A possible later provider-neutral source contract is `df.manifest-byte-audit/v1`, for an explicitly selected synthetic task whose goal is exactly to validate one finite canonical UTF8 manifest under a specified version. This is a proposed future contract, not a currently supported config field or authority. It would require:

1. Exact original task/owner/workspace scope and an explicit trusted byte-check goal/constraint contract; refuse arbitrary goals, supplements changing that objective, semantic repair requests and unsupported versions.
2. Original protected context validation, complete current source material coverage, the original artifact record/digest/byte length, current requirement semantic/policy binding, no missing or additional material. Check every advertised content digest and materialDigest; inspect the protected context and original goal as material rather than marking them covered because their refs exist.
3. Exact canonical manifest bytes and a finite allowlist schema with owner/workspace/task refs and a bounded vector of payload recordRefs/digests/byteLengths. Validate exact UTF8 content, duplicate refs, byte limits, required payload availability and task constraints. Unsupported semantic assertions yield unknown/unexamined; malformed or mismatching byte properties yield failed with original response-schema findings. No live tools, network, provider account or external model call.
4. A fresh independent original native reviewer session/generation, one exact preview/grant, actual source stream/session JSONL facts, charged actual byte accounting, original manager validation/capture and submitAuditResult. Only that actual checked stream may return passed plus full coverageRefs and empty unexaminedRefs. No fixture-only passed report or synthetic native carrier may be used.
5. Original local acceptance/plan/preview/grant/claim/publication, read-only query and original current access evidence. Loss after an actual publication commit must leave one publication and an uncertain retained command; query may reconcile facts without resending. Reopen/quiet/frequency/owner group cases remain independently required.

No implementation or execution is proposed against the current source because the named byte reviewer and compatible producer/owner-manifest audit path are absent. The generic original ledger has enough content and binding fields to express a finite task, but installed selection/provenance cannot presently realize it. Root must separately approve a concrete bounded source/config/provenance extension, independent design and exact execution lease before a positive oracle can be authored or run. Current unknown recipe and all87 HOLD/accepted0 remain unchanged; no external model fallback or blocked receipt experiment is involved.
