ORIGINAL TOKEN USAGE AND PUBLIC ACCOUNTING
Pinned @deepseek-ai/dsh-llm TokenUsage EXACT interface fields:
 {inputTokens:number,outputTokens:number,totalTokens?:number,
 cacheReadTokens?:number,cacheWriteTokens?:number,reasoningTokens?:number}.
InputTokens is uncached input; cacheReadTokens/cacheWriteTokens are disjoint
cached counts. Authoritative total includes aggregate input plus output when
provided; absence/inconsistency is not silently inferred as actual.
Original assistant/message event may carry usage?:TokenUsage alongside its actual
AssistantMessage/stream and optional interrupted:true. Public type absence of
usage/total is not an actual-usage claim. No summaries replace original usage.
Selected public source accounting is explicit df-testing-utf8-byte-units/v1 with
source_zero pricing. In this source, inputUnits is UTF8 byte length of the actual
JSON.stringify(full request messages), outputUnits actual response UTF8 bytes,
totalUnits their sum. Source reports those actual counters as inputTokens,
outputTokens,totalTokens in original TokenUsage fields. This is source-specific
byte accounting, not a conversion for arbitrary provider token/cache/reasoning data.
Public committed worker execute usage is {state:'actual',units:totalUnits,
 accounting:'df-testing-utf8-byte-units/v1'}, otherwise the original unknown/null
DTO. Adapter validated facts expose usageUnits and persisted result evidence;
public capture returns an original artifact/audit result receipt, not TokenUsage.
Public finish returns OriginalSettlementReceipt, not TokenUsage or a generic
success flag. Actual role completion and reservationHeld/release evidence remain
original settlement facts. No claim of native/cold/source/UI/functional proof.
