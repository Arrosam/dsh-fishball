## Numeric partitions and decisions

| Numeric primitive | Exact memoryRemember / prepareContext capture | Any other operation capture | Separate domain oracle |
| --- | --- | --- | --- |
| Safe integer, including0,1 and ±Number.MAX_SAFE_INTEGER | Accept without coercion. | Accept without coercion. | Operation-specific ranges still apply; capture success alone permits no write. |
| Finite nonintegral:0.9,0.1,−0.125,1.5,Number.MIN_VALUE | Accept and preserve the JavaScript numeric value through object/array recursion. | `INVALID_INPUT` before operation callback. | Confidence must be0..1; vector rules still apply; authoritative integer fields reject fractions. |
| Integral outside safe range, including ±(Number.MAX_SAFE_INTEGER+1),1e20 | `INVALID_INPUT` before operation callback. | Same. | A mathematically finite vector component does not bypass this frozen transport limit. |
| NaN,+Infinity,−Infinity | `INVALID_INPUT` before operation callback. | Same. | Direct in-process capture tests preserve these values; JSON serialization is not used to pretend they survived the wire. |
| Numeric string, boolean, null, boxed number | No numeric coercion. Ordinary JSON primitives remain their original types; boxed/nonplain objects reject. | Same. | Memory numeric fields reject wrong types, even where generic JSON capture accepts a string/boolean/null. |

Use confidence partitions just below0,0,Number.MIN_VALUE,0.1,0.9,just below1,1 and just above1. Finite out-of-range confidence passes the newly scoped numeric capture but fails the unchanged domain validator without a memory row/receipt. Confidence0 and1 remain positive regressions. For vectors, exercise negative/positive fractional components, zero and safe integer components in both `candidate.embedding` and nested `prepareContext.vectors`; preserve existing finite/representation/dimension validation and do not raise transport array limits. Capture preservation is distinct from any already documented memory-core vector normalization.

Exercise fractions in `expectedRevision`, `expectedTaskVersion`, `expectedAuthEpoch`, `observedAt`, `now` and `limit`, using otherwise valid exact memory operations. They reach the unchanged domain boundary and refuse with no write. Revisions, IDs, timestamps, quotas/budgets and version/authorization fields remain safe integers. Safe negative integers may pass capture but still fail nonnegative/positive domain ranges. No claim is made that Number.MAX_SAFE_INTEGER is a valid value for every semantic field.

`-0` is a safe integer under the existing JavaScript predicate; preserve the existing capture behavior. Do not invent a new persistence/sign distinction that ordinary JSON does not preserve. No rounding, clamping, stringification or parse-based coercion is allowed at capture. Counting and accounting returned by context preparation remain integer facts.
