## Config, provenance and admission decisions

Supported plain dictionaries follow the existing `record` convention: ordinary or null-prototype objects with enumerable own data properties. Preserve both base-config shapes; exercise both shapes for the new closed memory record. Custom prototypes, arrays/classes, accessors, symbols, hidden properties and Proxies are negative partitions. Do not claim universal reflection-trap zero: assert ordinary getter non-execution and, where the Node validator explicitly checks `types.isProxy` before reflection, that particular Proxy trap non-execution. Redaction remains required even if a native/framework boundary reflects a hostile object.

| Config / state | Expected validation and composition | Public features / effect |
| --- | --- | --- |
| `memory` omitted | Same memory choice as `{enabled:false}`; detached frozen base passed to unchanged factory. | Disabled: `enabled:false, ready:false, accounting:null, bounds:null`. |
| Exactly `{enabled:false}` | Accept; no implicit bounds or tokenizer choice. | Same disabled result; no memory/context operations or optional estimator service activation. |
| False with either bound or extra field | Reject before SetupState construction. | Stable error; zero DF storage writes. |
| Literal true plus both in-range safe integers | Validate; establish exact estimator provenance before any enabled setup write. | Enabled metadata carries selected bounds and `dsh-fixed-density-text/v1`; preconsent `ready:false`. |
| True missing either bound; explicit null/undefined/non-object memory; truthy flag; unknown field | Reject. No example becomes a default. | Stable error; zero DF storage writes. |
| Enabled, provenance missing/mixed/aliased/altered | Refuse enabled setup; no fallback tokenizer or silently substituted bounds. | No initialization; retain existing bytes if storage already exists. |
| Enabled, verified setup and current child admits `capabilities.memory === true` | Compose private MemoryAdapter/ContextAssembler. | Only this current admitted child permits `ready:true`. |
| Enabled, partial/recovery/unavailable setup or child unavailable/closed | No automatic repair or authority inference from configured true. | No falsely ready feature; existing stable recovery/unavailable or disposed result remains visible. |

The `/df-setup/v1/features` request is exactly `{}`. Anonymous/non-operator, payload identity, wrong native scope, aborted request and disposed-own-entry cases fail through the existing admission fence. Configured enablement never substitutes for operator authentication or action approval. Original status/prepare/confirm envelopes remain exact; a new feature response must not be merged into those old carriers.

## State, race and fault oracles

The installed state sequence is unconfigured→volatile preview→explicit consent→existing private setup publication→current child ready. Configuration, a feature read, memoryRead revision0, or a retry after unknown confirmation is not a setup commit. A partial publication stays recovery-required; it is not reset to empty. After setup, an explicit memory mutation is a ledger transaction with revision/command binding. Prepared context is a different task/auth/memory CAS transaction and grants no execution authority.

| Ordering / condition | Required result |
| --- | --- |
| Current child closes before a captured feature/memory/context call reaches admission. | Deny disposed; zero new mutation. Read-only diagnostics from an immediately disposing *ancestor* are not used as an instant-cancellation oracle; use the product's own scope/route closure and final awaited quit. |
| Mutation commits, then reload/quit begins. | Preserve the acknowledged revision and receipt through reopen; seal later admissions. No rollback claim for an already committed fact. |
| Two already-open processes observe revisionR and attempt distinct mutations. | One commitsR+1; the other stale/refused. Preserve both visible results without an implicit constructor-recovery ordering. |
| Context observes no namespace at0, then memory is created or tombstoned before context commit. | Reject stale memory; a deleted row is not absence. No stale context record. |
| Context observesR, then correction/deletion or task/auth change commits first. | Reject at final/atomic CAS; no context row, phantom command receipt or task advance. |
| Protected minimum exceeds rendered bound or complete-envelope cap. | Refuse `CONTEXT_LIMIT`; retain protected goal/constraints/supplements unchanged and persist nothing. |
| Crash before transaction commit versus after returned acknowledgement. | Respectively no durable mutation versus exact recoverable acknowledged revision/record. No automatic resend/import/key regeneration. |
| Estimator provenance fails or enabled child cannot be admitted. | Visible bounded unavailable/refusal; never quietly use another tokenizer or mark ready from config alone. Existing setup bytes stay intact. |

Final meaningful concurrent/crash cases use actual independently running Node processes and real SQLite storage. Typed doubles remain useful only for shape/reflection/lifecycle timing partitions. They cannot establish encrypted persistence, atomicity or actual packed CLI behavior. Fault oracles should use existing permitted seams or actual FS/SQLite conditions, not modify production core code.

## Hold, execution order and reporting

After root freezes this design, the author publishes APIs/source/test/package hashes and holds executable bytes. The independent lane then writes only its newly assigned adversarial file, verifies held hashes before/after, runs targeted meaningful module/process/native-no-listener cases and sends reproduced findings to root/author before any source remediation. Root supplies separate actual tarball/original CLI evidence after correction. Consolidated regression occurs at a later coherent hold; this design authorizes no broad old-suite rerun now.

Before the future required portability expectation change, preserve the old test's complete bytes and SHA256 as a historical snapshot. Add only the exact consumed `@deepseek-ai/dsh-token-meter:0.2.1-alpha.1` peer expectation, retain all existing provenance/missing/mixed/alias/duplicate/no-fallback assertions and record focused before/after command evidence. Do not modify that test at design publication.

Final NI1 review records command, Node/public package/source versions, exact source/manifest SHA, family/test names, expected/actual error or receipt/revision, counters, filesystem/state preservation, exit/result counts and elapsed time. First failures/source hashes remain separate from corrected retests. Synthetic examples, keys and canaries never become production settings or evidence payloads. Output scans are bounded and redact canaries rather than publishing secrets. A MODULE PASS or bounded packed-functional PASS must retain final CODE/browser/selected-model/full-product HOLD and the next required NI unit; no ticket, MVP, release, stable or remote/publication claim follows.

Publication disposition: **independent NI1 design ready for root freeze; implementation and all new NI1 execution await the specified holds.**
