The create contract and its twelve routes remain unchanged by this document. Original BUB004-03 and BUB008-01..05 remain required. ## 1. Eligible continuation and its durable origin

Support only the original installed NI2 worker for the same authenticated owner/workspace/task, using the exact pinned original AgentLoop factory and profile-owned JSONL root/compression. A predecessor qualifies only after its committed execution, exact captured version1 native-result artifact, actual synthetic usage, owned stopped/drained evidence, resolved effect/message/delivery/handoff obligations and authoritative reservation release. Its immutable action, claim, generation, execution, session, result and settlement facts must agree. A terminal task remains terminal; no resume route reopens it. Task control must independently be active. `control.resume` unpauses task control and never resumes a native worker or grants execution.

Add the signed `normal_native_intent -> normal_native_origin -> normal_native_capture -> normal_native_finish` graph from the trusted installed composer's **actual** create/capture/finish chain. Intent and encrypted native identity are atomic with the original claim; origin attaches actual created/baseline facts; capture is atomic with the encrypted artifact; finish is atomic with authoritative settlement. The graph binds ownerRef/workspaceRef/taskRef, original actionRef/actionDigest/claimRef/generationRef/sessionRef/executionRef, captured artifactRef/version/digest, terminal/outcome/release evidence refs, actual usage/accounting, persisted header/prefix digests/count and installed configuration/source/preset/environment/tool/permission descriptions with original factory/backend provenance. Process-local identities are checked live; persist only canonical descriptions, never symbols/callbacks. Only an exact known released finish qualifies. Pending/unknown graph facts retain accountability without granting resume.

Current create code does not yet persist this normal-origin graph. Signed worker mapping, action/spec and encrypted `df.native-result/v1` source prove important scoped facts but do not alone establish the installed composer/backend origin after restart. The primary create author confirmed this gap. Pre-origin records, advanced factory workers, legacy `bubbles-` IDs, forks/subagents, foreign tasks and manually copied transcripts are initially ineligible. No automatic backfill/adoption from matching JSON, header, prefix, filename, spec shape or an owner assertion is allowed. Root/core favor separate genuine schema7 after held schema5/6; exact graph/migration design must be frozen before source GO. Actual new schema7 normal creation must mint the graph; first-unit schema4 physical evidence cannot count as eligible schema7 origin.

Raw native ID is decrypted privately only from the exact scoped encrypted original identity record, checked against the original create algorithm `df-${originalGenerationRef}` and its UTF-8 SHA-256 sessionRef after current source/backend verification. Descendant continuations retain that same origin and sessionRef. Never derive it from the new generation or accept a raw ID/path/seed/proof from RPC. A lost prior handle is not stop proof; unknown/unreleased predecessors are observation/reconciliation cases and refuse new resume. There is no same-claim recovery, force unlock, replacement create, alternate backend or duplicate executor exception.

## 2. Closed optional selection and cumulative budgets

Propose optional `worker.continuation`; omitted or exactly `{enabled:false}` disables new normal-resume routes without history reads, native resume or streams. Explicit undefined is invalid. Enabled form is exactly:

```text
{enabled:true,maxContinuations,maxTotalAttempts,
 history:{maxEvents,maxMessages,maxBytes}}
```

All numbers are safe integers: maxContinuations1..8, maxTotalAttempts2..32, maxEvents1..96, maxMessages3..17, maxBytes256..49152. Enabled continuation requires enabled worker and memory. No enabled value is defaulted. The strict record/descriptor/Proxy/null-prototype/redaction rules and all create selections remain in force. Continuation must use the same selected source-owned local provider/model, fresh resolved `deterministic` reasoning, empty preset, environment and persistence root/compression as the current accepted configuration and the origin. A changed route/environment requires a separately specified future unit, not an implicit conversion of historical work.

The original workerPolicyPreview/Confirm explicitly disclose and accept the complete shared policy, now including continuation ceilings and plaintext retained history. NI3 role expansion, if enabled, must compose one shared policy with an explicitly sufficient maxTotalAttempts; it cannot overwrite the continuation selection silently. Keep units1, maxActive1 and maxAttempts1 per immutable group. maxTotalAttempts is a **per-task** cumulative ceiling; the existing declared runtime/usage/cost policy accounts across the store's charged actions. Released attempts and charges remain counted; actual usage greater than reservation is conservatively charged. Unknown usage/effects refuse further admission. Source-zero cost remains proven by the current owned deterministic registration, never provider-name or caller zeros.

Let ordinal0 be original create and ordinal1..maxContinuations be consecutive successful predecessor continuations. Derive each fresh group as `H(['df.installed-resume-attempt/v1',taskRef,originRef,ordinal])`, attemptIndex1. New generation/action refs derive from owner/workspace/task/origin/ordinal/command under distinct `df.installed-resume-*/v1` domains. Transactionally serialize the predecessor slot: at most one claimed successor of that exact released predecessor. A refused unclaimed plan consumes no native attempt; a claimed timeout/unknown consumes its attempt and blocks this chain. Never reset attempts through a fresh group, configuration reload or policy replacement. Counts/charges for producer, reviewer, repair and continuation all share the authoritative limits.

Retain create requestBytes512..131072, resultBytes128..16384, output128..4096, capture128events/1048576physical bytes and existing ledger/data limits. Continued accounting includes the **entire** actual ordered message JSON plus output reservation, not only the new instruction; require requestBytes+maxOutputTokens within the selected usage reservation and full request/output within the synthetic135168 context-unit cap. NI1 UTF-16 heuristic, UTF-8 history bytes and actual synthetic usage are separate labels. maxBytes counts the canonical header/events/surface/messages history payload. The complete encrypted history envelope must additionally fit existing maxDataBytes65536; metadata must fit the unchanged selected4096 limit. Oversize refuses as a whole, without truncation or silent policy expansion. The96-event history ceiling leaves nominal headroom below128 capture events; it is not a guarantee that a native turn uses at most32events. Actual complete capture still refuses if its independent cap is exceeded.
