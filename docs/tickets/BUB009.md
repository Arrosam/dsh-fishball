## Approved source scope and acceptance

BUB009 事件定时与 webhook 唤醒
目标 DSH 运行期间由可信事件或计划唤醒任务，重启后可对账，避免重复执行和离线盲目补跑。
范围 包含持久事件收件箱、验证、路由、去重、重试、计划与时区、过期判断、暂停和重启补偿。排除完整退
出后继续运行，排除上游 provider 未承诺的回放。
依赖 BUB001、003、005、006、012；通知经 BUB010、013。
预期行为 先认证与持久登记，再按 owner、workspace、订阅、任务版本路由。建议离线错过多个计划时合并
一次并重新评估时效；有外部副作用的计划不直接补跑。provider 能回放才请求回放，否则明确可能缺失。
验收标准
BUB009-01 按 owner、workspace、provider 与 event id 持久去重，防止重复派发；triage 冻结去重保留窗
口。崩溃恢复可能重新进入 handler，须可对账；无 id、签名失败、过期与错误订阅分别测试，不保证任意外
部副作用只发生一次。
BUB009-02 登记前后与处理途中崩溃时，恢复可分辨未处理、处理中、已处理和结果未知；副作用未知时先
查询，不盲目重试。
BUB009-03 DSH 停止期间不承诺接收；重启报告错过的本地计划和已知事件缺口，按配置合并、跳过或等用
户核查。
BUB009-04 时区变更、夏令时重复或缺失时刻、午夜跨日均有确定行为；计划显示 owner 使用的时区和下一
次运行时间。
BUB009-05 安静时段可继续允许的后台工作，普通通知延后且合并；紧急例外、频率上限和暂停须可配置并
有验证。
异常与竞态 乱序 webhook、队列爆发、撤销订阅时在途事件、计划与手动运行撞车、宿主重载、provider 超
时而重投。
评审结论 宿主 webhook 与内存 jobs 不足以直接满足该票，bubbles 必须补持久合同。建议先做一个事件来源
和一个计划闭环，再扩 provider。
统一待决项 D9 首个事件来源、错过计划策略、时区和安静时段；provider 回放能力逐个声明。
