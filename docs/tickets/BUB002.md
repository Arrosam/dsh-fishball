## Approved source scope and acceptance

BUB002 主对话接单与用户打断
目标 用户能随时提出新问题、纠正方向或停止任务，主对话持续可用，长任务不把交流锁住。
范围 包含请求归类、任务关联、澄清、优先级、打断和消息合并。排除用聊天内容直接执行未批准的高风险动
作，排除承诺瞬时中断正在发生的外部动作。
依赖 BUB001、003、006、008；工作执行接 BUB004、资源约束接 BUB012。
预期行为 收到新消息先登记再判断是新任务、已有任务补充或控制命令。能安全独立开展的工作继续；缺少必
要决策时只暂停依赖分支。优先处理用户的新消息，旧任务保持可见。
验收标准
BUB002-01 主对话接收同一 provider message id 的重复投递只建立一个入口；用户刻意重发但拥有新 id 的
消息保留，不按文本相同误删。
BUB002-02 同一任务运行时用户修改约束，任务版本递增；后续工作看到新版本，旧结果不得覆盖新要求。
BUB002-03 用户说停止时先停止新派发，再请求 DSH 取消；呈现已请求、已停止或结果不确定，不能在未确
认时写已取消。
BUB002-04 新问题与长任务并发时，无须等待整个工作会话结束才能接收输入和查询状态；响应性能在
BUB012 的选定环境下测量。
BUB002-05 确需澄清时，把相关决策一次汇总；可从已有上下文确定的事项不重复追问，也不把沉默当批
准。
异常与竞态 消息乱序；用户纠正与完成通知同时到达；多个远程入口同时改同一任务；删除了原消息；用户停
止后工作会话晚到的结果。
评审结论 保留为独立体验工单。关键不是一段欢迎语，而是用户能插话、能改方向、能看清停止是否生效。必
须测试并发消息与版本冲突。
统一待决项 D3 首发输入与响应性能目标；任务优先级是否允许 owner 配置。
