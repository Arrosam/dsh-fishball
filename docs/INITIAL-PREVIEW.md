# DF initial preview

This is the October8 local initial preview, version **0.1.0-preview.1**. The owner accepts incomplete validation for this initial delivery; it is not the accepted full MVP or a stable release. The package's `BUILD-METADATA.json` identifies its exact source commit, selected files and hashes. The worktree keeps the complete development history and evidence. Nothing is published remotely.

The useful initial boundary is a local DF workbench inside the maintained DSH Web app: encrypted task intake/query/control, scoped memory/context, explicit bounded native worker admission, a deterministic worker/result demonstration and retained artifacts. The host owns models, sessions, permissions, tools and HTTP/browser authentication. DF supplies product state and coordination. It has no separate harness, launcher runtime or background daemon. Quitting DSH stops it.

## Start and retain your work

The launcher is [initial-preview.mjs](../scripts/initial-preview.mjs); its original-host contribution is [initial-preview-host.mjs](../scripts/initial-preview-host.mjs). It uses the existing separately installed **DSH Web0.2.1-alpha.1** flat dependency graph and **Node22.22.2** on this Mac. The archive does not include that host, install packages, run lifecycle scripts or change the installed Desktop. DSH-X and the SDK are different products and are not dependencies of this preview.

The exact launch command and final smoke outcome are recorded in the delivery section of [the work log](INITIAL-PREVIEW-WORKLOG.md). Run from the repository or extracted package, pass the existing host root explicitly when needed, and use only the new initial-preview profile. The clean endpoint is `http://127.0.0.1:3091/`. Its authentication-required page alone is not the application. The launcher privately retains the authenticated launch URL; keep that file private and use the supported browser handoff. Never paste the URL, token, cookie or private raw host output into an issue or work record.

The profile, workspace, agents/session home, storage and private launch files are owned by this initial preview. A later start reuses only this same owned profile, so retained tasks survive. Do not move only a SQLite main file, discard its sidecars, replace keys or point it at another profile to clear an error. Keep the entire private state together. The older port3080/profile and the cancellation-requested QA record `4da34a6d` are excluded from this delivery.

The normal setup flow previews the exact local storage target and confirms it separately. First load and preview do not authorize work. Model policy, action preview and exact grant are separate decisions; creating a task is not an execution grant. Refresh/reconnect does not repeat a mutation. A missing reply after create or execute is uncertain: inspect current status rather than resubmit the same operation as new work.

Use the local task panel to create/select a task, refresh status and inspect its state. Native worker controls resolve the current catalogue and context, preview/confirm policy, plan/preview/grant the action, create an idle worker and explicitly execute it. Capture/result/finish use the existing original receipt path. The local artifact remains associated with the task and available through the panel. Controls may be disabled until storage, policy, context and exact current consent are ready; this is a meaningful admission refusal, not a suggestion to broaden DSH permissions.

To stop, quit the owned DSH process or send Ctrl+C to its launcher. Closing a browser tab alone does not stop the host. Cancellation requests stop new dispatch first; they do not instantly undo a running call. Held or unknown work remains accountable across restart until factual termination/outcome evidence resolves it. Retain the private state on an incomplete stop. No cleanup command in this delivery deletes tasks or an old profile.

## Build and install boundary

[package-initial-preview.py](../scripts/package-initial-preview.py) creates a deterministic local tar.gz from an explicit public-file list. It includes the canonical plugin source, generated Web client, source descriptor, notices, launcher and selected documentation. It excludes `.git`, personal files, runtime dependencies, private homes, keys, credentials, logs, databases and historical fixture directories. The source descriptor's protected files are copied as opaque bytes; packaging is not a final semantic code audit.

The builder takes the committed source identity as an explicit argument, normalizes archive ownership/timestamps, records member hashes and writes an external archive SHA256. It does not run npm, download code, regenerate the client or execute the plugin. Keep the archive and hash together. Its exact filename and source commit are in the work log's delivery record and the final delivery message. The archive is an initial-preview artifact, not a public npm or GitHub release.

Extract into a new directory. Supply the same separately installed pinned flat DSH host to the launcher. The launcher links only the existing selected peers for that owned package/profile and invokes the original CLI. An unknown/nonflat/changed host, a different Node version or an unsafe/unrelated profile refuses rather than installing a fallback. [Runtime installation](runtime-installation.md) explains host/profile resolution and the underlying native APIs; [compatibility](compatibility.md) records the pinned target.

## Persistence, versions and recovery

The durable SQLite ledger is scoped by owner, workspace and task. It records task versions/authorization epochs, immutable command digests, complete source identities, actions, grants, claims, reservations, worker mappings, event/message/outbox state and encrypted content/artifact associations. The initial setup selects one private database and key. Diagnostic/export metadata uses references, digests, types, counters and stable codes; it does not export decrypted prose or keys.

The foundation began with schema1/2. Runtime stages added schema3/4, followed by the normal native provenance/resume composition's later schema7 interfaces. These are chronological schema cuts, not interchangeable current defaults. The existing [runtime API](runtime-api.md), [workspace/automation API](runtime-automation-api.md) and [normal resume contract](normal-worker-resume-contract.md) describe the transitions and their proposal/implementation cuts. Current normal single-worker code is the canonical schema7 composition; the protected final schema/provenance audit remains unfinished. Do not infer exhaustive migration acceptance from that worker result.

Supported migrations validate source/version/topology/key invariants and retain a durable pre-migration backup. Unknown/future/corrupt/WAL/unsafe/legacy-unverifiable storage fails closed. The ledger supports the specified DELETE journal recovery boundary; ordinary copy-and-delete is not a supported migration. Encrypted records use the existing crypto2 AES256GCM format with authenticated scope and closed record metadata. Prior records lacking verifiable authenticated provenance are preserved and refused rather than silently resealed. The native vault and its key must stay with the exact owned profile.

Restart reconciles in-flight actions, mappings and outbox outcomes as unknown/held. It does not infer that a lost reply means no effect, recreate an agent, resend a message or repeat an external mutation. Admission capacity includes held unknown obligations. An eventual terminal observation, outcome and release receipt are separate facts. A clean process exit or empty browser does not substitute for the factual worker/session/outcome bindings.

## Tasks, consent, worker execution and cancellation

The ledger owns task status and revision. Task states distinguish queued/running/completed/failed, cancellation/recovery and related control facts. Action/worker/execution states are independent: a worker can be idle while its durable execution is unknown; a result does not itself complete the task. Pause fences new work. Cancellation is a request, with later factual stopping/confirmation. Same current command is idempotent; the same command reference with different normalized content conflicts.

At claim, one transaction checks trusted handle scope, complete immutable action/target/data digest, task version, authorization epoch, current unexpired grant, current model/resource policy, permissions and admission. The transaction reserves before a provider/native effect. Revoke/cancel before the claim rejects it; after the claim they stop new dispatch while existing obligations remain held. No arbitrary external effect has an exactly-once guarantee. The UI must not imply instant cancellation or automatic refunds.

The normal worker resolves original current native catalogue/model/preset/environment/persistence facts, prepares source-bound task/context, previews and grants an exact action, creates one idle original DSH agent/session, then explicitly executes its approved context. Tools are empty/vetoed in this initial demonstration. Native request/stream/history/result facts feed the original capture/result/finish path; a JSON success flag is insufficient. Source cost/usage accounting and actual usage remain distinct from billing limits.

A status response is task-scoped. The ordinary client reconstructs worker `taskRef` from the enclosing task and takes action/digest/claim/reservation/generation/session/phase from the worker row. A worker-query receipt carries the full binding. The delayed validation incorrectly required a raw status row to repeat `taskRef`; that fixture mismatch does not prove a broken product identity boundary. Its failed result remains failed and will be corrected only in a future explicitly selected check.

## Memory, events, delivery and audit choices

Memory uses explicit owner/workspace/task namespaces and revision checks. Correct/forget operations affect future retrieval and current context, while tombstones distinguish forgotten state from a missing namespace. Bounded context construction includes current task/constraints and selected retrieved memory; earlier task versions do not authorize new work. No personal memory source is shared, imported or searched automatically. [Fishball provenance](fishball-provenance.md) and [notices](../THIRD_PARTY_NOTICES.md) identify the translated subset and license boundary.

Schedules and event ingress run only while DSH runs. Durable source/event identities deduplicate complete ingress. Unknown external side effects are retained for reconciliation. Native owner ingress and local approved schedules are different from a public live webhook receiver; no live account or background daemon is configured. The neutral chat contract is implemented and tested, while choosing and connecting a chat product remains deferred by the owner amendment.

Result records associate encrypted content/digests with an immutable task/artifact/version/producer scope. Verification is separately scoped; a producer cannot self-mint independent reviewer authority. Optional notifications/delivery distinguish accepted/sent/delivered/access facts, expiry and stale observations. The default initial profile promises local persistence/display only, not external chat/email delivery. Runtime audit/repair is implemented as bounded optional workflow and consumes resources; it is not a substitute for development review, nor an untested real-model-quality guarantee.

## Ownership, errors, dependencies and tradeoffs

Trusted native OperatorPeer/profile and private process capabilities establish identity. Model/payload owner/role/permission fields never do. Secret/key/auth values stay out of evidence, logs, exports and memory. New profile/private files use owner-only permissions and reject unsafe links/unrelated roots. Errors are stable bounded codes; raw owned diagnostic files remain private. The service is loopback-bound, uses original DSH authentication and retains original permission fences.

The plugin uses Node built-ins, SQLite and separately pinned public DSH/Cordis/AgentLoop/Session/Connection/persistence/preset/tool/token-meter packages. Exact dependencies and notices are in [package.json](../package.json), [runtime package](../scripts/dsh-web-runtime-package.json), the tracked host lock, [compatibility](compatibility.md) and [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). The package does not redistribute the full host or fishball application. MIT is the explicit owner choice, not an inferred publication decision.

Principal design tradeoffs are: one transactional ledger instead of summaries as state; fail-closed unknown outcomes instead of automatic replay; exact immutable consent instead of broad payload flags; current source/native facts instead of arbitrary provider claims; optional adapters instead of a new harness; host-lifetime scheduling instead of a daemon; a strict pinned preview host instead of unverified cross-version shims; and a local initial package with disclosed debt instead of waiting for exhaustive acceptance. These choices protect retained work, but make setup/admission more explicit and limit the initial provider/tool surface.

Deliberate deferrals include real cloud inference, production/live chat and webhooks, arbitrary tools and cross-environment handoff, fully accepted native cold resume, real-model audit quality, full browser/visual matrix, exhaustive migration/fault/resource/performance acceptance, mobile control/Hydrogen integration, arbitrary host layouts/platforms, stable/public releases and the unfinished protected final code audit. Deferred acceptance is preserved, not silently removed from the tickets.
