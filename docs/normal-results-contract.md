# NI5 normal local artifacts, results and notification contract

Status: docs-only design candidate from baseline d91d749. Root must give separate contract/design GO before source/test/library/Git/native-host changes. This is required normal implementation under [normal integration](normal-entry-integration-plan.md), preserving all82 original source AC plus5 DF010 contract AC. ## Actual supported local route

Pinned DSH Web0.2.1-alpha.1 supplies the original authenticated Connection RPC/Fetch registries and native client renderer/sidebar/workspace composition. It does not supply a generic host-to-owner message push, opened artifact receipt or recipient-read acknowledgement in the inspected public Connection interfaces. Session.append/session events/Agent.inject can alter model-visible session history; append/flush/queue success proves neither owner receipt nor result opening. NI5 will not invent such a native method, append fabricated assistant output or wake a worker merely to present a result.

The concrete supported local result route is the normal installed **df native panel**, backed by exact scoped encrypted ledger artifact/result reads through the existing admitted `/df-rpc`. The renderer is the existing client plugin, not a second app/harness. Implement local publication/recipient resolution and exact result-read/query/access code even while external channels stay disabled. No anonymous file/webhook server, filesystem download path, external recipient, new account or callback selection is allowed. Actual rendered opening remains HOLD until an authorized supported browser oracle exists.

RecipientRef is privately derived from retained owner/workspace, verified profile and `df.native-owner/v1`; channelRef derives the same scope and `df.local-results/v1`. A live private recipient capability additionally binds the actual current HostConnectionService/OperatorPeer object, admitted child lifetime and profile. The user may select the local route; JSON may not select an arbitrary recipient identity, host/service object, generation, opening proof or digest label. Refresh/current-access resolves actual native facts again. Restart retains durable recipient/channel references but replaces live capabilities; old copied references or callbacks cannot represent the new peer incarnation.

## Named normal report and notification provenance

`writeLocalReport` is exactly `{taskRef,commandRef,expectedTaskVersion,expectedAuthEpoch,progressRef,kind,artifactRef,artifactVersion,digest,completedScopeRef,unfinishedRef,nextStepRef,blockerRefs}`. Kind is milestone|obstacle|question|final; blockerRefs is a unique bounded list of at most16 scoped references. Content selections must identify existing permitted encrypted context,clarification or constraints material in this task, with byte/digest integrity checked. These are explicitly selected report statements, not new native facts or proof that the scope is complete. The owner supplies report content references only. It cannot supply originalGoalRef,verificationState,verificationEvidence,progressDigest,semantic revision,time,producer/reviewer identity,passed/delivered/emergency flags or a provenance object.

The closure calls additive typed `writeLocalProgress(owner,input)` with precisely the same closed fields. In one existing Ledger transaction it checks task/auth CAS, selected current immutable artifact version/digest, actual independent source-bound verification/audit facts and selected material. It derives the actual original goal reference from retained authoritative intake/goal history, current semantic revision and server date. It writes normalized encrypted report bytes, the existing progress association and a signed localReport association atomically with the command receipt; invalid association/version/capacity changes nothing. Original goal remains original while semantic/context changes invalidate applicability of an earlier report. Derived report progressDigest covers normalized factual content/status/coverage/digests and relevant semantic/artifact version binding, excluding progressRef,commandRef,server report date and record identity. Identical facts under another progressRef cannot evade normal fact dedup; the signed localReport binds all those identities separately. The typed read is `readLocalProgress(owner,{taskRef,progressRef})`, returning only actual `{progress,report,localReport,currentness}`; currentness is current|stale|unverified, read-only, with no key/handle/raw proof exposed to configuration. A raw advanced progress record returns report:null/localReport:null/currentness:unverified rather than treating its plaintext verification labels as trusted normal facts. Corrupt encrypted/signed metadata rejects instead of becoming unverified.

localReport binds exact owner/workspace/task/progress record/digest, original goal/ref/digest, scope/unfinished/next/blocker record/digests, artifact/ref/version/digest, current semantic revision and actual verification/audit evidence bindings, with contractVersion df.local-progress/v1. Normal passed requires NI3's signed authentic native audit_result→current report→exact artifact verification association and actual independent producer/reviewer/material/semantic coverage. Bare advanced verifyArtifact accepted with guessed evidence, legacy records and untraceable provenance derive unknown/provenance-unavailable; they are never resealed or blessed as normal passed/not_run. Normal report retains the existing goal/scope/unfinished/next/verification/evidence/blocker/progressDigest fields but uses source-derived verificationState passed|failed|not_run|stale|unknown|unexamined|budget_limited|blocked; advanced normalizeReport remains unchanged. The normal typed branch validates its complete closed shape and source evidence rather than passing unknown through the older four-state normalizer. Required audit failures/uncertainty remain completion gates. Content summaries and report labels do not resolve findings or confer authority.

Aggregate state precedence is explicit and matches the core-author freeze: stale for bound artifact/material/semantic drift; otherwise blocked for fatal/configured blocking findings or required pending review with no current report; otherwise budget_limited for actual signed budget_exhausted; otherwise unexamined for actual current report partial/unexamined coverage; otherwise unknown for actual unknown verification/audit or provenance-unavailable; otherwise failed for remaining known negative report/rejected verification; otherwise not_run only when no review/verification/audit exists; otherwise passed only for the complete current authentic covered chain. Unexamined remains aggregate even when that partial coverage derives unknown artifact verification. Missing original goal or protected source refuses typed writing rather than inventing provenance. localReport additionally retains every applicable source audit's actual pending|passed|failed|unknown|budget_exhausted state, verdict, exact binding, coverage/unexamined references, findings and repair/currentness metadata, bounded by existing caps. Aggregation never erases historical failures, fatal gates or an uncertainty axis; a stale display cannot authorize completion or imply a prior failure disappeared.

## Truthful local publication, query and access

Local recipientAdapter.send is invoked only after the existing atomic exact delivery claim commits reservation/outbox. It rechecks the current live native recipient route, original scope, artifact version/data digest and committed claim/generation. It publishes only that immutable delivery in the normal native result list, using existing Ledger delivery/artifact rows as the durable publication association. There is no second queue/store or borrowed user/model session. The private adapter returns **sent** with actual route/byte publication evidence and current permission only if that local publication was actually committed and accessible; openability remains unknown. A registered route alone or a successful callback that published nothing is not sent. If publication or acknowledgement may have happened but cannot be proved, return unknown and retain ownership. If an effect could have occurred, never synthesize confirmed failure.

One additive core requirement is proposed before implementation: `publishLocalDelivery(host,{taskRef,commandRef,deliveryRef,claimRef,generationRef,actionDigest,observedAt,evidenceRef,notification?})`. This is a private typed RuntimeStore method, not a native DSH API or caller-provided evidence. In one existing Ledger transaction it rechecks the exact current action/grant/auth/control and policy, immutable current artifact/data/recipient/notification binding, private installation admission fence and committed outbox, then commits sent with opening unknown to the same delivery row. The publication association uses the same existing delivery row; normal provenance requires schema6 as defined above, with no new publication store. Separate assertClaimCurrent followed by deliveryObservation is insufficient because revoke/cancel can linearize between those transactions. Optional notification is exactly {policyRef,policyRevision} and required iff the immutable delivery has notification; it must match that complete original binding and actual current enabled policy/revision under lock. Omitting it cannot waive any policy. Core recomputes complete canonical publication UTF8 bytes and checks the exact action.charges.usageUnits at both atomic claim and publication under source-owned local-none permission. For notifications publication revalidates the existing committed claim/group/fact ownership and current predicates without new frequency/resource charging. There is no owner RPC carrying this private host input, observed time or evidence. ledger_core owns the serial core edit after NI2 core holds; this author owns the new module only. Source GO must freeze the exact method with ledger_core; runtime cannot emulate atomicity by returning a sent callback before the durable publication exists. The adapter then returns the exact committed receipt, and the existing ResultPipeline observation is idempotent rather than a second effect. Cancellation/revoke first refuses publication; publication first retains the already-committed sent/unknown obligation for later reconciliation.

The authenticated local result list/read endpoint derives visible publications from actual scoped delivery/artifact records and current peer access. The owner can read/inspect the exact bytes without the UI claiming delivery. An HTTP response, returned JSON, route registration, local path, queue injection, link existence, client boolean or echoed digest cannot establish recipient receipt, browser rendering or opening. The current inspected public host exposes no generic trusted opened/read receipt. Therefore the initial normal adapter must truthfully preserve sent/unknown and opening unknown; **it must never synthesize delivered/granted+verified opening to satisfy a fixture**. Actual independent recipient evidence would require a separately frozen supported trusted observation source; no new browser hook/proxy/tool bypass is authorized here.

`query` reads the exact durable publication/observations and current route facts; it performs no send, append, new claim or arbitrary effect. A source-confirmed sent publication can remain sent; uncertainty is reported unknown. `open/currentAccess` is a read of current native permission and exact record availability, never an external launch or inferred rendering event. If the route is no longer admitted, current permission is revoked/unavailable or unknown according to actual facts; opening remains unknown unless a supported trusted observation really establishes it. Distinguish available exact bytes from verified opening. A historical delivered receipt supplied by a future supported trusted source stays delivered after later access revocation, with separate current access and monotonic observations. Current failure does not erase historical truth.

Because ResultPipeline.currentAccess is deliberately delivered-only, NI5 defines a separate exact local branch instead of weakening it or synthesizing delivered. The private normal localDeliveryAccess handler resolves actual native recipient permission and exact publication/bytes, then calls `recordLocalDeliveryAccess(host,{taskRef,commandRef,deliveryRef,artifactRef,artifactVersion,digest,recipientRef,channelRef,permissionState,observedAt,evidenceRef})`. Core verifies exact published association/current scope/lifetime, derives opening unknown (no input field), checks monotonic actual time/evidence and updates only currentAccess while preserving state/historical receipts. The original delivery may be sent,unknown,failed or historically delivered; no released claim is re-required for a historical access read. Unknown opening never certifies delivery. Private server-derived permissions/evidence/time are not RPC fields. Retain existing signed observation bounds and protected terminal/reconciliation capacity; repeated access refresh cannot starve the final known receipt or command reserve.

No false terminal release is permitted. Sent/unknown publications retain reservation/message obligations until an actual known outcome and native termination/resource settlement evidence permits release. HTTP request abort/disconnect after claim does not erase the effect. Reconcile query is the sole operation after unknown; no automatic resend, new delivery ID, expiry, policy change, restart or changed report circumvents held group/fact ownership. A confirmed failed/released item alone may use a new exact approved attempt with original previousDeliveryRef and same item/recipient/channel.
