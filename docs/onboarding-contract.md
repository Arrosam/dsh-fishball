Existing valid state can be read to resume its same namespace/key and compose the closed runtime; no replacement key or identity is created. Never silently create a fresh namespace over retained state.

## Setup RPC

All methods require the native admitted owner peer, a live current plugin and strict bounded plain JSON. Stable error codes only. No key, raw secret, private handle or credential value is returned.

| Method | Input | Result / permitted effect |
| --- | --- | --- |
| `v1/status` | `{}` | `{ phase, executionEnabled: false, storage: { location }, reasonCode? }`. Phase is `setup_required`, `ready`, `recovery_required`, or `unavailable`. Reading does not initialize persistent state. |
| `v1/prepare` | `{}` | Volatile `{ previewRef, planDigest, expiresAt, description }`. Description has `operation: create-local-storage`, `databaseLocation`, `identityMode: native-dsh-owner`, `encrypted: true`, `permissions: owner-only`, `externalExecution: false`. No persistent writes. |
| `v1/confirm` | `{ previewRef, planDigest, accept: true }` | Explicit one-use acceptance of that current exact plan. Recheck live peer/scope, expiry, path/binding and unchanged empty-state facts at commit. Create only the described bounded private local identity/key state and encrypted runtime database, then return current status after real runtime activation. |

Setup previews expire within60seconds, belong to this plugin/owner generation, and are invalid after unload, a new preview, target change, prior commit or expiry. A false/missing acceptance, unprepared confirmation, stale/different digest, unknown field or concurrent loser creates no alternate state. Multiple processes cannot overwrite the winning installation state. This setup consent grants no model/tool/recipient/event authority.

Use private owned files/directories with0600/0700 modes, bounded versioned authenticated/checkable metadata and atomic no-overwrite publication. The unchanged RuntimeStore auto-creates a missing SQLite target, so a preflight check alone cannot protect against concurrent target creation. Recheck canonical profile/parent/path, owner/mode/inode binding and empty-state facts at claim/publication. Partial markers and uncertain outcomes remain preserved; do not claim an atomic transaction across arbitrary external effects.

Keep secrets out of repository, log, status, evidence, task ledger, memory and RPC. Do not pass key material through profile JSON. Zero transient key buffers after runtime copies them. Preserve partial/uncertain state and report stable recovery/unavailable status if storage or activation fails; do not silently replay confirmation or generate another key. A request abort before commit prevents initialization; abort after commit cannot undo durable facts. Read status before retrying an uncertain result.
