# Outside agent: headed CLI conversations in DSH

**Decision:** ship `dsh-outside-agent` as a separate, explicitly installed DSH plugin, proposed repository `/Volumes/SSD1/GitHub/dsh-outside-agent`. Do not create it as part of this design review. An outside session has one live interactive CLI and one structured conversation. Opening it shows messages, status, a CLI-specific model selector and a composer in DSH—not a terminal. The local user can give Fishball control of that same session and take it back.

**Evidence convention.** “Verified” below means inspected source for DSH 0.2.2-rc.3 / connector staging, or the cited vendor documentation, not a successful live integration. All new interfaces, cache policies and version gates are proposals. None of the three CLIs was run; no provider settings, credentials or session stores were inspected.

**DSH loading.** Follow the [connector manifest](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/package.json>), [Cordis bundle patch](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/cordis.patch.yml>) and [isolated link fixture](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/tests/wire/worker.mjs>). Give the new repo its own package name, version, host entry/exports, `dsh.bundle.patch` inserting its host plugin, and `dsh.client` web entry/injections for the renderer, layout, sidebar and locale. In a disposable DSH profile install/enable the two packages **as siblings**: e.g. `"dsh-outside-agent":"link:/Volumes/SSD1/GitHub/dsh-outside-agent"` and the connector's actual manifest name linked to the connector **package directory** in its implementation worktree. Do not add either link to the other's dependencies, make a global Node link or edit the installed DSH. Exercise actual DSH bundle resolution, activation, UI registration and disposal. Release and enable separately; clean removal must leave regular DSH/Fishball working. No auto-install. Trusted host plugins share a process: this is an installation trust decision, not a sandbox between packages.

**Registry v1 (proposed semantic ABI, not present in staging).** Use the [unmerged registry](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/feat/external-sessions/packages/dsh-connector/host-services/sessions.d.ts>) at `22f6bea` as precedent, not the [prototype lifecycle](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/feat/external-sessions/packages/dsh-connector/src/external/index.js>). Port against staging (`61c4e35` inspected); do not merge it. `backends.register({apiVersion:1,id,label,catalog,prepare,lookup,read,act,leaseChanged}, caller) → registration/dispose`. Registry scopes IDs/callbacks to trusted registration; reject unsupported versions, duplicate IDs, oversized or malformed results. Connector allocates/recognizes a reserved routable ID namespace by backend; plugin mints unique IDs within it, never claims native IDs. `prepare` creates a session **without** a message. `lookup/read` expose bounded summaries/messages; `act` accepts typed send/interrupt etc., not arbitrary commands. Registration-scoped host sink reports turn settled, state changed or a verified blocking permission request/withdrawal; no raw output. Negotiate a typed one-call response bound to the registered request and lease, not a terminal command. Negotiate capabilities per version. Plugin can operate locally without connector; absence/incompatibility disables Fishball controls. If connector disappears revoke its writer/offer immediately. If plugin disappears abort dispatch, remove catalog entries and revoke leases; persisted mappings alone grant no access on reconnect.

**No two sources of truth.** Connector stores its normal manager→ID routing only. Plugin owns the view/store for all its rows; the authenticated handover/takeback operations resolve plugin IDs through the registry and publish lease changes. Before Fishball sees a read or event, connector checks the current principal and share boundary. Before a side effect, plugin serializes under a per-session fence, checks active registration, policy, generation and current connector-issued lease; revocation fences in-flight actions at the final write, not just tool entry. A disconnect is never implicit consent to replay work.

## 3. From a headed process to a readable conversation

Use a confined `ctx.subprocess.spawnTerminal` with verified host policy binding, canonical cwd, fixed executable/argv, real TUI terminal type and scrubbed environment. The [terminal controller](</Users/samuel/Library/Application Support/DSH/data/versions/0.2.2-rc.3/node_modules/@deepseek-ai/dsh-api-terminal-controller/src/index.ts>) opens a new shell owned by a DSH Agent, not an arbitrary external CLI or adoptable PTY. The [terminal handle](</Users/samuel/Library/Application Support/DSH/data/versions/0.2.2-rc.3/node_modules/@deepseek-ai/dsh-subprocess/src/types.ts>) exposes bytes, input, signal and process lifetime—not roles or turns. No shell wrapper/second chat process, ambient fallback, terminal panel or remote keyboard. PTY lives independently of windows; revalidate confinement on policy changes or stop writes and require safe restart.

**Projection pipeline.** Adapter binds `{outsideId,generation,cwd,providerSessionId,rootTurnId}` at launch → admits only same-root normalized events (`promptAccepted`, `assistantFinal`, `turnEnded`, `attention`, `modelChanged`) → deduplicates by provider record ID/cursor + generation → plugin assigns monotonic `seq`, bounded text and user/assistant role → UI snapshot + ordered deltas; Fishball gets the same filtered records since handover. Mark a pending composer submission separately until acknowledged. Partial text is optional and replaceable; a final record commits once. Keep tool traces, thinking, hooks, chrome, prompts for secrets and subagent messages out of the timeline. Backfill a gap from an authorized source only; otherwise show “history incomplete,” never concatenate screen redraws. A final text event and a safe-to-write composer are different facts.

|---|---|---|

[Resume](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli) by `codex resume <ID>`. | Correlate top-level hook and record IDs; map accepted user message and final assistant text only, not tool items. Pins/fixtures required for any file decoder. |
| Claude Code (`claude`) | [CLI](https://code.claude.com/docs/en/cli-reference.md) supports `--session-id <UUID>` / `--resume <ID>`. **File access is an exception, not discovery.** Prefer private launch-bound events. Enable transcript mode only with explicit local consent for the plugin-created session and a version-specific format. A path in a hook is untrusted: require trusted launch origin, pinned ID, authorized provider-owned root and exact file, regular file/no symlink traversal or replacement (verify opened handle), session/cwd match; bound record size, tail/cursor and time. Only extract allowlisted fields; discard raw data immediately. Never glob histories, choose “latest”, follow arbitrary paths, import old chats by default, or read auth/config stores. A missing file is pending, not an empty reply. On rotation/truncation/schema mismatch stop ingestion, preserve last verified seq, signal gap. If a safe reader cannot be built, that channel is not supported.

**Fallback:** unknown build, ambiguous ownership/role, unsafe input targeting, or no reliable extraction → retain verified messages, set “Conversation unavailable for this CLI version”, disable composer/handover/managed start and show cause plus End/explicit resume or update instructions. User can continue outside DSH only after exclusive ownership is safely released. Never show raw PTY, infer assistant replies from ANSI, silently launch headless mode or treat degraded sessions as a successful integration.

## 4. Ownership, approval and session lifetime

Persist `{externalId, backend, profileVersion, canonicalWorkspace, title, confirmedResumeId?, createdAt, lastStatus, nextSeq}`; retain manager identity in connector's existing routing store. Keep `{launchGeneration, ownedHandle, inputEpoch, outstandingTurn, promptRevision, boundedScreen}` in memory. Provider ID, external ID, DSH Agent ID and PTY handle are **not interchangeable**. Proposed default: redacted, byte- and count-bounded delivered turns in memory only, metadata durable, no PTY recording. `session_read` returns newest complete entries in order with `truncated` for eviction/gaps (including previous-process history); reconnection never invents history. UI shows what will be shared on handover; expose only redacted conversation from the consented boundary (default: current handover forward) plus the single bounded pending request if its transfer is expressly confirmed. No bulk import of provider transcripts.

| Event | Required behavior |
|---|---|
| User selects **New outside agent** | Choose installed, eligible backend and authorized folder; create unmanaged record, spawn once, show readiness or actionable failure. User is writer. Row selection later is attach-to-view only. |
| Fishball starts | Authenticate paired principal; validate capability, folder, quotas and arguments before allocating. Reserve ID, spawn, wait for verified normal composer, bind manager and admit first text under that ownership. Publish coherent row/result or roll back new record/ownership and reap process before first delivery. |
| Submit/finish | Serialized per session. At most one turn in flight. Normalize and bound text, reject control sequences and provider command/shortcut prefixes; use verified literal input mechanism (atomic paste plus adapter-controlled submit only if safe) to the normal composer, never replay unconfirmed input. Append the acknowledged user/principal turn once and final assistant turn once, with monotonic seq. Redraws and echoed input are not new turns. |
| Hand over | Local user confirms the selected paired Fishball by stable ID and sharing boundary. Normally require verified idle with no partial input, in-flight write or unresolved interaction. The sole pending-prompt exception is below. Under the session lock fence old actions, bump the input epoch, bind manager and emit the handover event. Same process, session ID and conversation; local observer, no second writer. |
| Take back / `session_release` / manager loss | A confirmed takeback revokes Fishball immediately, even if busy. With a pending prompt use the same confirmed reissue procedure below. Release, connector loss or revocation fences the old epoch and retires its offers; never replay input or convert a stale offer into a user answer. Already-running work may continue; show it and allow only verified recovery/interrupt. Involuntary loss is not consent to issue a replacement remote offer. |
| Disconnect, stop, close, exit | Closing/collapsing a view releases its subscription, not the CLI. Stop interrupts only the active turn using the adapter's verified interrupt, waits for acknowledgment; no close-as-stop. End Session explicitly terminates owned process tree and marks exited. Crash/unload/restart: invalidate handles/offers, settle active turn once as stopped, reap owned children, recover metadata as disconnected. Explicit resume only after exclusive ownership/no surviving writer is proven, by exact provider ID in same workspace; otherwise offer **new session**, never automatic resend/restart. |

**What Fishball observes:** internally model `starting → ready → running → ready`, with `waiting_user`/`waiting_approval`, `unknown`, `exited` and `disconnected` distinct. Route to existing `sessions_list` (`running` = active turn, not live process; `pendingInteraction` for waiting user/approval), `session_read` (seq/role/author/text, empty images), and ordinary `turn-finished` inbox events, respecting the connector's manager-stop suppression. Add optional external summary `{backend,state,inputMode}` to the closed schema if needed to distinguish idle from disconnected/unknown without abusing booleans. On ownership change, filter reads, streams and future events at dispatch, not just on subscription. Don't send a manager another principal's content.

**Evidence for state:** adapters must bind events to the top-level process, generation and turn: e.g. provider session-ready, submitted prompt, final assistant event and cancel/exit. Per-launch, private authenticated local event channel only if supported; validate origin, schema, role, size and ordering. Project files, process stdout and arbitrary hook invocations are untrusted; do not install global hooks or assume a hook name authenticates its sender. If authenticity/isolation cannot be demonstrated, do not use a hook for authority. A version-pinned VT parser can provide conservative display/attention hints, not an authoritative approval or proof of readiness based on model-printed text. `inputWaiting`, prompt glyphs and silence are insufficient. Fail to `unknown`, withdraw writes, and show a human recovery action. Gate managed capability on reliable same-process input targeting **and** turn boundaries; a manual-only adapter must never be advertised as Fishball-ready.

### Native CLI permission offers

**One prompt, one decision owner.** A verified native tool permission request pauses ordinary writes. For an unmanaged session the authenticated local user receives a local offer with **Allow once / Deny**. For a managed session only its **current** eligible Fishball receives a connector offer; the local panel says who can answer and offers explicit takeback, not duplicate decision buttons. A local offer is not placed in a remote inbox. A disconnected manager’s valid offer can wait without a timeout while the request and lease remain live; no timer ever decides it. Neither ownership nor a click to transfer is permission to execute. DSH launch/sandbox policy, CLI policy and connector policy must all permit the operation; no remote reply can override them.

**What constitutes a verified offer?** Bind the registered backend, outside ID, owned process/generation, canonical workspace, native session/turn/request identity, immutable tool + arguments, reason, offered one-call choices and decision transport to the live blocking prompt. Bound and redact before display or routing. Provider-native evidence varies:

| CLI | Documented evidence | Gate for a headed session |
|---|---|---|
| Claude Code | [PermissionRequest input and decision control](https://code.claude.com/docs/en/hooks.md#permissionrequest-decision-control) is invoked for a permission decision and can return a per-request `hookSpecificOutput.decision.behavior` of allow or deny. | Use only a private, authenticated, launch-bound blocking hook, matched to this top-level request. No updated input or permission rules. Prove timeout/abort retires the offer and a stale hook cannot respond. An unrelated hook invocation is not consent. |
| Codex | [App Server approvals](https://learn.chatgpt.com/codex/app-server.md#approvals) are server-initiated JSON-RPC requests, e.g. `item/commandExecution/requestApproval` with thread/turn/item IDs and offered decisions; one-call `accept` / `decline`, not session grants or policy amendments. | Use only the pending request on the **same instance/client** that owns this headed operation. Starting another server, reading a transcript or matching a thread ID does not answer the TUI. A TUI-only build needs a separately certified, version-pinned adapter proving native modal origin (not model text), full request, exact one-call choices, unchanged revision/focus and exclusive targeted response with settlement readback. Generic VT text is not that proof. |
| Antigravity CLI | [agy hooks](https://antigravity.google/docs/hooks.md#pretooluse) document pre-tool policy (`allow`, `ask`, `auto_approve`, etc.), not a demonstrated per-call response to a *pending native* permission modal. | Approval transport unknown. Never substitute a pre-tool allow/override. Local-human attention only until exact build, identity, choices and settlement are independently proven. |

If detection **or** response transport is uncertain, or the prompt is for auth, workspace trust, billing, OS permission or secrets, surface local-human attention only: no remote offer or permission details, no DSH decision buttons, no blind keys. Keep the manager unchanged, suspend writes and explain safe local recovery (e.g. end/release before continuing directly in the CLI). A known request ruled ineligible by policy also cannot acquire a remote allow path. Surface the restriction; do not silently take back, weaken the native policy, lower the risk or treat a refusal as consent.

**Transferring a pending decision** is the only exception to idle-only handoff. The same process must be quiescent *at one verified blocking permission prompt*, not running elsewhere, editing a draft or waiting at an arbitrary screen. Show the authenticated local user both owners, the session/workspace, bounded tool, arguments, reason and one-call choices being shared (even when the turn predates forward-only sharing). Confirm **transfer of control and this decision**, not approval of the request. Cancel leaves the original owner/offer unchanged. Under the per-session lock retire the old offer, invalidate its writer epoch and all pending callbacks, and revalidate the very same native request, fingerprint, live transport, eligibility and target manager. Issue a fresh revision to the new sole owner only after all checks pass. Takeback does this in reverse; the old Fishball revision can never answer the reissued local card. If the prompt changed, settled, disappeared, cannot be safely shared or cannot be rebound, issue no replacement: refresh state, require local-human attention for unresolved work, never guess the answer. Do not silently transfer to cure ineligibility.

**Answering Fishball offers.** Use the existing [tool schemas](../../packages/dsh-connector/mcp-schema/tools.js), [offer desk](../../packages/dsh-connector/src/mcp/tools/offers.js) and [per-pair inbox](../../packages/dsh-connector/src/mailbox/mailbox.js), not chat, a keyboard API or a second approvals tool. A `permission` event carries the bounded descriptor (`kind:"approval"`, title, prompt, `at`, toolName, callId, reason, quotes, arguments + argumentsStatus, choices, approvalId, revisioned offerId). The plugin holds native correlation privately. Only the holder can see it via `approvals_list({sessionId})` and answer via `approval_answer({sessionId,approvalId,offerId,answer})`. Inbox acknowledgment is receipt, never a decision. The [live ledger](../../packages/dsh-connector/src/routing/offers.js) retires even acknowledged offers and does not restore authority from durable mail after restart.

- Reuse the connector’s [decision rules](../../packages/dsh-connector/src/domain/permissions.js#L60-L75), [risk values and limits](../../packages/dsh-connector/mcp-schema/constants.js) and [payload checks](../../packages/dsh-connector/src/mcp/tools/payload-rules.js). Risk values are **low / high**, not a UI severity score. Remote `allow` requires explicit `risk:"low"`, a nonblank reason (≤500 code points), and `argumentsStatus:"complete"`. Remote `reject` needs a nonblank bounded reason, not a risk. A high-risk, truncated or unavailable request is never remotely allowable; if local policy rejects incomplete arguments before offering, honor that. A refused answer does not execute anything or transfer ownership. Do not mark redacted, omitted or truncated security-relevant arguments complete; see the [argument projection](../../packages/dsh-connector/src/domain/call-log.js).
- The external decision set is intentionally narrower than native DSH. No `grant`, “always”, `ask`, auto-escalation or dual-responder `escalate`; do not route through the stock DSH waterfall unchanged. It checks standing grants and its [delegate registry](../../packages/dsh-connector/src/delegates/index.js) before the manager offer. [Watchdog](../../packages/dsh-connector-watchdog/src/core.js) can claim a native session with an active brief from the current manager: within scope allow once, dangerous and beyond purpose reject, otherwise pass; failed judgment is reported, not assent. External offers do **not** enlist Watchdog, delegates, standing grants or timers as decision owners. Keep native DSH behavior unchanged.
- **Watchdog parity is an admission gate, not an answer.** Before creating/reissuing a managed offer, the proposed connector broker must pass the bound request and only authorized context to a verified policy adapter. Resolve applicable supervision for this session and current manager; assess the active brief’s purpose, scope and drift. A pass or favorable assessment permits *one eligible offer* under the remaining rules, not a native response. Reject, drift or stop vetoes remote allow and enforces the applicable block/stop; do not represent it as a user or Fishball answer. If a required check cannot run or its judgment is unknown, disable remote decision delivery. Bind the assessment to the request, principal and policy revision; recheck at final dispatch. Neither takeback nor a replacement offer clears a policy veto. This adapter is proposed, not available proof of Watchdog coverage today.
- Serialize answers with transfer, abort and exit. Recheck holder, offer revision, epoch, process, request and policy at the final response boundary. Deliver at most one allow-once or deny through the certified transport; retire on stop, prompt replacement, exit or unload. Record actor + outcome only on confirmed native settlement. Distinguish a refused/stale answer from a denial and a delivered approval from successful tool execution. An uncertain delivery fences all further writes and requires reconciliation, not a retry. Other holder → `forbidden`; stale revision → `expired`; committed duplicate from the same holder → `already-settled` under the existing offer desk.

## 5. Automatic, CLI-local model catalogs

The only valid model key for an outside session is **(backend, opaque CLI model ID)**. Same label in two agents ≠ same model. Do not join, translate or fall back to DSH `models[]`, vendor marketing lists or a hand-maintained allowlist. Label “CLI default” separately from a model whose identity is confirmed. Keep requested, configured and actually routed model distinct.

**Refresh contract.** After user enables a trusted CLI/profile, automatically probe on first catalog request and on expiry (suggest 5-minute memory TTL), coalesce identical probes, bound time/output/pages and negative-cache failures briefly. Metadata-only probes may start a short-lived process but never a second writer on a user session, an auth flow, inference or a persistent setting change. Cache key = backend + executable identity/version + adapter schema + authorized profile/account-generation + workspace/policy context. No credential reads; if equivalent account scope cannot be proved, isolate per session/context, don't reuse. Invalidate on sign-in/profile/workspace/policy/version change, rejected model, disconnect or plugin unload. If caller supplies no workspace and catalogs vary, return `scope-required`, never their union. No prompt sent merely to prove access. Membership indicates selectable **now**, not guaranteed billing/quota at inference.

On start/switch revalidate against fresh exact-context catalog, resolve only a known exact ID, verify before any user message. Busy, stale generation, unknown version, partial list, timeout, auth challenge or parser drift → unavailable/stale, **no selectable stale IDs**, no free text. Cache revision can detect a selection race; existing choice and first message stay unchanged on failure. Live switch is a typed idle operation of the sole writer (never chat text); disable the selector or offer explicit new session if not certified. No switch via raw keys/tool text or fallback to another provider. Same rules for Fishball and user.

## 6. Fishball contract

One new **built-in** tool. The other changes are an additive discovery projection and generic dispatch, not a parallel suite. Proposed shapes below extend the [current tool definitions](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/mcp-schema/tools.js>).

- `models_list({folder?})`: with no registration preserve native response; `folder` optionally scopes *external discovery only* to an authorized workspace ID or permitted absolute directory. Never alter top-level native `models`/`defaultModel`. Project the positively discovered installed registrations (blocked entries get `canStart:false` and a safe inline reason); add `backends:[{backend,label,catalogState,revision,models:[{id,label}],canStart,canSwitchLive,blockedReason?}]`. `catalogState` = ready / stale / unavailable / scope-required; unless ready, return empty models, no selection. `canStart` for Fishball requires ready catalog **and** certified extraction/input/approval behavior; a backend being listed is not certification. Catalog errors do not break native discovery. Do not disclose account identifiers or filesystem paths.
- `external_session_start({backend,folder,title,message,attachments:[],model?,catalogRevision?})`: e.g. choose a row from `models_list({folder:"<workspace-id>"})`, pass its `backend` and exact `models[i].id` for the same folder. Require paired principal, nonempty bounded title/text, installed, supported and enabled backend by registered ID (not a connector enum) and fresh context. Omitted model uses CLI default only under a ready catalog and verified launch state. Reject attachments, reasoning effort, arbitrary flags/env/shell, extra properties, unknown or other-backend IDs. Prepare handle → confirm actual selection/identity → bind manager → deliver first message. Return `{ok:true,sessionId,managed:true,running,delivery?}`. Pre-send failure rolls back handle/lease. If delivery is uncertain, return stable discoverable ID, `delivery:"unconfirmed"`, freeze writes; list/read to reconcile, never automatically retry.
- `session_message({sessionId,message,attachments:[]})`, `session_redirect` (same args), `session_stop({sessionId,reason?})` and `session_release({sessionId,reason})` keep existing schemas. Redirect interrupts then rechecks ready state/ownership before sending; stop a turn, not a process; release control, not the conversation. `sessions_list({limit,workspaceId?})` and `session_read({sessionId,maxMessages,maxBytes})` use current manager only. Route only reserved IDs via registry; native IDs never leave connector. `approvals_list({sessionId})` and `approval_answer({sessionId,approvalId,offerId,answer})` reuse the current-holder desk and risk rules in §4 for the remote offer only. Never list a local-only offer or translate an unknown native wait into an offer, stock `prompt_answer` or actionable inbox event. No fabricated release event for the manager's own release.
- For certified live switching, the plugin can contribute `dsh-outside-agent.model_set({sessionId,model,catalogRevision})` via the [existing contributed-tool API](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/tools/README.md>), **not another connector built-in**. Use authenticated call principal and same connector lease check as send; serialize with pending turns/decisions. Return verified effective ID via contributed result data; mismatch or missing confirmation means unknown, freeze sends, don't claim success or automatically reverse. The UI calls the same plugin operation with the local-user writer lease.
- Use `{ok:false,code,message?}` with short safe reasons. `invalid-arguments` for wrong model/folder/inputs, `images-unsupported` for attachments, `unavailable` for missing capability/auth/catalog, `unsupported-operation` for unsupported live control, `conflict` for busy, changed revision or uncertain state; preserve size/capacity and permission/unknown-session refusals. No provider stderr, suggestions containing keys, or retries hidden from the caller.

## 7. Security, tests and rollout
- **Credentials stay with the CLI.** User installs and authenticates externally using the provider's normal flow. Never read, enumerate, copy, pass through from an unsanitized parent, store, ask for, type or log keys, OAuth tokens, auth files, keychains, cookies, device codes or passwords. No credential settings or terminal login automation. On auth/secret input: stop collection and writes, discard raw buffers, mark “sign in outside DSH,” then explicitly reopen/resume. If required auth is unavailable under confinement, report it; do not relax confinement or mount the user's whole home to make it work.
- Resolve executable from trusted install/explicit admin profile, not cwd, repository scripts or caller PATH. Canonicalize directory and validate policy at launch and before control changes; if policy changes invalidate writes until safely restarted. Never launch with approval bypass, automatic accept-all, permissive sandbox flags or user-controlled config overrides. Repository-controlled hooks/plugins are not trusted bridges. Do not grant the external agent independent access to connector management or PTY-control endpoints.
- Treat output and even text labelled “assistant” as untrusted data, not instructions for the wrapper. Suppress terminal side effects (OSC clipboard/title, links, DCS), escape UI content, cap frames, history, timeouts and concurrent handles. Avoid disk spooling of raw PTY data. Log operation names, IDs, safe state transitions and errors only; bounded redaction is defense in depth, not permission to capture credentials. Keep explicit end/delete and purge of local metadata distinct from vendor-owned history.
