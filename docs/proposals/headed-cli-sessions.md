# Outside agent: headed CLI conversations in DSH

**Decision:** ship `dsh-outside-agent` as a separate, explicitly installed DSH plugin, proposed repository `/Volumes/SSD1/GitHub/dsh-outside-agent`. Do not create it as part of this design review. An outside session has one live interactive CLI and one structured conversation. Opening it shows messages, status, a CLI-specific model selector and a composer in DSH—not a terminal. The local user can give Fishball control of that same session and take it back.

**Evidence convention.** “Verified” below means inspected source for DSH 0.2.2-rc.3 / connector staging, or the cited vendor documentation, not a successful live integration. All new interfaces, cache policies and version gates are proposals. None of the three CLIs was run; no provider settings, credentials or session stores were inspected.

Add a bounded catalog projection to `models_list` and an external-ID dispatch branch in existing managed-session/handover operations. These are glue to let the same Fishball read, message, stop, release and receive events, not a new session engine. **DSH loading.** Follow the [connector manifest](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/package.json>), [Cordis bundle patch](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/cordis.patch.yml>) and [isolated link fixture](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/tests/wire/worker.mjs>). Give the new repo its own package name, version, host entry/exports, `dsh.bundle.patch` inserting its host plugin, and `dsh.client` web entry/injections for the renderer, layout, sidebar and locale. In a disposable DSH profile install/enable the two packages **as siblings**: e.g. `"dsh-outside-agent":"link:/Volumes/SSD1/GitHub/dsh-outside-agent"` and the connector's actual manifest name linked to the connector **package directory** in its implementation worktree. Do not add either link to the other's dependencies, make a global Node link or edit the installed DSH. Exercise actual DSH bundle resolution, activation, UI registration and disposal. Release and enable separately; clean removal must leave regular DSH/Fishball working. No auto-install. Trusted host plugins share a process: this is an installation trust decision, not a sandbox between packages.

**Registry v1 (proposed semantic ABI, not present in staging).** Use the [unmerged registry](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/feat/external-sessions/packages/dsh-connector/host-services/sessions.d.ts>) at `22f6bea` as precedent, not the [prototype lifecycle](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/feat/external-sessions/packages/dsh-connector/src/external/index.js>). Port against staging (`61c4e35` inspected); do not merge it. `backends.register({apiVersion:1,id,label,catalog,prepare,lookup,read,act,leaseChanged}, caller) → registration/dispose`. Registry scopes IDs/callbacks to trusted registration; reject unsupported versions, duplicate IDs, oversized or malformed results. Connector allocates/recognizes a reserved routable ID namespace by backend; plugin mints unique IDs within it, never claims native IDs. `prepare` creates a session **without** a message. `lookup/read` expose bounded summaries/messages; `act` accepts typed send/interrupt etc., not arbitrary commands. Registration-scoped host sink reports turn settled, state changed or a real blocking offer; no raw output. Negotiate capabilities per version. Plugin can operate locally without connector; absence/incompatibility disables Fishball controls. If connector disappears revoke its writer/offer immediately. If plugin disappears abort dispatch, remove catalog entries and revoke leases; persisted mappings alone grant no access on reconnect.

**No two sources of truth.** Connector stores its normal manager→ID routing only. Plugin owns the view/store for all its rows; the authenticated handover/takeback operations resolve plugin IDs through the registry and publish lease changes. Before Fishball sees a read or event, connector checks the current principal and share boundary. Before a side effect, plugin serializes under a per-session fence, checks active registration, policy, generation and current connector-issued lease; revocation fences in-flight actions at the final write, not just tool entry. A disconnect is never implicit consent to replay work.

## 3. From a headed process to a readable conversation

Use a confined `ctx.subprocess.spawnTerminal` with verified host policy binding, canonical cwd, fixed executable/argv, real TUI terminal type and scrubbed environment. The [terminal controller](</Users/samuel/Library/Application Support/DSH/data/versions/0.2.2-rc.3/node_modules/@deepseek-ai/dsh-api-terminal-controller/src/index.ts>) opens a new shell owned by a DSH Agent, not an arbitrary external CLI or adoptable PTY. The [terminal handle](</Users/samuel/Library/Application Support/DSH/data/versions/0.2.2-rc.3/node_modules/@deepseek-ai/dsh-subprocess/src/types.ts>) exposes bytes, input, signal and process lifetime—not roles or turns. No shell wrapper/second chat process, ambient fallback, terminal panel or remote keyboard. PTY lives independently of windows; revalidate confinement on policy changes or stop writes and require safe restart.

**Projection pipeline.** Adapter binds `{outsideId,generation,cwd,providerSessionId,rootTurnId}` at launch → admits only same-root normalized events (`promptAccepted`, `assistantFinal`, `turnEnded`, `attention`, `modelChanged`) → deduplicates by provider record ID/cursor + generation → plugin assigns monotonic `seq`, bounded text and user/assistant role → UI snapshot + ordered deltas; Fishball gets the same filtered records since handover. Mark a pending composer submission separately until acknowledged. Partial text is optional and replaceable; a final record commits once. Keep tool traces, thinking, hooks, chrome, prompts for secrets and subagent messages out of the timeline. Backfill a gap from an authorized source only; otherwise show “history incomplete,” never concatenate screen redraws. A final text event and a safe-to-write composer are different facts.

|---|---|---|
| Codex (`codex`) | [Hooks](https://learn.chatgpt.com/codex/hooks) identify session, cwd/model and nullable transcript path; children may carry the parent ID; transcript format is not stable. [App Server](https://learn.chatgpt.com/codex/app-server) has thread/turn/item history. [Resume](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli) by `codex resume <ID>`. | Correlate top-level hook and record IDs; map accepted user message and final assistant text only, not tool items. If an owned headed client is proven attached to the *same* server/thread, prefer typed item/turn events; a second App Server or `exec --json` does not observe this TUI. Pins/fixtures required for any file decoder. |
| Claude Code (`claude`) | [CLI](https://code.claude.com/docs/en/cli-reference.md) supports `--session-id <UUID>` / `--resume <ID>`. [Hooks](https://code.claude.com/docs/en/hooks.md): `UserPromptSubmit`, `Stop.last_assistant_message`, `PermissionRequest`. [Sessions](https://code.claude.com/docs/en/sessions.md) describe transcript pointers; internal records can change. | Match confirmed UUID + cwd and top-level generation. Prefer incoming prompt plus acknowledged submission, root Stop for final; reject late/duplicate hook rounds. **File access is an exception, not discovery.** Prefer private launch-bound events. Enable transcript mode only with explicit local consent for the plugin-created session and a version-specific format. A path in a hook is untrusted: require trusted launch origin, pinned ID, authorized provider-owned root and exact file, regular file/no symlink traversal or replacement (verify opened handle), session/cwd match; bound record size, tail/cursor and time. Only extract allowlisted fields; discard raw data immediately. Never glob histories, choose “latest”, follow arbitrary paths, import old chats by default, or read auth/config stores. A missing file is pending, not an empty reply. On rotation/truncation/schema mismatch stop ingestion, preserve last verified seq, signal gap. If a safe reader cannot be built, that channel is not supported.

**Fallback:** unknown build, ambiguous ownership/role, unsafe input targeting, or no reliable extraction → retain verified messages, set “Conversation unavailable for this CLI version”, disable composer/handover/managed start and show cause plus End/explicit resume or update instructions. User can continue outside DSH only after exclusive ownership is safely released. Never show raw PTY, infer assistant replies from ANSI, silently launch headless mode or treat degraded sessions as a successful integration.

## 4. Ownership, approval and session lifetime

Persist `{externalId, backend, profileVersion, canonicalWorkspace, title, confirmedResumeId?, createdAt, lastStatus, nextSeq}`; retain manager identity in connector's existing routing store. Keep `{launchGeneration, ownedHandle, inputEpoch, outstandingTurn, promptRevision, boundedScreen}` in memory. Provider ID, external ID, DSH Agent ID and PTY handle are **not interchangeable**. Proposed default: redacted, byte- and count-bounded delivered turns in memory only, metadata durable, no PTY recording. `session_read` returns newest complete entries in order with `truncated` for eviction/gaps (including previous-process history); reconnection never invents history. UI shows what will be shared on handover; expose only redacted conversation from the consented boundary (default: current handover forward). No bulk import of provider transcripts.

| Event | Required behavior |
|---|---|
| User selects **New outside agent** | Choose supported backend and authorized folder; create unmanaged record, spawn once, show readiness or actionable failure. User is writer. Row selection later is attach-to-view only. |
| Fishball starts | Authenticate paired principal; validate capability, folder, quotas and arguments before allocating. Reserve ID, spawn, wait for verified normal composer, bind manager and admit first text under that ownership. Publish coherent row/result or roll back new record/ownership and reap process before first delivery. |
| Submit/finish | Serialized per session. At most one turn in flight. Normalize and bound text, reject control sequences and provider command/shortcut prefixes; use verified literal input mechanism (atomic paste plus adapter-controlled submit only if safe) to the normal composer, never replay unconfirmed input. Append the acknowledged user/principal turn once and final assistant turn once, with monotonic seq. Redraws and echoed input are not new turns. |
| Hand over | Authenticated local user selects paired Fishball principal by stable ID, not display name. Check manage-capable version; require verified idle, no partial user input or unresolved offer. Under lock cancel stale operations, set manager, increment input epoch and issue ordinary handover event. Preserve PTY, external ID and visible conversation. User becomes observer. Second window cannot acquire a second writer. |
| Take back / `session_release` / manager loss | Revoke manager and pending input **immediately**, retire offers, bump epoch and leave same PTY visible; recheck at the final write boundary. Already-running work may continue: show it, allow human interrupt, never replay a pending input. User can take back even when blocked/busy. Handle revocation during spawn/stop/offer; old callbacks cannot affect new epoch. |
| Disconnect, stop, close, exit | Closing/collapsing a view releases its subscription, not the CLI. Stop interrupts only the active turn using the adapter's verified interrupt, waits for acknowledgment; no close-as-stop. End Session explicitly terminates owned process tree and marks exited. Crash/unload/restart: invalidate handles/offers, settle active turn once as stopped, reap owned children, recover metadata as disconnected. Explicit resume only after exclusive ownership/no surviving writer is proven, by exact provider ID in same workspace; otherwise offer **new session**, never automatic resend/restart. |

**What Fishball observes:** internally model `starting → ready → running → ready`, with `waiting_user`/`waiting_approval`, `unknown`, `exited` and `disconnected` distinct. Route to existing `sessions_list` (`running` = active turn, not live process; `pendingInteraction` for waiting user/approval), `session_read` (seq/role/author/text, empty images), and ordinary `turn-finished` inbox events, respecting the connector's manager-stop suppression. Add optional external summary `{backend,state,inputMode}` to the closed schema if needed to distinguish idle from disconnected/unknown without abusing booleans. On ownership change, filter reads, streams and future events at dispatch, not just on subscription. Don't send a manager another principal's content.

**Evidence for state:** adapters must bind events to the top-level process, generation and turn: e.g. provider session-ready, submitted prompt, final assistant event and cancel/exit. Per-launch, private authenticated local event channel only if supported; validate origin, schema, role, size and ordering. Project files, process stdout and arbitrary hook invocations are untrusted; do not install global hooks or assume a hook name authenticates its sender. If authenticity/isolation cannot be demonstrated, do not use a hook for authority. A version-pinned VT parser can provide conservative display/attention hints, not an authoritative approval or proof of readiness based on model-printed text. `inputWaiting`, prompt glyphs and silence are insufficient. Fail to `unknown`, withdraw writes, and show a human recovery action. Gate managed capability on reliable same-process input targeting **and** turn boundaries; a manual-only adapter must never be advertised as Fishball-ready.

**Approvals:** distinguish CLI consent (native policy) from DSH launch/sandbox consent and ownership. Never lower any of them. Default: pause automation; user answers the native CLI permission choice via a narrowly scoped human-only action on the *current* verified prompt, or takes back. If no validated native prompt UI is available, interrupt safely or stop and request user attention; no guessed key. For a provider with an authenticated, blocking per-call approval callback, optionally translate it into a connector `permission` offer: complete tool, arguments and reason, session/generation/turn/call ID, one-time offer revision. Fishball uses `approvals_list` / `approval_answer`; check current manager, unexpired revision, unchanged request and local policy at settlement; return exactly one allow-once or deny through that callback. Do not run prototype standing grants/delegates for headed prompts by default. Never convert general chat, a screen regex, timeout, disconnect or a grant into “y”, “always allow”, or Enter. Revoke or deny on race; a genuine unknown prompt stays human-only. No answer on behalf of user for auth, trust-workspace, billing, OS prompts or secrets.

## 5. Automatic, CLI-local model catalogs

The only valid model key for an outside session is **(backend, opaque CLI model ID)**. Same label in two agents ≠ same model. Do not join, translate or fall back to DSH `models[]`, vendor marketing lists or a hand-maintained allowlist. Label “CLI default” separately from a model whose identity is confirmed. Keep requested, configured and actually routed model distinct.

**Refresh contract.** After user enables a trusted CLI/profile, automatically probe on first catalog request and on expiry (suggest 5-minute memory TTL), coalesce identical probes, bound time/output/pages and negative-cache failures briefly. Metadata-only probes may start a short-lived process but never a second writer on a user session, an auth flow, inference or a persistent setting change. Cache key = backend + executable identity/version + adapter schema + authorized profile/account-generation + workspace/policy context. No credential reads; if equivalent account scope cannot be proved, isolate per session/context, don't reuse. Invalidate on sign-in/profile/workspace/policy/version change, rejected model, disconnect or plugin unload. If caller supplies no workspace and catalogs vary, return `scope-required`, never their union. No prompt sent merely to prove access. Membership indicates selectable **now**, not guaranteed billing/quota at inference.

On start/switch revalidate against fresh exact-context catalog, resolve only a known exact ID, verify before any user message. Busy, stale generation, unknown version, partial list, timeout, auth challenge or parser drift → unavailable/stale, **no selectable stale IDs**, no free text. Cache revision can detect a selection race; existing choice and first message stay unchanged on failure. Live switch is a typed idle operation of the sole writer (never chat text); disable the selector or offer explicit new session if not certified. No switch via raw keys/tool text or fallback to another provider. Same rules for Fishball and user.

## 6. Fishball contract

One new **built-in** tool. The other changes are an additive discovery projection and generic dispatch, not a parallel suite. Proposed shapes below extend the [current tool definitions](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/mcp-schema/tools.js>).

- `models_list({folder?})`: with no registration preserve native response; `folder` optionally scopes *external discovery only* to an authorized workspace ID or permitted absolute directory. Never alter top-level native `models`/`defaultModel`. With registrations add `backends:[{backend,label,catalogState,revision,models:[{id,label}],canStart,canSwitchLive}]`. `catalogState` = ready / stale / unavailable / scope-required; unless ready, return empty models, no selection. `canStart` for Fishball requires ready catalog **and** certified extraction/input/approval behavior; a backend being listed is not certification. Catalog errors do not break native discovery. Do not disclose account identifiers or filesystem paths.
- `external_session_start({backend,folder,title,message,attachments:[],model?,catalogRevision?})`: e.g. choose a row from `models_list({folder:"<workspace-id>"})`, pass its `backend` and exact `models[i].id` for the same folder. Require paired principal, nonempty bounded title/text, supported enabled backend (`codex`, `claude-code`, `antigravity` in this plugin) and fresh context. Omitted model uses CLI default only under a ready catalog and verified launch state. Reject attachments, reasoning effort, arbitrary flags/env/shell, extra properties, unknown or other-backend IDs. Prepare handle → confirm actual selection/identity → bind manager → deliver first message. Return `{ok:true,sessionId,managed:true,running,delivery?}`. Pre-send failure rolls back handle/lease. If delivery is uncertain, return stable discoverable ID, `delivery:"unconfirmed"`, freeze writes; list/read to reconcile, never automatically retry.
- `session_message({sessionId,message,attachments:[]})`, `session_redirect` (same args), `session_stop({sessionId,reason?})` and `session_release({sessionId,reason})` keep existing schemas. Redirect interrupts then rechecks ready state/ownership before sending; stop a turn, not a process; release control, not the conversation. `sessions_list({limit,workspaceId?})` and `session_read({sessionId,maxMessages,maxBytes})` use current manager only. Route only reserved IDs via registry; native IDs never leave connector. `approvals_list({sessionId})` and `approval_answer({sessionId,approvalId,offerId,answer})` only for a verified offer, not a human-native wait. No fabricated release event for the manager's own release.
- For certified live switching, the plugin can contribute `dsh-outside-agent.model_set({sessionId,model,catalogRevision})` via the [existing contributed-tool API](</Volumes/SSD1/GitHub/dsh-connector/.agents/worktrees/design-headed-cli-sessions/packages/dsh-connector/tools/README.md>), **not another connector built-in**. Use authenticated call principal and same connector lease check as send; serialize with pending turns/decisions. Return verified effective ID via contributed result data; mismatch or missing confirmation means unknown, freeze sends, don't claim success or automatically reverse. The UI calls the same plugin operation with the local-user writer lease.
- Use `{ok:false,code,message?}` with short safe reasons. `invalid-arguments` for wrong model/folder/inputs, `images-unsupported` for attachments, `unavailable` for missing capability/auth/catalog, `unsupported-operation` for unsupported live control, `conflict` for busy, changed revision or uncertain state; preserve size/capacity and permission/unknown-session refusals. No provider stderr, suggestions containing keys, or retries hidden from the caller.

## 7. Security, tests and rollout
- **Credentials stay with the CLI.** User installs and authenticates externally using the provider's normal flow. Never read, enumerate, copy, pass through from an unsanitized parent, store, ask for, type or log keys, OAuth tokens, auth files, keychains, cookies, device codes or passwords. No credential settings or terminal login automation. On auth/secret input: stop collection and writes, discard raw buffers, mark “sign in outside DSH,” then explicitly reopen/resume. If required auth is unavailable under confinement, report it; do not relax confinement or mount the user's whole home to make it work.
- Resolve executable from trusted install/explicit admin profile, not cwd, repository scripts or caller PATH. Canonicalize directory and validate policy at launch and before control changes; if policy changes invalidate writes until safely restarted. Never launch with approval bypass, automatic accept-all, permissive sandbox flags or user-controlled config overrides. Repository-controlled hooks/plugins are not trusted bridges. Do not grant the external agent independent access to connector management or PTY-control endpoints.
- Treat output and even text labelled “assistant” as untrusted data, not instructions for the wrapper. Suppress terminal side effects (OSC clipboard/title, links, DCS), escape UI content, cap frames, history, timeouts and concurrent handles. Avoid disk spooling of raw PTY data. Log operation names, IDs, safe state transitions and errors only; bounded redaction is defense in depth, not permission to capture credentials. Keep explicit end/delete and purge of local metadata distinct from vendor-owned history.
