# Headed CLI sessions for DSH and Fishball

**Proposal, not a shipped feature.** Run one interactive CLI in one confined PTY. Selecting a row, refreshing DSH, handing the session to Fishball, and taking it back must all reach that **same conversation**, not spawn another agent. Fishball receives conversation messages and state, not a remote keyboard. A person can always see who has control.

**Scope assumptions to confirm:** “headed” means the actual interactive terminal application, not an SDK, background JSON invocation, or a separately automated desktop window. “Only the conversation” means one conversation view, without a shell console, tool logs, hidden reasoning or a duplicate DSH chat. Native permission questions need a human-visible way to answer. V1 lists only plugin-created sessions, not arbitrary processes on the machine. All prescriptions below are proposals; only the evidence sections describe observed behavior.

## 2. Package and process ownership

**Decision:** add an optional, independently installable DSH plugin package `packages/dsh-outside-agents` in the connector worktree, **not** a new repository or provider dependencies in connector core. A new repo would allow independent release but would split the first change to the session contract, fixtures and consumer across checkouts. Keep the interface versioned and provider-neutral so the plugin can move later. No changes to Fishball itself should be required if it discovers current tool schemas; verify with a Fishball-shaped client. Do not replace any Fishball session implementation.

| Owner | Responsibilities |
|---|---|
| Connector core (`packages/dsh-connector`) | Stable external ID, durable descriptor, workspace resolution, authenticated UI and MCP operations, manager/offer authority, normalized bounded read log, inbox events. Own one registry and **one** source of ownership truth. Preserve existing native sessions, delegates and optionality on older hosts. |
| New host plugin | Registers installed adapters; one supervised live handle per external ID. Resolves immutable launch profile, confinement and PTY; binds callbacks to this launch generation; translates native events and semantic inputs. No MCP listener or second manager database. |
| New plugin web client | The “outside agent” disclosure, rows and selected conversation panel. Subscribe through DSH peer-authenticated scoped snapshot/updates. Reuse connector handover/takeback routes and principal picker; no tokens in browser state. Unregister/fold cleanly when disabled. |

**Boundary change from prototype:** keep optional registry negotiation in `dshConnectorSessions`; advertise a headed capability version, do not reinterpret an SDK registration as headed. Define scoped host operations for local create/view/submit/end in addition to manager start/message/stop; both paths resolve the same record. Adapter descriptor includes backend ID, executable/version availability, managed-send, final-answer, approval mode and exact-resume capabilities. One adapter per ID; collision with old `claude-code` is a surfaced configuration error, never “last registered wins.” Separate disabling manager writes from destroying the conversation. Only the supervisor owns the OS handle; connector supplies a revocable lease per operation, not a raw handle.

**Transport choice:** use a plugin-owned `ctx.subprocess.spawnTerminal` with a real TUI terminal type and the CLI executable as argv[0]. If a shell is strictly required, use a fixed, non-login, no-rc launcher that immediately `exec`s the prevalidated argv: no shell left to receive messages on CLI exit. Obtain the *host-authorized* workspace/sandbox policy in the execution world, apply confinement **before spawn** (the primitive is not a sandbox), use its scrubbed environment, enforce terminal/session limits. If external IDs lack a legitimate policy owner, require a supported policy binding or disable launch. Do not invent a dummy Agent, borrow Fishball's terminal, launch unconfined, or patch the installed host. Client `ctx.webTerminals` is a window/tab service, not a process supervisor. Consider a native tab only if the host later offers the correct owner, safe view and revocable control. Never spawn a hidden second CLI just to get events.

**View:** the server consumes ordered output once; a versioned adapter uses same-process events (preferred) and, for presentation, a bounded VT screen model that handles alt-screen, cursor rewrites, resize and split UTF-8. Render escaped conversation text as text, not ANSI bytes/HTML. Strip status bars, tool output, echoes and secrets; use a plain status such as “Waiting for your approval” outside the transcript. No unsupported screen is exported as assistant text. When projection is unknown, show “Cannot read this CLI screen,” block sends, and offer a **user-only**, explicitly opened, transient native prompt view if safe. No general terminal pane, file tree or raw keystroke API. If a CLI cannot give a safe conversation or prompt view, mark that version unsupported. A terminal renderer by itself does not implement a conversation parser.

## 3. Session, turn and control contracts

Persist `{externalId, backend, profileVersion, canonicalWorkspace, title, confirmedResumeId?, createdAt, lastStatus, nextSeq}`; retain manager identity in connector's existing routing store. Keep `{launchGeneration, ownedHandle, inputEpoch, outstandingTurn, promptRevision, boundedScreen}` in memory. Provider ID, external ID, DSH Agent ID and PTY handle are **not interchangeable**. Proposed default: redacted, byte- and count-bounded delivered turns in memory only, metadata durable, no PTY recording. `session_read` returns newest complete entries in order with `truncated` for eviction/gaps (including previous-process history); reconnection never invents history. UI shows what will be shared on handover; expose only redacted conversation from the consented boundary (default: current handover forward). No bulk import of provider transcripts.

| Event | Required behavior |
|---|---|
| User selects **New outside agent** | Choose supported backend and authorized folder; create unmanaged record, spawn once, show readiness or actionable failure. User is writer. Row selection later is attach-to-view only. |
| Fishball starts | Authenticate paired principal; validate capability, folder, quotas and arguments before allocating. Reserve ID, spawn, wait for verified normal composer, bind manager and admit first text under that ownership. Publish coherent row/result or roll back new record/ownership and reap process before first delivery. |
| Submit/finish | Serialized per session. At most one turn in flight. Normalize and bound text, reject control sequences and provider command/shortcut prefixes; use verified literal input mechanism (atomic paste plus adapter-controlled submit only if safe) to the normal composer, never replay unconfirmed input. Append the acknowledged user/principal turn once and final assistant turn once, with monotonic seq. Redraws and echoed input are not new turns. |
| Hand over | Authenticated local user selects paired Fishball principal by stable ID, not display name. Check manage-capable version; require verified idle, no partial user input or unresolved offer. Under lock cancel stale operations, set manager, increment input epoch and issue ordinary handover event. Preserve PTY, external ID and visible conversation. User becomes observer. Second window cannot acquire a second writer. |
| Take back / `session_release` / manager loss | Revoke manager and pending input **immediately**, retire offers, bump epoch and leave same PTY visible; recheck at the final write boundary. Already-running work may continue: show it, allow human interrupt, never replay a pending input. User can take back even when blocked/busy. Handle revocation during spawn/stop/offer; old callbacks cannot affect new epoch. |
| Disconnect, stop, close, exit | Closing/collapsing a view releases its subscription, not the CLI. Stop interrupts only the active turn using the adapter's verified interrupt, waits for acknowledgment; no close-as-stop. End Session explicitly terminates owned process tree and marks exited. Crash/unload/restart: invalidate handles/offers, settle active turn once as stopped, reap owned children, recover metadata as disconnected. Explicit resume only after exclusive ownership/no surviving writer is proven, by exact provider ID in same workspace; otherwise offer **new session**, never automatic resend/restart. |

**What Fishball observes:** internally model `starting → ready → running → ready`, with `waiting_user`/`waiting_approval`, `unknown`, `exited` and `disconnected` distinct. Route to existing `sessions_list` (`running` = active turn, not live process; `pendingInteraction` for waiting user/approval), `session_read` (seq/role/author/text, empty images), and ordinary `turn-finished` inbox events, respecting the connector's manager-stop suppression. Add optional external summary `{backend,state,inputMode}` to the closed schema if needed to distinguish idle from disconnected/unknown without abusing booleans. On ownership change, filter reads, streams and future events at dispatch, not just on subscription. Don't send a manager another principal's content.

**Evidence for state:** adapters must bind events to the top-level process, generation and turn: e.g. provider session-ready, submitted prompt, final assistant event and cancel/exit. Per-launch, private authenticated local event channel only if supported; validate origin, schema, role, size and ordering. Project files, process stdout and arbitrary hook invocations are untrusted; do not install global hooks or assume a hook name authenticates its sender. If authenticity/isolation cannot be demonstrated, do not use a hook for authority. A version-pinned VT parser can provide conservative display/attention hints, not an authoritative approval or proof of readiness based on model-printed text. `inputWaiting`, prompt glyphs and silence are insufficient. Fail to `unknown`, withdraw writes, and show a human recovery action. Gate managed capability on reliable same-process input targeting **and** turn boundaries; a manual-only adapter must never be advertised as Fishball-ready.

**Approvals:** distinguish CLI consent (native policy) from DSH launch/sandbox consent and ownership. Never lower any of them. Default: pause automation; user answers the native CLI permission choice via a narrowly scoped human-only action on the *current* verified prompt, or takes back. If no validated native prompt UI is available, interrupt safely or stop and request user attention; no guessed key. For a provider with an authenticated, blocking per-call approval callback, optionally translate it into a connector `permission` offer: complete tool, arguments and reason, session/generation/turn/call ID, one-time offer revision. Fishball uses `approvals_list` / `approval_answer`; check current manager, unexpired revision, unchanged request and local policy at settlement; return exactly one allow-once or deny through that callback. Do not run prototype standing grants/delegates for headed prompts by default. Never convert general chat, a screen regex, timeout, disconnect or a grant into “y”, “always allow”, or Enter. Revoke or deny on race; a genuine unknown prompt stays human-only. No answer on behalf of user for auth, trust-workspace, billing, OS prompts or secrets.

## 4. Connector API for Fishball

**Add `external_session_start` as the discoverable connector tool for Fishball.** It requires `backend` and delegates to the same external start operation as `session_start({backend,…})`. Generate both input/output schemas from one definition (backend required on the named tool, optional on the ordinary tool); no per-CLI tools, second launcher or second permission lifecycle. In staging preserve `dshConnectorSessions.startInput`, `start({principalKey,args,afterManaged?})` and `stop({sessionId,reason?})`. Invoke `afterManaged` before first send; unlike a normal DSH start, a manager-initiated external start must not continue unmanaged. Leave the native path unchanged.

| Call | External contract (proposed unless noted) |
|---|---|
| `models_list({})` / `workspaces_list({})` | Preserve existing outputs; optional `backends:[{backend,label}]` lists only **manage-capable** registrations; UI discovery may also show manual-only/missing with reason. Workspace IDs, not display names. |
| `external_session_start({backend,folder,title,message,attachments:[],model?})` / `session_start` with identical external args | IDs: `codex`, `claude-code`, `antigravity`. Folder = registered workspace ID or existing absolute directory permitted by policy. Nonempty bounded title and text; optional validated provider-native model, otherwise CLI default. Reject attachments, unsupported models, reasoningEffort and extra properties; no binary/flags/env/command/terminalId. Omit backend for unmodified native DSH. Success `{ok:true,sessionId,managed:true,running}`, stable connector ID. Example: `session_start({backend:"codex",folder:"<workspace-id>",title:"Review docs",message:"Summarize the README.",attachments:[]})`. |
| `session_message({sessionId,message,attachments:[]})` / `session_redirect` (same args) | Current manager only; return normal `{ok:true,status,running}`. Redirect interrupts first, waits for verified safe composer, rechecks ownership before sending. If busy and not redirecting, refuse, don't queue blind input. |
| `session_read({sessionId,maxMessages,maxBytes})` / `sessions_list({limit,workspaceId?})` | Normal bounded read and managed-only list. Resolve external IDs as their own roots; include workspace association when known. No output from other terminals/sessions. |
| `session_stop({sessionId,reason?})` / `session_release({sessionId,reason})` | Normal `{ok:true,stopped:true}` or `{ok:true,sessionId,managed:false}` respectively. Release gives the same live session back to user, not an end-session or a new release event. |
| `approvals_list({sessionId})` / `approval_answer({sessionId,approvalId,offerId,answer})` | Only broker-backed one-shot offers can be answered by Fishball. Native human-only waits set pending status, show the user a scoped attention action and tell the manager that user intervention is required; do not fabricate an answerable offer. Use existing inbox poll/ack for offers, settlements and completion. |

**Failures:** use `{ok:false,code,message?}` and connector validation/auth precedence. `invalid-arguments` for invalid folder, flags, unsupported model/reasoning; `images-unsupported` for nonempty attachments; `too-large` / `limit-exceeded` for payload/capacity. `unavailable` for absent/unverified backend, preflight/auth or missing confinement; `unsupported-operation` for manual-only sends/unsupported controls; `conflict` for busy, stale epoch or waiting for user. Respect existing operation-specific `unknown-session`/`forbidden`/`not-managed` and stale-offer refusals. Use short redacted reason text, never provider stderr. Before first input, failure must not leave an orphan. If first delivery may already have occurred, retain and return the discoverable ID, add optional `delivery:"unconfirmed"` to external start success, freeze writes until reconciled. A lost MCP reply is not a reason to start again: list/read existing sessions and ask the user if ambiguous. For later uncertain sends use existing `status:"unconfirmed"`. No transparent retries.

## 5. Sidebar and handoff experience

Mount a single **outside agent** disclosure, initially collapsed, above Settings via `sidebar.footer.action`. In wide mode it expands *in place* to a bounded scrollable list; in rail mode use a labelled button opening an anchored accessible list. Activation of the heading toggles only; clicking a session opens the keyed conversation panel in `main`. Keep collapse/selection per window; do not auto-focus a tab on a Fishball tool call. New/unmanaged, managed by <principal>, running/idle, waiting for you, unavailable, disconnected and empty states must be distinguishable without color. Support keyboard navigation, `aria-expanded`, focus return and localized strings. Test narrow windows and long lists. If footer layout cannot fit, request a supported host section slot or user-approved placement; do not nest buttons in a panel icon, replace the workspace list or patch host DOM.

Row actions: **Open**, **Hand to Fishball…**, **Take back**, **End…** (user confirmation). Disable handover with a reason for missing pairing, ineligible build, non-idle or existing manager. Reuse the connector owner-only `/api/dsh-connector/ui/handover` / `takeback` authority path. Session selection must not disclose contents in the global sidebar snapshot: publish ID, title, backend, manager label, availability/attention only; load content for the authorized selected ID. Extend typed `UiSnapshot` without displacing staging's per-principal `windows` or native session marks. A user-started and a Fishball-started row are the same row type; only the initial writer differs.

## 7. Security and operations

- **Credentials stay with the CLI.** User installs and authenticates externally using the provider's normal flow. Never read, enumerate, copy, pass through from an unsanitized parent, store, ask for, type or log keys, OAuth tokens, auth files, keychains, cookies, device codes or passwords. No credential settings or terminal login automation. On auth/secret input: stop collection and writes, discard raw buffers, mark “sign in outside DSH,” then explicitly reopen/resume. If required auth is unavailable under confinement, report it; do not relax confinement or mount the user's whole home to make it work.
- Resolve executable from trusted install/explicit admin profile, not cwd, repository scripts or caller PATH. Canonicalize directory and validate policy at launch and before control changes; if policy changes invalidate writes until safely restarted. Never launch with approval bypass, automatic accept-all, permissive sandbox flags or user-controlled config overrides. Repository-controlled hooks/plugins are not trusted bridges. Do not grant the external agent independent access to connector management or PTY-control endpoints.
- Treat output and even text labelled “assistant” as untrusted data, not instructions for the wrapper. Suppress terminal side effects (OSC clipboard/title, links, DCS), escape UI content, cap frames, history, timeouts and concurrent handles. Avoid disk spooling of raw PTY data. Log operation names, IDs, safe state transitions and errors only; bounded redaction is defense in depth, not permission to capture credentials. Keep explicit end/delete and purge of local metadata distinct from vendor-owned history.

## 8. Delivery and acceptance gates

1. **Feasibility, no public capability yet.** Verify installed host services, policy binding and UI slot with a fake interactive fixture and disposable workspace. Confirm each provider identity with the user; run optional live checks only with explicit consent, preauthenticated CLI, no sensitive output recorded. Document each version and unknown. Stop at a missing policy or input boundary rather than shipping an insecure fallback.
2. **Single-provider pilot (opt-in).** Port registry/tool schema/routing on staging, a local unowned launch and a headed Claude slice. With a fake paired manager, demonstrate same session across local message → handover → Fishball read/send → native approval → takeback; separately start from Fishball. Ship only if management, denial and cleanup are proven. Keep default connector behavior unchanged with plugin absent.
3. **Codex and Antigravity independently.** Repeat that matrix with provider-specific fixtures and a manual smoke for each confirmed build. A registered name or manual-only launch does not satisfy the managed acceptance test. Report blocked capabilities rather than marking all three complete. Consider optional structured one-shot approval brokering after human-first flow works.
4. **Enable per backend**, behind user configuration. Roll back by revoking new admissions, notifying active users, retiring offers, draining/closing owned handles and removing registrations; retain metadata as disconnected. No automatic SDK fallback, credential migration or merge of legacy sessions.

**Test only affected packages.** Use the package-local `npm test` scripts; e.g. `npm --prefix "$DEV_WT/packages/dsh-connector" test` and `npm --prefix "$DEV_WT/packages/dsh-outside-agents" test` (new package must define a scoped suite). `DEV_WT` must be the new absolute implementation worktree. Only if embedded UI or Watchdog is affected run its own package script too. No root npm test, test:v3, workspace-recursive commands, or whole-repo builds/runs.

| Scope | Black-box cases and pass condition |
|---|---|
| Connector | Test schema/discovery with plugin absent/present/colliding; all three IDs; folder/model/attachment validation; failed management before first send; preserves staging afterManaged and native start/stop. Stale revision rejected, single settlement; bounded reads reflect delivery, not echo. |
| Plugin PTY and adapters | Synthetic interactive fixture counts launches, writes, signals and exits. | Sidebar client | Keyboard-expand, empty state, create/open both origins, local-vs-managed composer, select paired principal, take back with pending decision, refresh, two clients, status/error labels; assert normal workspace/Fishball rows remain and opening a view does not spawn or claim input. |

## 9. Decisions for the user before rollout

1. Does “headed” mean a conversation-only view backed by the live TUI, with the native prompt visible only for a human decision, or do you want the **unaltered CLI screen** including tool output and status? The latter changes the UI/privacy boundary.
2. Is Google **Antigravity CLI (agy)** the intended product? Which versions/OS of all three should be supported? Can we schedule a consented smoke with each already authenticated, and label unsupported versions rather than using headless fallback?
3. Is a dropdown above Settings acceptable, or must it sit inside the workspace scroll area (may need host support)? Is plugin-created-only discovery sufficient?
4. Do you want both the named `external_session_start` tool and the ordinary `session_start` backend argument (proposed), or just the latter? Is one optional connector-repo package acceptable for release?
5. At handover, should Fishball receive previous redacted turns or only new ones? Must normalized history survive restart? Defaults here are forward-only sharing, metadata-only persistence and explicit exact-ID resume.
6. Should native approval prompts always stay human-only, or may a verified structured callback offer **allow once / deny** to Fishball? Is takeover during active work allowed to leave it running (proposed), or should it interrupt?
