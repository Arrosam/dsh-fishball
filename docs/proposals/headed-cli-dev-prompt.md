7. Build one decision path for native CLI approvals. These are not DSH sandbox/launch approvals. A verified pending request has one offer, held either by the authenticated local user or by the Fishball that currently manages the session. Nobody decides by default. Management, a handoff, a low risk label, a model reply, a timeout and an old approval are not answers. The local holder gets Allow once / Deny; while Fishball holds the offer the local view shows its recipient and Take back, not decision buttons. Pause the ordinary composer until the native prompt resolves and normal input is verified again.

- Certification: require a private, authenticated, blocking, one-request response path to the *same* owned headed CLI. Bind outside ID, process generation, workspace, provider session, root turn, native call/request ID, full tool/arguments, reason, permitted one-shot choices and prompt revision. Verify the request is still blocked and unchanged before dispatch; distinguish provider acknowledgement from an attempted write. For Codex, test a request and its correlated response on that same server/thread/turn/item, not another app-server or a transcript. For Claude, prove a launch-scoped PermissionRequest blocks that call, carries complete inputs and accepts an allow-once or reject response for that call only; Stop/UserPromptSubmit and notification hooks are insufficient. For agy, conversationId/transcriptPath/modelName/fullyIdle prove neither a permission request nor a response channel. Require separate build-specific proof or mark approval control unsupported.
- Contract: for the remote holder only, publish the connector's permission inbox event and expose the same descriptor through approvals_list({sessionId}): kind:"approval", approvalId, offerId (<approvalId>.r<revision>), title, at, prompt, choices:["allow","reject"], toolName, callId, reason, quotes:[], bounded serialized arguments and argumentsStatus. Epoch/process/native callback bindings are private server state, not new MCP fields. approval_answer({sessionId,approvalId,offerId,answer}) is the only remote decision tool. Reuse connector holder, revision, payload/risk checks and first-commit semantics; fence registration, principal, epoch, native identity, policy and final dispatch together. Authenticate a local card against its local holder, binding and applicable policy; MCP manager risk attestation is not a local user field. Never impersonate Fishball. Record who answered and what happened without recording raw PTY bytes. Do not report execution or replay the answer when delivery is uncertain.
- Rule source: packages/dsh-connector/{mcp-schema/shapes.js,mcp-schema/constants.js,src/mcp/tools/offers.js,src/mcp/tools/payload-rules.js,src/domain/permissions.js}. Fishball allow requires risk:"low", nonblank reason (max 500 Unicode code points) and argumentsStatus:"complete". The only risks are low/high; missing risk → risk-required, high allow → allow-needs-low-risk, blank reason → reason-required, truncated/unavailable arguments cannot authorize allow. Reject needs a nonblank reason, not a risk. A refusal does not execute, transfer, or settle a still-valid offer. Honor stricter connector settings (including configured refusal of incomplete arguments), native policy and workspace restrictions; relabelling a call "low" cannot override them. Never use handoff to route around a refusal or silently give the session to the human.
- Only explicit one-call decisions for this external kind. Do not invoke the native standing-grant/delegate waterfall, publish a stock prompt via prompts_list/prompt_answer, or reuse native escalate's concurrent answerers. Do not admit grant, escalate or ask as external answers. Native Watchdog can decide a native managed call before its manager sees an offer. Preserve that behavior and its session_start-derived schema. External approvals require equivalent policy checks, not the native automatic settlement.
- Watchdog parity gate (proposed, not present today): before issuing or reissuing a remote offer, pass the verified request descriptor and only consented, bounded session context through a trusted connector-side policy adapter. Resolve the active unpaused brief for this external session and its current manager; evaluate the tool/arguments against its purpose, scope and drift/stop state. A pass (or favorable assessment) permits exactly one offer if all other rules pass; it never sends a native answer. A reject, drift or stop vetoes remote allow, including an answer already in flight. Bind the assessment to the request revision, manager epoch and brief/policy state; recheck at final dispatch. If a required check is unavailable, fails, lacks permitted context or is stale, withhold/retire the remote offer and explain the block without transferring control. Never invent a Watchdog approval, use a screenshot as a verdict, or bypass a veto by reissuing to the user. See packages/dsh-connector-watchdog/src/{core.js,tools.js}.
- Handoff normally needs verified idle and no partial input. Narrow exception: the native call is demonstrably quiescent, blocked solely on this one identified approval. Show the named recipient, session/CLI/workspace, bounded tool/arguments/reason and one-call scope in the confirmation: this request is the specific exception to forward-only sharing. Confirm transfers control, not consent to the call. Cancel leaves the live owner and revision untouched. Under the same per-session lock: retire the old offer and invalidate its input epoch, revalidate the very same native request and eligibility under the new lease, then issue a fresh revision to the new eligible holder. A confirmed Take back does the symmetric operation; the reissued local offer is not the old card and does not decide the call. No overlapping writers, forwarded old token, or replay. Preserve session ID and PTY. Takeback may revoke write authority even when busy; never issue new write controls on that fact alone.
- Unknown detection, ambiguous transport, changed request, lost acknowledgement or failed revalidation: withdraw stale authority; local-human attention ONLY, no remote offer or DSH answer buttons. Show what stopped and how to recover without a second writer. Never synthesize blind keys, open a raw terminal, automate billing/trust/auth, or treat silence as a decision. An ineligible answer is a policy refusal, not an invitation to take over: retain management unless explicitly changed, never bypass native policy, and do not convert a forbidden action into an interactive Allow. Stop collection for authentication; sign in outside DSH. No arbitrary argv/env, shell fallback, credentials, raw prompt/output logs or persistent user-config edits.
