# Fishball manager tool inventory: what can actually be triggered?

**Design review, not a runtime change.** Baseline: Fishball staging `b9a2ddb69deee795562df216c3f5b58cb6f7a0bc`. For target-side behavior, the independently inspected [connector staging schema](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector/mcp-schema/tools.js#L43-L119) is an example compatible offer, **not** proof of what a paired DSH offers. External packages below were inspected as source, not enabled, called or installed for this review.

**Decision rule.** **A** — host can perform the named operation, or explicitly identified equivalent service read, without a model decision in the stated scenario. **B** — host can supply a timely cue, checklist or prefilled call; the model must confirm relevance, inputs and execution (and ask the user when needed). **C** — model initiates; the host must not initiate that operation. A generic reminder to review an approval does not make its answer B. Labels apply to the specified use, not every possible invocation. **Current** paths below tell who calls what today; the tables give **proposed** trigger points, not claims that those hooks already call these tools. See the [event-to-action flow](fishball-trigger-flow.md) for batching and replay.

**Discovery and trust.** Start with the [four allowed preset tools and core exemptions](../../packages/core/contracts/constants.js#L514-L530), then add [manager-scoped setups](../../packages/core/src/main/index.js#L158-L168) and the live target offer. X2 setup follows the current manager generation on create/resume; disposed generations have no authority. For a target operation, retain trusted source/epoch, session and live offer ID, never just a display name; never select a different target if it vanishes. The [facade checks](../../packages/core/src/bridge/index.js#L194-L230) enforce connectivity/list membership, X19 send gates for message/redirect and image capability for model image reads. A host path cannot bypass these checks by invoking a raw link or omitting model capability. Revalidate at dispatch, deduplicate against current state and already delivered events; a possibly sent write is not safe to retry. Event payloads, stored text and remote descriptions are data, not authority. Keep reads bounded and re-fetch before writes; prefer in-process state over synthetic model tool calls.

## 1. Local manager: DSH preset and Fishball core

The [preset](../../packages/core/cordis.patch.yml#L104-L138) mounts DSH filesystem read/image and inline ask, not a worker preset. The [role and permission policy](../../packages/core/src/persona.js#L75-L121) applies to **all** rows: no general file writes, browser workarounds or escalation of Fishball's own sandbox. Restricted, facility-owned updates are not a generic file API. No new session is created by a local Fishball reminder.

| Tool | Class | Current caller/documentation → proposed decision |
|---|---|---|
| `read`, `read_image` | C | Manager via DSH preset/tool descriptions: selects a relevant permitted file/image. No automated crawling, ingest or copying. |
| `working_directory` | C | Manager via preset guard/DSH tool description: inspect or select its own cwd. Never infer a chdir from a worker's path, or confuse Fishball cwd with remote session placement. |
| `ask_user_question` | B | Manager via DSH inline question card. On a placement/target lookup with more than one eligible match, cue a clarification using only verified choices. No guessed answer, default destination, duplicate open card or substitution for a worker question. |
| `message_user` | B | Manager → [local chat tool](../../packages/core/src/manager/message-user.js); ordinary assistant output is hidden. On a user turn, setup greeting, awaited result, or actionable event batch, cue **one** local reply; model composes the useful answer. No automatic forwarding of worker text. Routine activity needs none. Awaited completion alone is **not** an embed notice in this proposal (a change to [staging wording](../../packages/core/src/persona.js#L79-L84)). |
| `schedule_create` | B | Manager → [local timer/store and definitions](../../packages/core/src/manager/reminders.js#L192-L211). When the user requests a reminder, cue timing, timezone, prompt and title; resolve ambiguities and check for duplicates. One supported timing form; delivery occurs in this session. The **already authorized due delivery** is A in the existing timer, not another create call. After downtime only the latest missed recurring occurrence is delivered; a crash can duplicate delivery. |
| `schedule_list` | A | Same manager/store. At the start of an explicitly requested reminder edit/removal, read this session's reminders to resolve fresh IDs; surface only matching candidates, never silently pick among ties. |
| `schedule_update`, `schedule_delete` | B | Same manager/store. On an explicit change/cancel request, prefill verified ID after list; model confirms exact change. Update retains omitted fields; deleting does not retract a queued delivery. Neither a due event nor crash replay authorizes mutation. |
| `private_skill_list` | A | Manager → [private registry/tools](../../packages/core/src/manager/skills.js#L183-L205). On setup/resume, use the manager-scoped catalog/projection if needed; do not reload every body. Incomplete discovery is not authoritative absence. |
| `private_skill_read` | B | Same registry. If the current work matches a named catalog entry, suggest its exact name; model decides whether to load and which lesson, if any, to paraphrase to a worker. A worker cannot load the private skill by name. |
| `private_skill_create`, `private_skill_update` | B | Same tools. At an explicit “keep/change this way of working” request, cue create vs replace after catalog check; model verifies durable scope and the complete document. No accumulating private chat excerpts by default. Staging also lets the model judge patterns itself. |
| `private_skill_remove` | C | Same tools: manager selects the exact private name to remove; neither age nor lack of use implies consent. |
| `private_skill_reload` | A | Same tools: on a committed-but-unconfirmed refresh failure, invalidate and reread the catalog once for this generation. Report unresolved/incomplete status, never replay the underlying mutation. |
| `ask_user` (per target) | B | Manager → [core card handler](../../packages/core/src/asks/index.js), mounted **locally under the requesting target's facade**. If a live permission request should be answered here, suggest filing that target/request with a reason; never file a question/plan card. The actual human Allow once/Reject submits to the source target; no subsequent manager answer, no claim of settlement before confirmation. This is distinct from the DSH inline question above. |

The six skill tools require a usable scoped skills provider, not just the presence of core ([attachment and caller checks](../../packages/core/src/manager/skills.js)). The single confined exception concerns Fishball's own skill documents; it does not authorize worker files or cross-project memory writes.

## 2. Bundled facilities: editable taskboard, heartbeat and separate board

The [amenities umbrella patch](../../packages/fishball-amenities/cordis.patch.yml) contributes component rows, not an extra model tool. Each may also be installed separately. Taskboard's **current** caller is the manager via [four registered definitions](../../packages/fishball-taskboard/src/tools.js#L45-L70) and [manager setup](../../packages/fishball-taskboard/index.js); its [guide](../../packages/fishball-taskboard/src/guide.js#L9-L23) and [component contract](../plugins/fishball-taskboard.md) describe when to maintain it. The user also edits it via UI routes (not model tool calls).

| Tool | Class | Proposed mechanism, scenario and limit |
|---|---|---|
| `taskboard_read` | A/B | A: after successful manager compaction with unfinished tasks or a committed changing user edit, project the current count/revision. B: cue a full read only when the next real request needs the board. Current [compaction watcher](../../packages/fishball-taskboard/src/reminder.js#L23-L39) injects **a cue to call**, with no wake; do not add a second wake or repeat a full board on every turn. A read projection must not imply the full board is empty. |
| `taskboard_add` | B | On a new user task, cue adding it now (or decomposing it); manager distinguishes assignment from discussion, checks live duplicates and selects parent. Never open tasks automatically for every chat message. |
| `taskboard_update` | B | At reported progress, turn-finished or user correction, show candidate task IDs and current data; confirm match, status and evidence. Tasks are not session-bound. A finished/interrupted turn is not a finished task. Future A would require an explicit task binding, authoritative structured outcome, fresh revision and dedup; never overwrite an intervening user edit. |
| `taskboard_memo` | B | At an explicit request to keep/edit a board memo, cue the appropriate memo or new-entry form. Manager confirms text and identity; deleting requires a deliberate choice. No transcript siphoning. |
| `heartbeat_focus` | B | Manager via [heartbeat setup](../../packages/fishball-heartbeat/index.js) and [timer](../../packages/fishball-heartbeat/src/heartbeat.js). When the user changes what to check during idle turns, cue complete replacement focus (empty clears). Only when both interval and consecutive limit are configured; never derive/change those settings from focus. The idle wake and cooling/optional compaction are already host work, **not** instructions to call this tool each tick. |
| `board_read` | A* | Compatible board only: project bounded current open state at resume/context loss, refresh on demand before a write. Manager normally calls the [guarded board tools](../../packages/fishball-board/src/board.js#L312-L335); do not construct a complete write from a truncated read. |
| `board_write` | B* | Compatible board only: on relevant status change, cue read/transition/validate against the **whole** open set; model owns transition, links and any clear. Serialize, check freshness; an interrupted archive+board write can have partial effects. Do not mirror taskboard writes. |
| `board_search` | B* | Compatible board only: when past/cleared work is requested, suggest bounded literal title/note search. [Search tool + guide](../../packages/fishball-board/src/search.js#L5-L18) return historical snapshots (newest matching, not necessarily current); never restore a card from a hit automatically. |

* **No board triggers on this staging core.** [Board setup](../../packages/fishball-board/index.js#L17-L40) requires API 1, the [shared follower](../../packages/shared/instance-follower.js) checks equality, and [core](../../packages/core/src/main/constants.js) publishes API 2. Fix/test compatibility and target-safe link semantics first. Archiving is internal, not a fourth board tool. Taskboard, card board, memory and a worker's task list are different stores.

## 3. Per-target connector manager tools

**Current call path for each row:** manager → [target-specific name](../../packages/core/src/targets/names.js) → [bridge registry and call](../../packages/core/src/bridge/index.js#L194-L249) → connector [MCP dispatch](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector/src/mcp/tools/dispatch.js). The connector [tool schema with descriptions, required parameters and refusals](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector/mcp-schema/tools.js#L43-L119) documents every base name in this section; these match Fishball's [contract table](../../packages/core/contracts/constants.js#L280-L304). The base names in the tables are **not** unqualified model call names: select the current target-specific function from the registry. Dots in contributed names become double underscores before target qualification. Handles may change across rename/reconnect. Stable labels, not a copy of the current function list, belong in the persona.

| Base name | Class | Proposed mechanism, scenario and limit |
|---|---|---|
| `sessions_list` | A | Reconcile owned sessions on connection/handover or before resolving an explicitly requested worker. Current [target session cache](../../packages/core/src/targets/sessions.js) already consumes this read. Retain source; absence during disconnect is not release, and a title is not ownership. |
| `workspaces_list` | A | On a start request specifying workspace placement, fetch this target's registered IDs, paths and existence. No fallback folder: ask if ambiguous/refused. |
| `models_list` | A | When a start request specifies a model/effort, fetch the target's current choices; validate exact string and effort. Do not silently substitute another model or send a start. |
| `session_start` | B | On an authorized delegation with no suitable existing worker, prefill destination, verified placement/model and scoped first instruction. Model confirms content/attachments; check for an existing or partially started session before any retry. On workspaceError report the existing session ID; no replacement start. See Watchdog below. |
| `session_message` | B | On a blocked/partial worker result with a concrete next step, cue a follow-up for this managed session; model confirms the instruction is useful and authorized. No idle polling or duplicate send; retain X19 and reconcile uncertain delivery. |
| `session_redirect` | B | On an explicit change of course needing interruption, offer redirect vs ordinary steer; confirm cancellation of current turn/subagents/jobs and replacement text, respect X19, then report. A drift signal alone does not authorize redirect. |
| `session_stop` | B | On an explicit stop request for an unambiguous managed worker, prefill target/session and stop impact; model confirms, checks result and reports. A completed turn, timeout or silence is not a stop request. |
| `session_read` | A | If a source-bound turn-finished payload is **truncated** and the continuation decision actually needs missing context, fetch one bounded tail from that session. No whole transcripts, other targets or routine reread of an adequate finalMessage ([current behavior](../../packages/core/src/persona.js#L99-L105)). Non-mechanical relevance judgments remain model-led. |
| `session_release` | B | When the user asks for handback or the actual delegated work appears complete, cue verification of ownership, pending requests/work and reason; model confirms release. A worker turn ending is not release authority. |
| `approvals_list` | A | On a pending request/reconnect or before a human card action, refresh offers **only for its source/session** and reconcile by exact ID. [Core asks](../../packages/core/src/asks/index.js) already uses this read for reconciliation. Listing grants no approval. |
| `approval_answer` | C | Manager must decide allow once, standing grant, reject or escalate under the [permission rules](../../packages/core/src/persona.js#L107-L116). Host may present live IDs and exact call facts; never infer approval from history, a worker, or “read-only” wording. A deliberate human click in Fishball's card also reaches this endpoint; it executes that user's decision, not an automatic manager answer. |
| `question_answer` | C | Manager must determine whether the user's words cover the answer; otherwise send to the user in the worker's session. First answer wins; refresh stale offers. No hook answers a question or approves a plan. |
| `prompts_list` | B | Cue a read only on user request or a concrete worker message giving reason; manager confirms scope. These already-visible user prompts are not normally sent to Fishball; do not poll all worker prompts. |
| `prompt_answer` | C | Manager/human chooses allow/reject and reason for the exact live prompt under the same low-risk/allowance rules; not a generic response to a wake. |
| `grants_list` | A | After an explicit narrowing/withdrawal of a standing allowance, read this principal's current grants and show relevant candidates, scoped to the source. List results do not authorize revoke or future approvals. |
| `grant_revoke` | B | On that user change, cue the matching current grant and reason. Model verifies exact scope/identity before revocation; no inference from silence or from an already expired grant. |
| `attachment_put` | C | Uploads file/image chunks and yields a single-use hostRef. Only deliberate authorized content/destination; no host harvesting, unsolicited uploads or reuse of a ref in another session/target. |
| `attachment_read` | B | If a relevant event references an image needed to answer and the model supports images, offer the bounded source-bound read; let the manager decide. Preserve the existing [image projection](../../packages/core/src/bridge/index.js#L251-L270); no dumping raw base64 or coercing a text-only model. |

**Host-only connector operations** — all four [withheld from the manager](../../packages/core/src/bridge/constants.js#L48-L63), not model prompt instructions:

| Operation | Class | Current caller, trigger and boundary |
|---|---|---|
| `inbox_poll` | A | [Link loop](../../packages/core/src/link/link.js): read pending pages for the paired principal as part of the connected listener/reconciliation. Reading is not acknowledgement; bind cursor to link. |
| `inbox_ack` | A | [Target acknowledgement router](../../packages/core/src/targets/index.js) after durable intake; send exact source-bound receipts and digests, not “seen by model” guesses. A replay must not produce a second side effect. |
| `pair` | A | [Identity pairing](../../packages/core/src/identity/pairing.js) once in an owner-authorized connection flow; not permission to create credentials or pair unknown servers. |
| `set_name` | A | [Identity rename path](../../packages/core/src/identity/pairing.js) propagates owner-selected display identity, handling conflicts. Never derive identity from an event body. |

### Conditional target contributions

**Embed UI:** [three definitions and handlers](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector/src/ui/tools.js#L25-L68), contributed only while that target's UI contributor is registered. Staging Fishball explicitly mentions notify and exposes an extension attention path; mere listing of a notice tool does not require a notice.

| Wire name (before facade mapping) | Class | Proposed mechanism, scenario and limit |
|---|---|---|
| `embed-ui.notify` | A/B | **A only** after a concrete still-open human action, destination and safe fixed message are mechanically known (e.g. a verified pending human card for this source). Otherwise **B**, cue relevance/text/destination or abstain. At most one notice per actionable batch. Notify is non-idempotent and takes plain text (1–4000 code points); important only if action is needed. No follow-up notice for an awaited completion already reported in local chat. Never notify another DSH because the intended one lacks the tool. |
| `embed-ui.attention.signal` | B | This raises an attention latch rather than delivering a message. At a verified outstanding human action with an agreed attention-only UI policy, cue that route **instead of**, not alongside, notify. No routine turn-finished or duplicate alert. |
| `embed-ui.attention.state` | A | Before raising a justified latch on this target, inspect its current latch state to suppress a redundant raise. A latch is not the same as a delivery receipt, a user answer, or evidence a particular card is still open. |

**Watchdog:** same manager → contributed facade path. Wire namespace `dsh-connector-watchdog`; the table shows **local** tool names. [Registration and capability checks](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector-watchdog/index.js#L42-L82) require a configured model and compatible services; supervised start also needs the plugin-start capability. [Definitions](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector-watchdog/src/tools.js) / [semantics](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector-watchdog/src/constants.js#L80-L94) are target-owned, not five unconditional core tools.

| Local name | Class | Proposed mechanism, scenario and limit |
|---|---|---|
| `watchdog_session_start` | B | For authorized work **intended to be supervised**, prefill a scoped start rather than plain start then brief. Model checks exact purpose/approvable scope, placement and the result's managed/supervised status. Do not broaden permissions or start twice on partial success. |
| `watchdog_brief` | B | For an already running managed session whose supervision is requested, cue a brief from verified purpose/scope. Earlier requests are **not** covered retroactively. Watchdog's own explicitly scoped delegate is different from Fishball auto-answering approvals. |
| `watchdog_refine` | B | On an explicit change to a supervised task's purpose or allowance, cue a diff against the current brief; model confirms exact changed scope. A worker request cannot expand its own authority. |
| `watchdog_pause` | B | On a request to suspend supervision, cue its effect: stops the current turn as well as pausing patrol/permission answers. Confirm actual session and effect first. |
| `watchdog_resume` | B | On a request to restart supervision, cue exact paused session and recheck current scope. Resuming oversight is not authority to restart the worker's task. |

**Other lanes, not Fishball model tools.** The managed **worker** calls [`message_agent`](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector/src/domain/session-tools.js#L48-L67) (C, worker decides what to report). The generic DSH adapter's [`dsh_connector_sign_in`](https://github.com/Arrosam/dsh-connector/blob/83e26c9173595a2e66b77ee2429743449cd17e55/packages/dsh-connector-adapter/src/sign-in-tool.js) is for an adapter client (C, owner/user-directed); it is not the Fishball manager pairing path. Neither gets a Fishball trigger. Future X2 contributors, per-target MCP tools and owner-modified presets are open sets: inventory the **live** scope and declaration, not every tool in a developer's DSH; default unfamiliar tools to C/no automatic dispatch until owner, schema, effect and authority are reviewed. Diagnostics about extra tools do not make them sanctioned automation.

## 4. External, optional: verified memory and compaction tools

The [recommendations list](../../packages/core/ui/src/recommended.js#L47-L59) is a catalog, not an install or an activation record. Inspected the source artifact of [meow-memory 0.33.1](https://www.npmjs.com/package/meow-memory/v/0.33.1) under the managed profile's node_modules (a separate plugin cache has 0.32.4). Exact reproducible evidence **inside the 0.33.1 package**: `lib/index.js:3206–3214` registers seven tools; `3477–3500, 5037–5055` define/register dream separately. Current caller for the eight named tools is the model via the external plugin's `ctx.tools.register`; not core X2. `lib/prompts/en/tools.md` is the per-tool contract, with `README.en.md` for configuration. Package presence is **not** evidence the current manager has the tools or permission to invoke them. Check the live registry and owner-approved policy, trusted workspace, disabled/read/write/privacy settings and destination for each use. Without them, omit cues. Memory content is not standing authority; never store secrets, permission tokens or raw conversations as a side effect of a turn.

| Tool | Class | Proposed mechanism, scenario and limit |
|---|---|---|
| `memory_search` | B | On a request recalling a prior decision, suggest a short query tied to this workspace/project. Confirm relevance and cap matches; no cross-project/global search by default. |
| `memory_find_similar` | B | When considering an authorized new or changed entry and a candidate ID exists, cue a bounded duplicate/conflict check. Similarity is not proof of identity or permission to merge. |
| `memory_read` | B | After retrieval identifies a relevant entry, cue its exact ID if the snippet is insufficient. Model confirms before receiving full content; do not forward it to a worker or consultant by default. |
| `memory_project` | B | On a request for a particular project's decisions/context, cue exact verified project name. Returns a full active project block; use narrow search instead where possible. Never inject an unrelated project's block on every wake. |
| `memory_remember` | B | Only in an explicitly authorized managed memory facility: when the user asks to retain an appropriate durable fact/preference, cue scoped entry + keywords after duplicate/privacy check. Model verifies what, where and why; no heartbeat/compaction/worker-finished auto-write. If the store is outside permitted scope, do not write. |
| `memory_update` | B | On a user correction to an explicitly identified remembered fact, cue re-read of the current entry then a proposed change. Verify ID, provenance and trust; do not silently mark old decisions stale or replace user text. Same write boundary as remember. |
| `memory_home` | C | No-arg inspection differs from switching the instance-wide data directory, which **moves files**. No trigger; never invoke the mutating mode as a Fishball file-policy exception. Route a requested storage migration to the owner/appropriate worker. |
| `memory_dream` | C | Deliberately scheduling consolidation can run additional model work and reorganize durable content. No Fishball idle/compaction trigger, duplicate dream scheduler, or hidden promotion of chat to memory. |

**Do not reinvent the plugin.** In 0.33.1, `lib/index.js:5057–5081` (`tryRegisterGuideSection`) registers `meow-memory:guide` at order 130 if the prompt service appears; failure does not remove the tools. `lib/prompts/en/system-guide.md` is one locale, not necessarily the active one. `session/event` (5085ff.) arms reinjection after successful compaction; `agent/pre-step` (5171ff.) conditions first-user-message, keyword and subsequent/reinjection context on workspace/session/config; `agent/turn-stopping` (5315ff.) and other plugin hooks govern reflection/dream behavior. These are **plugin-owned projections/workflows**, not evidence the model called a named memory tool or Fishball should automatically call one. If plugin auto-writes cannot meet the configured Fishball boundary, do not treat the package as an enabled read-only facility.

**Another installed optional surface:** [smart-compaction 0.3.15](https://www.npmjs.com/package/smart-compaction/v/0.3.15), `index.js:107–155,187ff.`. If offered, **A** `context_status`: at an authorized budget check, read the current session's measured token use rather than guessing (prefer the host meter). **B** `compact_now`: cue a safe point only if context pressure and current state justify it; model confirms, avoid active/duplicate compaction. The plugin has its own optional safe-point hooks. Neither tool is required by the preset's heartbeat cooling compactor; never add a second timer. Other recommended memory (e.g. `@a9i5k4/dsh-auto-memory` and `@zilliz/memsearch-dsh`), context or channel packages have no guaranteed tool names here. An installed external channel in particular would not make it acceptable to publish user content automatically.

**Provider tools are a separate conditional surface.** The managed profile contains [dsh-plugin-subscriptions 0.9.13](https://www.npmjs.com/package/dsh-plugin-subscriptions/v/0.9.13). Its `lib/index.js:17406–17420` registers model-callable `x_search` and `video_generate` when the Grok token service exists, `image_generate` with either Codex or Grok. `lib/index.js:11629–11649` falls back on registration collision to `dsh_subscriptions_x_search`, `dsh_subscriptions_video_generate` or `dsh_subscriptions_image_generate`. **C for each**: no Fishball trigger, even if offered. A search sends the query externally; production of files belongs in a worker. The Codex web search provider is a separate service attachment, not an extra Fishball core tool.

**Coverage check for future reviews.** Compare the four preset names, twelve core-owned names (including target-local ask), and eight facility names **by their actual registration tables** rather than a global prompt dump; then compare each connected target's advertised names against the 22 core protocol operations (18 model-facing, four host-only), enumerate every named contributor and check optional packages against the exact installed version. Recheck on generation/target/plugin changes; an absent, withdrawn or different-version tool means skip or ask, not emulate through another tool.
