# 实施前的验收清单

这是后续实现应通过的检查，不是已运行的功能测试。与[字段和事务边界](board-contract.md)及[宿主前提](host-contract.md)一并使用。

| 操作或故障注入 | 应观察到什么 |
|---|---|
| 用一个有任务、子孙和 memo 的旧板启动；不选模型，先手工编辑 | 无额外调用。旧板值、顺序、时间戳和 revision 除正常用户修改外均不变；新存储中的旧板投影和旁附审计都不会被整板保存抹掉。坏板不当空板。 |
| 开启前、换供应商前，检查设置页 | 先展示实际路由与数据类别，包括整树中的已关闭和不相关项。目录中的本机配置并非本地推理保证；模型失效不回退。设置/审计读写限当前 owner，弱模型无工具。 |
| 本轮无正文但上轮有；收到另一个用途的回合；输出截断、超限或停止 | 0 次推理，0 次写任务，0 条本功能通知；普通会话原有投递不变。长期运行后台 job 不单独成为跳过理由。 |
| 配置 A→B→A 或关→开；同一 endpoint 取回后再管理 | 即使设置值相同，也不可复活旧结果。要求本地配置单调世代、可信管理分配世代、可信本轮顺序标识；在发请求前及串行提交时双检。当宿主不能提供或证明这些事实时暂停自动入口。 |
| 同一会话新回合比旧模型结果早到；新回合因繁忙而被跳过 | 先持久登记该分配下最新可信轮次，再判断是否忙。老回合不得误提交，新回合不补跑；跨目标分别跟踪，不能比较随机 eventId 或按到达时间猜顺序。 |
| 供应商已收请求而本地未记结果，或同一回执两次到达 | **请求前**在同一队列认领本次尝试和一个额度。重启时不回放未定请求；失败/无匹配也不能重新算一次。若在认领后、发出前中断，宁可保守占一个配额。额度记录不产生 board revision、编辑冲突或用户提醒。 |
| 整板 20→21 项；第七次调用；输入太长；供应商拒绝；返回含未知字段 | 超预算在发出前跳过；其余一律不提交、不换模型、不自动重试。历史仅保留原因/计数，不回显密钥或完整提示。 |
| 自报完成，或真的改了两行并同时自报完成 | 前者仅新增持久复核记录，后者两行一次提交、一个通知，均不自动结案。普通 manager 无参数读取即在同一快照发现可选 autoReviews；旧维护指引不能以“会话结束”代替验收。复核读取后有人又改了该项，旧 decision/version 不得提交。 |
| 人先改、机器先改、撤销和复核竞争 | 任一整板冲突全批放弃；编辑器保留草稿。撤销只还原批内字段，同批未决复核作废；已有人处理则拒绝。无保留记录不能撤销。 |
| 板已提交，发通知前或入队后崩溃 | 提交时冻结版本、会话、父子标题/ID/进度与通知意图。在没有领过发送权时可对账后认领并发起唯一一次投递；已认领但无确定结果标未知、不重发（即便宿主已忘了去重键）。板与撤销仍可用。收到入队回执不标“已读”。即使后来撤销或改名，迟到摘要仍注明原批次/版本。 |
| 审计发出刷新、复核、更改通知状态、撤销、Fishball 处理内部通知 | 不启动推理。元数据不推旧板 SSE，不让打开的草稿报 409；用户编辑的既有通知路径不受影响。 |
| 审计将满或有长期未决事项 | 建议每板私有记录预算 16 MiB、未决复核与未知投递合计最多 100 条；预留无法保证就暂停新分析、保留手工编辑。鉴权 owner 可核查并归档未知投递（不假装送达）；Fishball 处理过期复核，不强制结案。可精简已结记录，不因清理丢失重放水位。 |

多目标同名任务和根节点还应分别验证：按 ID/父路径定位；顶层明确“无父任务”。所有来自回复或看板的文字只作转义后的数据。默认无实际变化时，用户不会收到聊天消息或推送。
