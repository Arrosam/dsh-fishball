## Scope contract

**V2 contains only:**

- DSH-native Web child, A-lite: effective read-only, Fishball-only conversation, sidebar/navigation/new-session entry hidden and nonfocusable; native ecosystem compatibility retained. **Independent child browser origin**, then distinct complex native shortcut bindings or unbind; main settings unchanged. No corrective navigation or archive fallback. Trusted same-host deployment and native framing defaults are accepted; remote/tunnel and exact-ancestor limitations are explicit (§4.3/§5). The dedicated private Skill tool below is the sole narrow agent-write exception.
- Manager-session creation on opening the Fishball page, through the existing singleton activation path, **after the child app's ready signal**, not after a timer. Creating the session does not itself run a model turn.
- Slim settings: status, restart, model/provider sync, one-line effective Read Only notice, link to the child's native DSH Plugins page; preserve native Settings access and return to Fishball. No parallel custom plugin editor or Watchdog editor.
- Existing connector contract 1.2, injection fix, and already integrated D1–D3 semantics. No new MCP transport or custom contract replacement.
- Child-only **Fishball 推荐 / Fishball Recommended** tab, id `fishball-recommended`, delivered as an instance-owned child client module, not a placed/bundled plugin.
- Manager-only private Skill tool: list/read/create/update/remove/reload within its own child-home Skills directory, native format and catalog semantics, no general filesystem permission widening.

**V3 contains all Watchdog work, board (including `board_search`), fold-notify, bundled-plugin placement Q2–Q4, and MCP. V2 ships no bundled plugins.** Shared already-integrated core seams are not automatically deleted merely because V3 consumes them; completing their deferred consumer features is not a V2 gate.

Fishball coordination decisions during this audit: recommendation delivery is instance-owned child composition; V2 assumes a fresh or V2-only child profile. **No migration work or migration cases.** Profiles containing deferred plugins are unsupported/out of scope. Fishball reports the `:7713` test home runs `ebe026d` without those plugins and main DSH runs the old `eaa33f5`; neither live environment was inspected here, and neither is evidence of final-V2 readiness.

### 4.3 PG-1 / shortcut remapping: read-only dual-SDK finding and safe plan

**Required user design:** isolated child browser origin, then DSH-native **distinct complex bindings or explicit unbind** for every navigate-away/create/open/switch-session shortcut. The user rejected corrective navigation/archive fallback: “这个方案听起来就很不稳定。不要”. Remove that mechanism from V2; no fallback-only release option remains. Main shortcut settings must stay unchanged. Fishball accepted a **trusted same-host** deployment: all services on `127.0.0.1` are the user's own trusted DSH processes; host-scoped cookies already cross those ports today. Keep audience/signature checks. Remote/tunnel incompatibility is a documented limitation, not a blocker or separate-host isolation gate. Static inspection below covers **both 0.2.1-rc.5 and 0.2.2-rc.1**, not live browser state.

The document partitions by runtime/platform (for example `web:macos`), not by DSH profile, session, child process or iframe path.

#### (2) Can child writes change main shortcuts? **Yes, in the current embed.**

The [embed broker:4–9](<../../packages/instance/src/slim/host/embed.js#L4-L9>) explicitly serves `/fishball/embed/` from the **main DSH origin**, forwarding privately to the child backend. Thus, for main `http://127.0.0.1:54679`, the embedded child is also at that browser origin; on another deployment the same conclusion follows for that deployment's main origin. A different pathname/query or private server port behind the proxy is **not** a localStorage boundary.

Combined with both SDK adapters above, a child native-settings edit can persist changes visible to main and notify its already-open clients. Separate child home, native admission cookie, process and session do not prevent it. **No shared-origin edit, reset-all, temporary save/restore, direct storage injection or global storage monkey-patch is safe under “never touch main settings.”** Do not implement any of those as a workaround. **Admission design:** preserve a same-origin, authenticated, credential-free *launch route* in the connector descriptor, but make it an admission redirect, **not a child document proxy**. Only the current owned child generation may supply its exact allowlisted authority; no user-controlled target URL, arbitrary port, external redirect, wildcard CORS or public bearer endpoint. The main broker obtains native access server-side, sends `303` only to that child's authenticated URL with `Cache-Control: no-store` and `Referrer-Policy: no-referrer`; native admission sets its cookie and redirects to clean `./`. The final iframe document/base/transport origin is the child port. Use iframe `referrerPolicy="no-referrer"`. Any view/language continuation must be non-secret and validated; the native redirect drops launch query parameters, so explicitly carry intended view/language after admission rather than assuming they survive.

This deliberately changes the existing [private-only exchange:68–89](<../../packages/instance/src/slim/host/native-web-access.js#L68-L89>): the browser now consumes native admission. **The reusable native token is visible in browser/network redirect traces and potentially server access logs**; `303` cleans the final URL, not every history/log record. Never place it in public status, shared descriptor state, error text, telemetry or persisted client config; redact launch query logging and never follow an unowned redirect. Do not claim a one-use native launch id: none was found in either SDK. A Fishball-owned opaque one-use broker handle may reduce parent exposure if necessary, but would be new Fishball machinery and would not make the native token itself one-use. Native `/connect` is a separate API-operator flow, not Web bootstrap. No token/cookie is sent deliberately to third-party origins; network traces are sensitive, and actual leakage checks remain required.

**Cookie boundary:** HTTP audience includes `host:port`; cookie name is `dsh-auth-` plus an authority hash, so main/child names do not overwrite. Cookies are HttpOnly, Path=/, SameSite=Strict, Secure only with actual TLS. Same-host same-scheme cross-port framing is same-site despite being cross-origin. **Cookies are not port-isolated**: the browser sends matching host cookies to sibling ports. Fishball explicitly accepts this trusted-own-DSH-process assumption; do not market port separation as malicious-local-server credential isolation. Keep audience/signature/expiry checks. No separate-host requirement is added.

**CSP / framing:** in both SDKs, inspected native index serving and frontend templates set **no CSP or X-Frame-Options**, and no CSP meta ([rc.5 template:1–18](</Users/samuel/Library/Application Support/DSH/data/versions/0.2.1-rc.5/node_modules/@deepseek-ai/dsh-web-frontend/dist/index.html#L1-L18>), [rc.1:1–21](</Users/samuel/Library/Application Support/DSH/data/versions/0.2.2-rc.1/node_modules/@deepseek-ai/dsh-web-frontend/dist/index.html#L1-L21>)).
